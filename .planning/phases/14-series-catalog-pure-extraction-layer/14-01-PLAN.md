Build the keystone of Phase 14: the `ExploreSeries` struct catalog + `ScaleKind` taxonomy + the field-discriminator-backed `quantitativeValue(from:)` / `isPresent(in:)` accessors that every downstream helper (extraction, scatter, normalization) and every Phase-15/16 UI composes on top of. <threat_model>
## Trust Boundaries

This phase is a PURE Foundation-only computation library over already-consented, already-projected in-memory `DaySnapshot` value types. There is NO new attack surface: no I/O, no persistence, no network, no UI, no new entry point, no user-input parsing (inputs are typed value snapshots defensively decoded upstream at the Repository seam). The classic ASVS web categories do not apply. The only meaningful "threats" are health-data HONESTY and PRIVACY-SUPPRESSION violations — a fabricated value is a data-integrity threat to the user's trust.

| Boundary | Description |
|----------|-------------|
| catalog → downstream extraction | The catalog's `field`/`scaleKind` is the contract every extractor reads; a wrong scale-kind would let a presence series be treated as quantitative |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Information disclosure (fabricated value) | ExploreSeries.quantitativeValue | mitigate | nil field → nil (no point); logged literal 0 → 0.0; `snap.x.map(Double.init)` never a `>0` filter (Pitfall 2) — proven by Plan-02 gap/logged-0 fixtures |
| T-14-02 | Information disclosure (suppression leak) | bleeding.intensity / bleeding.event | mitigate | both bleeding-derived accessors gate on `!snap.suppressed` (Pattern 3); pinned no-leak fixture in Plan 02 |
| T-14-03 | Tampering (presence coerced to 0/1) | ScaleKind / catalog | mitigate | presence series are scaleKind .presenceEvent and route via isPresent (→ [Date] in Plan 02), never quantitativeValue; type-level — the structural honesty move |
| T-14-04 | Tampering (Hashable silently wrong) | ExploreSeries conformance | mitigate | Equatable/Hashable derive from `id` only, no stored closure; id-uniqueness test proves no collision (Pitfall 3) |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | none — phase installs ZERO external packages; SC1 boundary (Package.swift zero-dep) makes any package un-linkable; BoundaryLintTests enforces Foundation-only |
