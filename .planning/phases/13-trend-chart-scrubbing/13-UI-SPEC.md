# Phase 13 — UI Design Contract (Trend-Chart Scrubbing)

> Visual and interaction contract for Phase 13 (CHART-01..04). Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **PLATFORM:** Native **iOS app in SwiftUI + Swift Charts** — NOT web/CSS/React. The design system is
> the shipped v1.0 app: SF Symbols, semantic system colors, Dynamic Type text styles, native SwiftUI
> controls, and Swift Charts. Web-only template fields are adapted or marked `not applicable (native iOS)`.
> This contract EXTENDS the approved v1.0 Phase 8 UI-SPEC (archived at
> `.planning/milestones/v1.0-phases/08-insights-integration-coordinator-cached-insights-dashboard/08-UI-SPEC.md`)
> — everything declared there (card structure, chart axis contract, color independence, empty/sparse
> states) remains in force and is NOT restated except where this phase touches it.
>
> **SCOPE:** Add scrub/tap-to-read selection to the EXISTING `InsightTrendChart` on the dashboard cards
> only. No Explore screen, no multi-series anything (Phases 15/16). The phase also ships the reusable
> selection foundations: the pure `ChartScrubSelection` resolver, the selection-accessibility pattern,
> and the DEBUG-gated `-uitest-select-day` E2E seam.
>
> **FOUR HONESTY CONSTRAINTS THAT SHAPE EVERY PIXEL OF THE SELECTION CHROME:**
> 1. **A gap day reads "Not logged" — NEVER 0, NEVER an interpolated value.** Selection resolves through
>    the pure resolver (raw selected `Date` → exact logged calendar day or nil); no nearest-neighbor snap.
> 2. **A logged severity-0 day reads "Severity 0 of 10"** — visually and textually distinct from
>    "Not logged" (absence ≠ 0).
> 3. **The tooltip is never the sole carrier of meaning** — its readout is mirrored into the accessibility
>    tree, and the existing per-mark labels + a new Audio Graph give VoiceOver users a non-gesture path.
> 4. **The PDF render path inherits ZERO selection chrome** — `allowsSelection: Bool = false` default;
>    `ReportPDFRenderer` is untouched in the diff; when `false`, NO selection modifier is even attached.

selection chrome only:

| Token | Value (pt) | Usage |
|-------|-----------|-------|
| xs | 4 | Tooltip internal line spacing (date line ↔ value line, `VStack(spacing: 4)`) |

| md | 16 | Unchanged card/section spacing (system grouped-List defaults) |

| tooltip-corner | 8 | Tooltip `RoundedRectangle(cornerRadius: 8)` |

**Touch targets:** the scrub surface is the whole 200pt-tall chart plot — far above the 44pt minimum.
No new buttons are added (no new tap targets to size).

Exceptions: none.

## Typography

Semantic Dynamic Type text styles only (never `.font(.system(size:))`). Existing chart typography
(summary `.caption`, axis labels caption-class) is unchanged. New roles:

| Role | SwiftUI text style | Weight | Used for |
|------|--------------------|--------|----------|
| Tooltip date line | `.caption2` | regular | The absolute date in the lollipop (e.g. "Jun 5"), `.secondary` |
| Tooltip value line | `.caption` | **semibold** | "Severity 6 of 10" — the payload, `.primary` |
| Tooltip "Not logged" line | `.caption` | regular | The gap-day state, `.secondary` (de-emphasized: the gap is information, not an error — never bold, never red) |

Rules:
- Exactly these roles — the tooltip never introduces ad-hoc sizes. Two weights total on this surface
  (regular + semibold), matching the app-wide convention.
- Tooltip text scales with Dynamic Type. The `.annotation(overflowResolution:)` keeps it inside the
  plot; at the largest accessibility sizes it may cover part of the plot — acceptable, because the
  non-gesture VoiceOver path (per-mark labels + Audio Graph) carries the same information.
- Date rendering uses `Text(date, format: .dateTime.month().day())` — the SAME format as the existing
  axis labels and per-mark accessibility labels (one date vocabulary per chart).

## Color

Semantic system colors only (auto Light/Dark/contrast adaptation). The v1.0 60/30/10 split is
unchanged; this phase only allocates colors for the new selection chrome:

| Role | Semantic value | Usage |
|------|----------------|-------|
| Dominant (60%) | `Color(.systemGroupedBackground)` / `.primary` text | Unchanged dashboard canvas |
| Secondary (30%) | `Color(.secondarySystemGroupedBackground)` / `.secondary` text | Card surfaces; **the tooltip card background** (`Color(.secondarySystemBackground)` in a rounded rect — a quiet system surface, dark-mode-safe); **the selection rule mark** (`Color.secondary.opacity(0.5)`, 1pt, drawn BEHIND the data line via `.zIndex(-1)`) |
| Accent (10%) | `Color.accentColor` (= the chart's `inkColor` on the dashboard) | See reserved-for list |
| Destructive | not used in this phase | No destructive actions exist in this phase |

**Accent reserved EXCLUSIVELY for (extends the v1.0 list):**
- The chart data series marks (existing — `inkColor`).
- The **selected-day highlight point** (the lollipop head): an emphasized `PointMark` at the selected
  LOGGED point, `inkColor`, `.symbolSize(100)` (visibly larger than the default ~36pt² marks).
- The Insights tab tint (existing).

Accent is NEVER used for: the rule mark (it would compete with the data line — the scan line is
secondary-gray), the tooltip background or text, the "Not logged" state.

**Color-independence (MANDATORY):**
- The selected day is signaled by **rule-mark position + larger point size + the tooltip text** — never
  by hue alone. A grayscale user distinguishes selected vs unselected by size and the scan line.
- The gap-day state is signaled by **the absence of a highlight point + the literal text "Not logged"**
  — never by a color change alone, never by a warning color (the gap is honest information).

**Honest absence (visual rule, the heart of CHART-02):**
- On a gap day the rule mark still draws (the DATE is real) and the tooltip shows date + "Not logged" —
  but NO highlight point is drawn (there is no point to highlight; drawing one would fabricate data).
- On a logged severity-0 day the highlight point draws AT the zero line and the tooltip reads
  "Severity 0 of 10" — provably different from the gap state in both pixels and text.

## Swift Charts Selection Specification (phase-specific source of truth)

### Gesture & state (CHART-01 / CHART-03 — locked in CONTEXT)

| Aspect | Contract |
|--------|----------|
| Gesture API | `.chartXSelection(value: $rawSelectedDate)` (`Date?` binding) — framework-standard; NO custom `DragGesture`, NO `highPriorityGesture`. Vertical List scrolling keeps priority via framework arbitration (the dashboard model is tap/touch-and-hold-to-select; free scrub is reserved for Explore's fixed layout in Phase 15). |
| Gating | `allowsSelection: Bool = false` — additive defaulted param on `InsightTrendChart` (the `inkColor` precedent). When `false`, the `chartXSelection` modifier is NOT attached at all (conditional application), so the PDF `ImageRenderer` path renders a chart with zero interaction modifiers. `InsightCardView`'s `.trend` branch passes `true`; `ReportPDFRenderer` is NOT edited. |
| Lifecycle | Tooltip + rule mark + highlight are visible iff the resolved selection is non-nil. They appear on touch, track the finger while touching, and dismiss on release (CHART-03 verbatim — the framework nils the binding on release). |
| Selection state | Per-card, view-local `@State`, ephemeral — never persisted, never placed in any shared `Observable` (a scrub frame must not invalidate the List). |
| Day resolution | The raw selected `Date` resolves through the pure **`ChartScrubSelection`** resolver (EndoInsights, unit-tested like `ChartSeriesGrouping`): `calendar.startOfDay` the raw date, then require an **EXACT logged-day match** → `InsightPoint?`. In-domain but unmatched → the explicit gap state (date + nil). NEVER interpolation, NEVER snap-to-nearest-logged. |
| Haptic | `UISelectionFeedbackGenerator.selectionChanged()` fires on resolved calendar-DAY change only: nil→day no haptic, dayA→dayB haptic (including logged↔gap transitions), day→nil (release) no haptic. Lifecycle (Claude's discretion): one generator instance held in the selection-owning view; `prepare()` when selection becomes non-nil; released when selection ends. Simulator no-ops are expected; device verification is a manual checkpoint. |
| Animation | Selection chrome moves WITHOUT implicit animation (selection state stays out of the inputs driving `.animation(..., value: points)` — the existing modifier is scoped to `points` and stays that way). No appear/disappear transition is added for the tooltip; Reduce Motion therefore needs no extra gate, but any future transition must respect `reduceMotion`. |

### Selection chrome (the lollipop — Health-pattern, locked in CONTEXT)

Rendered only while a selection is active, in this stack order:

1. **`RuleMark(x: .value("Selected", selectedDay))`** — vertical scan line spanning the full 0…10 Y
   domain. `Color.secondary.opacity(0.5)`, default 1pt width, `.zIndex(-1)` so it draws BEHIND the data
   line and points.
2. **Highlight `PointMark`** (logged day only) — at `(selectedDay, point.value)`, `inkColor`,
   `.symbolSize(100)`. Omitted entirely on gap days.
3. **Tooltip annotation** — attached to the RuleMark via
   `.annotation(position: .top, spacing: 0, overflowResolution: .init(x: .fit(to: .chart), y: .disabled))`
   so it pins at the chart top, never clips at window edges, and the finger never occludes it
   (the Apple Health pattern).

**Tooltip card layout** (`VStack(alignment: .leading, spacing: 4)`, 8pt padding,
`Color(.secondarySystemBackground)` in `RoundedRectangle(cornerRadius: 8)`):

| State | Line 1 (`.caption2`, `.secondary`) | Line 2 |
|-------|-----------------------------------|--------|
| Logged day | "Jun 5" (absolute date) | "Severity 6 of 10" — `.caption` semibold `.primary` |
| Logged severity-0 day | "Jun 5" | "Severity 0 of 10" — same style (a real value, not de-emphasized) |
| Gap day | "Jun 5" | "Not logged" — `.caption` regular `.secondary` |

### Accessibility of selection (CHART-04 — locked in CONTEXT)

- **Non-gesture path (the requirement):** keep/extend the existing per-mark
  `accessibilityLabel` (date) / `accessibilityValue` ("severity n of 10") — VoiceOver users swipe
  through logged days directly — AND adopt **`AXChartDescriptor`** via
  `.accessibilityChartDescriptor(...)`: title = the existing `summaryText`; X axis = the window's
  date range (categorical day labels in the same "Jun 5" format); Y axis = `AXNumericDataAxisDescriptor`
  0…10 "Severity"; ONE `AXDataSeriesDescriptor` containing logged points ONLY with
  **`isContinuous: false`** — so the Audio Graph plays discrete tones per logged day and never
  sonically interpolates across a gap (the audio equivalent of the broken line).
- **Tooltip in the a11y tree:** the tooltip is one accessibility element whose `accessibilityValue` is
  the full readout ("Jun 5 — Severity 6 of 10" / "Jun 5 — Not logged"). Quiet: NO
  `UIAccessibility.post` announcements on day change (locked — selection surfaces via value, not chatter).
- The chart's existing one-line text summary above it is unchanged — the chart remains never the sole
  carrier of meaning.

### A11y identifiers (additive — existing `insights.card.*` ids untouched)

| Element | Identifier |
|---------|-----------|
| Tooltip container (always, while selection active) | `insights.card.<signalKey>.chart.tooltip` |
| "Not logged" line (gap variant only — E2E asserts existence/absence) | `insights.card.<signalKey>.chart.tooltip.notLogged` |
| Existing chart id (kept) | `insights.card.<signalKey>.chart` |

### E2E seam (locked in CONTEXT)

- **`-uitest-select-day <yyyy-MM-dd>`** — DEBUG-gated launch arg (exactly like `-uitest-reset` /
  `-uitest-seed-insights`, and covered by the same release source-guard posture) that sets a
  deterministic initial selection on the seeded dashboard chart. XCUITests assert via the a11y ids +
  `accessibilityValue` above: seeded logged day → tooltip value contains "Severity 6 of 10"; gap day →
  `.notLogged` exists; severity-0 day → "Severity 0 of 10" (never "Not logged"). ZERO coordinate
  gestures, zero sleeps. At most one smoke-level real-gesture test, asserted via ids only.

## Component & Interaction Inventory

### A. `InsightTrendChart` (modified — additively)

- New params: `allowsSelection: Bool = false` (after `inkColor`, same defaulted-additive shape).
- New internal: `@State rawSelectedDate: Date?`, the resolved `(day: Date, point: InsightPoint?)?` via
  `ChartScrubSelection`, the selection chrome above, the haptic generator, the `AXChartDescriptor`.
- Everything else byte-identical: runs/gap-breaking, axis contract, fixed 0…10 Y domain, per-mark a11y,
  summary text, `asOf` injection, `inkColor`, animation scoping.
- **`allowsSelection == false` ⇒ the rendered output and modifier set are IDENTICAL to v1.0** (the
  acceptance criterion the PDF re-verification checks). The `AXChartDescriptor` is attached in both
  modes (it is render-inert and benefits the dashboard; it never reaches the PDF because
  `ImageRenderer` rasterizes visuals only) — if implementation shows ANY render diff, gate it behind
  `allowsSelection` too.

### B. `InsightCardView` (modified — one line)

- The `.trend` branch passes `allowsSelection: true`. Nothing else changes; card structure, confidence
  pill, dismiss affordance, sparse state all untouched. The card's swipe-to-dismiss coexists with
  selection because selection is a chart-plot gesture, not a row gesture (verify in the manual
  scroll-vs-scrub check).

### C. `ChartScrubSelection` (new, EndoInsights — pure layer, no pixels)

- Pure Foundation resolver: `(rawDate: Date, points: [InsightPoint], calendar: Calendar) →` exact
  logged-day match or nil. Unit-tested with the `ChartSeriesGroupingTests` gap fixtures: gap → nil;
  logged severity-0 → the literal 0 point; boundary days; DST-safe day math. This is the honesty
  choke-point Phases 15–16 reuse — its tests, not the E2Es, carry the invariants.

### D. `ReportPDFRenderer` (UNTOUCHED)

- Zero diff in this phase. Manual checkpoint: export a report and visually confirm the chart page is
  unchanged; `ReportFlowUITests` re-run green.

## Copywriting Contract

All new strings live in **`InsightsCopy`** (the existing audited dashboard surface — this is dashboard
chrome, not a new surface) and are added to `auditableStrings` BEFORE the views render them, so the
existing `CopyAuditTests` scans (forbidden verbs, gendered tokens, numeric confidence) cover them.
Substring curation applied: no "her" hosts (no "there/here/other/higher/whether/where"), no
"will"/"causes"/"treat"/"she" substrings anywhere below.

| Element | Copy |
|---------|------|
| Primary CTA | **none** — this phase adds no buttons; the interaction is direct manipulation on the existing chart (no hint/teaching copy is added either — the gesture is the platform reflex Apple Health trained, and the non-gesture a11y path covers discovery for VoiceOver) |
| Tooltip value (logged day) | **"Severity {n} of 10"** — `InsightsCopy.scrubSeverity(_ value: Int)`; matches the existing per-mark accessibilityValue vocabulary ("severity n of 10") |
| Tooltip gap state | **"Not logged"** — `InsightsCopy.scrubNotLogged`; the LOCKED gap wording (never "0", never "No data", never an error tone) |
| Tooltip date | rendered via `Text(date, format: .dateTime.month().day())` — a format, not a copy string (no audit entry needed; consistent with axis labels) |
| Tooltip a11y readout | **"{date} — Severity {n} of 10"** / **"{date} — Not logged"** — composed from the two audited strings + the date format |
| Empty state | unchanged — existing `InsightsCopy.emptyHeading`/`emptyBody` (this phase adds no empty state) |
| Error state | unchanged — selection is local view state with no failure mode; existing `loadError` covers the dashboard |
| Destructive confirmation | **none** — no destructive actions in this phase (card dismiss is pre-existing and non-destructive) |

**Audit registration (named task for the first plan):** append `scrubNotLogged` and a representative
`scrubSeverity(6)` to `InsightsCopy.auditableStrings` (the `supportingEvidence(loggedDays: 12)`
precedent — digits in a factual readout pass the numeric-confidence scan, which targets `%`/`p =`/`r =`
confidence framing, exactly like the shipped "Seen across 12 logged days.").

**Substring verification of the two new strings:**
- "Not logged" — contains none of: her, she, will, causes, treat, detect, %, p=, r=. PASS.
- "Severity {n} of 10" — "Severity" hosts no forbidden substring (s-e-**v-e-r**-i-t-y ≠ "her"). PASS.

## Accessibility Contract (first-class — endo audience)

| Dimension | Requirement |
|-----------|-------------|
| Non-gesture value access (CHART-04) | Per-mark `accessibilityLabel`/`accessibilityValue` KEPT on every Line/PointMark + `AXChartDescriptor` Audio Graph (discrete series, `isContinuous: false`, logged days only). A VoiceOver user reads "exact day + value" with zero drag gestures. |
| Quiet selection | No `UIAccessibility.post` on day change; the tooltip element's `accessibilityValue` carries the readout. |
| Color independence | Selected day = scan line + larger point + text (never hue alone); gap state = missing point + "Not logged" text (never a color code). |
| Dynamic Type | Tooltip uses `.caption`/`.caption2` named styles; `overflowResolution: .fit(to: .chart)` prevents clipping; axis behavior unchanged. |
| Reduce Motion | No new animated transitions are introduced; existing `reduceMotion` gate on chart animation untouched; selection chrome moves un-animated by construction. |
| Honest absence (a11y) | The gap tooltip reads "Not logged" to VoiceOver verbatim; the Audio Graph omits gap days rather than playing zeros; severity-0 reads "Severity 0 of 10". |
| Touch targets | The scrub surface is the full 200pt chart; no new sub-44pt targets exist. |
| Haptics | Selection haptic on day change only (CHART-03) — supplementary, never the sole signal (the visual tooltip + a11y value always accompany it). |
