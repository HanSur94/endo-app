  <files>Sources/EndoApp/Features/Insights/ChartSeriesGrouping.swift, Tests/EndoAppTests/ChartSeriesGroupingTests.swift</files>
  <behavior>
    - A set of consecutive calendar days groups into ONE run.
    - A one-day gap between logged days splits them into TWO runs (a break — the line must not connect across the gap).
    - Multiple gaps produce multiple runs; each run is a maximal gap-free span, runs are ordered by date.
    - A single logged day forms a run of one point (so it still renders as a PointMark, never dropped).
    - The helper NEVER fabricates a `value: 0` for an unlogged day — absent days are simply not present in any run (absence ≠ zero, UI-SPEC honest absence; RESEARCH Pitfall 1).
    - A literal logged `value: 0` (severity 0) IS retained as a point in its run (distinct from a gap).
  </behavior>
  <action>Create `ChartSeriesGrouping` as a pure helper (Foundation-only, no SwiftUI/Charts import) that takes an ordered `[InsightPoint]` (each = a logged day) + a `Calendar` and returns `[Run]` where `Run` has a stable `id` and `points: [InsightPoint]`, splitting whenever two consecutive logged points are NOT adjacent calendar days. This is the gap mechanism from RESEARCH Pattern 5 / UI-SPEC honest-absence — extracted as a PURE function so "absence ≠ 0" is provable WITHOUT rendering (08-VALIDATION "Swift Charts gap logic" layer). Do NOT insert zero-valued points for missing days; a literal severity-0 logged point stays. Create `ChartSeriesGroupingTests.swift` (`@Test`/`#expect`) covering all six behaviors with deterministic date fixtures (use a fixed UTC-ish `Calendar` for determinism).</action>
