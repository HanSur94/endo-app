<objective>
Add the app-side seam that maps the SwiftData store → the value contract: `Repository.daySnapshots() -> [DaySnapshot]`. This is the ONLY place `@Model` rows become `DaySnapshot` — it imports SwiftData AND EndoInsights, and it stays app-side so the package never touches the store (SC1, D-10/D-14). It mirrors the existing `factorDays()`/`bleedingDays()` projection pattern exactly.

Because Plan 01 chose Option D (the package owns its snapshot-facing enums), this mapping translates app-enum → package-enum at the boundary. The raw values match, so each translation is a same-raw-value passthrough — and a parity test asserts no drift (closing the Option-B trap that Option D otherwise risks).

Per D-14 (the `daySnapshots()` read, pure/Sendable output, mirrors `factorDays`/`bleedingDays`), D-10 (mapping stays app-side, NOT in the package), D-03 (absence ≠ 0 honesty preserved through the projection), and the V4 consent gate (`assertConsented()` first, like every sibling read).

Purpose: this is the live data path that Phase 8 will feed into `TrendsEngine`. Phase 5 proves the mapping is honest and consent-gated against an in-memory store; no UI, no device, no iCloud.
Output: `daySnapshots()` on the Repository protocol + `SwiftDataRepository`, plus the mapping-honesty + enum-parity test suite.
</objective>

| SwiftData store → DaySnapshot | The Repository reads health @Model rows and projects them to value snapshots. This is a privacy-sensitive read (Art.9 special-category data) crossing into the analysis layer. |
| consent gate → read | `assertConsented()` gates the read; no health data is projected before opt-in. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-07 | Elevation / policy | daySnapshots() reading health rows before consent | mitigate | `assertConsented()` is the first statement (V4 / ONBD-01 defense-in-depth), identical to factorDays/bleedingDays. A test seeds without consent expectations matching the sibling reads. |
| T-05-08 | Information Disclosure | Free-text health prose crossing into the analysis layer / snapshot | mitigate | The mapping carries `hasNote: Bool` only — never the DayEntry note text or symptom/food note prose. The package physically cannot receive free text. |
| T-05-09 | Denial of Service | Corrupt/unknown stored raw values crashing the projection | mitigate | Every enum decode uses the package `init(raw:)`/`init?(raw:)` defensive path (unknown → `.other`/nil); `clots` coalesces nil→false; no force-unwrap of a decoded raw (mirrors makeFactorDay). |
| T-05-10 | Tampering (architecture integrity) | SwiftData coupling leaking into the package | mitigate | The mapping stays app-side (this file imports SwiftData); the package imports only Foundation (Plan 01/02 lint). daySnapshots() is the ONLY @Model → DaySnapshot projection (SC1). |
