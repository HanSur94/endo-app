# Phase 16 — UI Design Contract

> Visual and interaction contract for Phase 16 (Scatter View & Correlation Deep-Link — SCAT-01..04).
> Generated by gsd-ui-researcher; verified by gsd-ui-checker.
>
> **PLATFORM:** Native **iOS app in SwiftUI + Swift Charts** — NOT web/CSS/React. The design system is
> the locked v1.0/v1.1 app and **the APPROVED Phase-15 Explore UI-SPEC** (`15-UI-SPEC.md`). This phase
> EXTENDS that contract — it does not reinvent it. SF Symbols, semantic system colors, Dynamic Type text
> styles, native SwiftUI controls, Swift Charts marks. Web-oriented template fields (px spacing, hex
> colors, shadcn/Tailwind, line-height ratios, registry) are adapted to their SwiftUI equivalents; web-only
> fields are marked `not applicable (native iOS)`. The shadcn/registry gate is **N/A** — there is no
> component registry in a SwiftUI project (Apple system frameworks + the zero-dependency EndoInsights SPM
> package only).
>
> **AUDIENCE:** Endometriosis patients. Accessibility is a first-class requirement: ≥44pt touch targets,
> no information by color alone, full VoiceOver + Dynamic Type, and a text-summary fallback for the scatter
> (a chart is never the sole carrier of meaning).
>
> **WHAT PHASE 16 ADDS.** A descriptive-only **factor-vs-factor SCATTER** view, reachable two ways:
> (1) a **`Lanes | Scatter` mode toggle** at the top of the existing `ExploreView`, where Scatter mode lets
> the user pick exactly **two quantitative axes** (X and Y) and renders one `PointMark` per both-logged day;
> and (2) a **"see the days behind this" deep-link** on a `.correlation` dashboard card that opens Explore
> in Scatter mode **prefilled** with that card's two factors. It composes the SHIPPED `ScatterPairing`
> (Phase 14) and the SHIPPED Explore screen/picker/`ExploreCopy` (Phase 15) UNCHANGED. **NO** new
> persistence, **NO** schema/engine/CloudKit/PDF changes.
>
> **WHY SCATTER FITS THE HONESTY POSTURE.** Visualization research (Xiong et al., IEEE VIS 2019) found
> scatter plots elicit the *lowest* causality ratings of common chart types — the least causally-suggestive
> way to show an association. The scatter is therefore the honesty-aligned differentiator: it shows the RAW
> evidence days with no fitted line, no r-value, no "% impact", a neutral caption only.
>
> **SEVEN HONESTY CONSTRAINTS THAT SHAPE EVERY PIXEL OF THE SCATTER (LOCKED — `16-CONTEXT.md` + RESEARCH
> Pitfall 5):**
> 1. **Each point = one BOTH-logged day** — `ScatterPairing.pairs(snapshots, x:, y:)`. A day missing EITHER
>    factor produces NO point; absence ≠ 0, never imputed, never 0-substituted, never last-known.
> 2. **Overplotting handled by COUNT, never jitter** — identical `(x, y)` day-pairs aggregate into ONE
>    `ScatterPoint` whose `count` drives mark **size and/or opacity**. NEVER `Double.random`/jitter — that
>    fabricates fractional coordinates the user never logged. Discrete 0–10 × 0–10 data collides on a grid;
>    count-encoding is the ONLY honest overplotting fix.
> 3. **DESCRIPTIVE-ONLY** — NO fitted/trend/regression line, NO correlation coefficient/r-value, NO
>    "% impact"/numeric confidence/p-value, NO shaded confidence band. A NEUTRAL caption only
>    ("Based on N days where both were logged"). The gated correlation engine remains the ONLY thing
>    allowed to say "possible association"; the scatter shows raw points.
> 4. **Axes in REAL units with FIXED honest domains** — both axes carry their `SeriesNormalization.domain`
>    + real-unit labels (`0…10`, `1…5`, `1…4`, `0…24`, `0…240`); a logged literal 0 on both axes IS a real
>    point. Neutral axis framing — the picker never implies X "affects"/"causes" Y.
> 5. **Quantitative axes ONLY** — the axis picker offers only `ScaleKind.isQuantitative` series
>    (`ScatterPairing` is quantitative-axis-only); presence/event series are NOT scatter axes. Bleeding
>    suppression still hides `bleeding.intensity`/`bleeding.event` (the Phase-14 accessor gate + the
>    Phase-15 picker filter carry through unchanged).
> 6. **The scatter is NEVER the sole carrier of meaning** — a text-summary / a11y descriptor (point count +
>    both axis names + the both-logged-day basis) so the information is available without seeing the plot;
>    count is encoded by size/opacity AND surfaced in the per-point readout, never by an effect a colorblind
>    user can't decode.
> 7. **ALL new chrome via the audited `ExploreCopy`** — every caption/empty-state/sparse/toggle/deep-link
>    string is added to `ExploreCopy.auditableStrings` and registered in `CopyAuditTests` BEFORE any view
>    renders it (an unregistered surface escapes the `ClaimsPolicy` substring scans — RESEARCH Pitfall 3).
>    The scatter's chrome is the most causality-sensitive copy of the milestone.

## Spacing Scale

Native iOS uses **points (pt)**, delegating to system defaults wherever possible. Declared values mirror
the multiples-of-4 scale Phase 15 already uses; this phase reuses the SAME tokens and adds **one** scatter
plot dimension so the square plot + its real-unit axes never clip at large Dynamic Type.

| Token | Value (pt) | Usage |
|-------|-----------|-------|
| xs | 4 | Tight inline gaps (axis-picker icon↔label, caption line spacing, point-readout line spacing) |
| sm | 8 | Default control spacing inside the axis-picker block / mode-toggle to axis-picker gap; plot edge inset so edge marks (a logged 0 or domain-max) are not clipped |
| md | 16 | Default element spacing between the mode toggle, the axis-picker block, the plot block, and the caption |
| lg | 24 | Inter-block gaps where the system default is insufficient (control block ↔ plot block ↔ honest state) — matches the Phase-15 `VStack(spacing: 24)` |
| scatter-plot-height | 320 | The square scatter `Chart` frame height (`.frame(height: 320)`, near-1:1 with the content width so a discrete grid reads as a grid, not a stretched smear); reflows taller only if axis labels need it at large Dynamic Type |
| chart-plot-inset | 8 | Plot inset on all four edges so a point at a domain corner (e.g. `(0,0)` or `(10,10)`) is fully visible, not half-clipped at the axis |

**System-default first:** reuse the Phase-15 `ScrollView` + `VStack(spacing: 24)` + `.padding()` scaffold
the screen already ships — do NOT hand-roll new page padding. The mode toggle, axis-picker, plot, and
caption stack vertically in that same column.

**Touch targets:** every interactive element MUST have a **≥44pt × 44pt** hit area (HIG): the
`Lanes | Scatter` segmented control, each X/Y axis-selector control, and the deep-link affordance on the
correlation card. (Swift Charts segmented `Picker` rows already clear 44pt.)

**Exceptions:** none beyond the system-default and 44pt-minimum rules above. `scatter-plot-height` and
`chart-plot-inset` are plot-geometry constants, not touch targets.

## Typography

Native iOS uses **semantic Dynamic Type text styles**, NOT fixed px sizes or line-height ratios. Declaring
fixed sizes would BREAK Dynamic Type (an accessibility requirement for this audience). The contract is text
styles + weights; the system supplies size and line height. These EXTEND the Phase-15 roles — no new ad-hoc
sizes are introduced.

| Role | SwiftUI text style | Weight | Used for |
|------|--------------------|--------|----------|
| Screen title | `.title2` (nav title) | semibold (style default) | "Explore" navigation title (UNCHANGED from Phase 15) |
| Mode-toggle / axis-picker label | `.subheadline` | regular | The `Lanes` / `Scatter` segment labels; the "X" / "Y" axis-selector labels + the chosen series `displayName` |
| Axis title (X / Y) | `.subheadline` | semibold | Each axis's series name + unit shown beside the plot (e.g. "Pelvic pain severity — of 10", "Stress — of 10") so the real scale is legible without reading the tick labels |
| Neutral caption | `.caption` | regular | "Based on {N} days where both were logged" beneath the plot — `.secondary` chrome, descriptive-only |
| Per-point readout (date-free) | `.caption` | regular | The count + both-axis real-unit values for a cell (e.g. "4 days — pelvic pain severity 7 of 10, stress 2 of 10") via `SeriesNormalization.readout` — a factual tally, never a statistic |
| Honest-state heading | `.headline` | semibold (style default) | The scatter empty ("pick two factors") + sparse ("not enough overlapping days") headings — reuses the Phase-15 `honestState` heading role |
| Honest-state body | `.body` | regular | The empty/sparse body copy — `.secondary`, `.fixedSize(…, vertical: true)` so honest framing never truncates |
| Chart axis / value labels | `.caption` / `.caption2` (Swift Charts defaults) | regular | X + Y real-unit tick labels — must stay non-clipping at large Dynamic Type (reduce tick density, never clip) |
| Deep-link affordance label | `.subheadline` | regular | "See the days behind this" on the `.correlation` card |
| Disclaimer | `.footnote` | regular | The reused `DisclaimerBanner` (UNCHANGED) |

Rules:
- **Exactly these roles** — no ad-hoc font sizes. Never `.font(.system(size: <fixed>))` for content text;
  always a named style so Dynamic Type scales it.
- Multi-line copy (caption, honest-state body, per-point readout) uses
  `.fixedSize(horizontal: false, vertical: true)` so honest framing never truncates.
- Each axis title carries its series UNIT in words ("— of 10", "— of 5", "— h", "— min") so the real scale
  is legible without reading the axis ticks (honesty constraint 4, text parity).

## Color

Native iOS uses **semantic system colors** that auto-adapt to Light/Dark Mode and accessibility-contrast
settings — NOT app-defined hex values. The 60/30/10 split is expressed in semantic terms and is IDENTICAL
to the Phase-15 Explore contract; this phase adds only the scatter-mark + count-encoding rules.

| Role | Semantic value | Usage |
|------|----------------|-------|
| Dominant (60%) | `Color(.systemGroupedBackground)` / system background; text in `.primary` | The Explore canvas behind the whole screen and the scatter plot background |
| Secondary (30%) | `Color(.secondarySystemGroupedBackground)`; text in `.secondary` | The mode-toggle / axis-picker control surfaces; the neutral caption; the per-point readout; the axis tick labels; the empty/sparse placeholder copy; the disclaimer banner background |
| Accent (10%) | `Color.accentColor` (the app tint) | See reserved-for list below |
| Scatter point fill | `Color.accentColor` (single hue) **with `count` carried by SIZE and/or OPACITY** | Every `PointMark` is ONE stable accent-tinted mark; the day-`count` is encoded by `.symbolSize(by:)` and/or per-mark opacity — the count signal is redundant (size + the per-point readout's "{N} days"), never hue-only |
| Destructive | not used as a hue here | The scatter is a read-only inspection surface; the deep-link is a navigation, not a destructive action. NO red anywhere in this phase. |

**Accent (`Color.accentColor`) is reserved EXCLUSIVELY for:**
- The **selected** segment of the `Lanes | Scatter` mode toggle (system segmented-control self-tint).
- The **selected** axis in each X/Y selector (system control self-tint).
- The **scatter `PointMark` fill** — a SINGLE accent hue for all marks (this is the one data surface in the
  phase; there is exactly one series of points, so one hue is honest and count is the only varying encoding).
- The **deep-link affordance** on the correlation card (its `arrow.up.forward.square` glyph + label tint),
  consistent with a tappable "open" action.

Accent is NEVER used for: encoding the day-`count` (that is SIZE/OPACITY + the readout, never hue), body
text, the caption, axis labels, the plot background, or any "this factor matters more" emphasis.

**Color-independence (MANDATORY — accessibility):**
- **The day-`count` is NEVER conveyed by color alone.** It is encoded by `.symbolSize(by:)` (and/or
  opacity) AND restated in words in the per-point readout ("{N} days — …"). A grayscale / Smart-Invert user
  reads the count from mark size + the text, never from a hue gradient.
- **The mode toggle's selected segment** differs from unselected by the system segmented-control's
  fill + position, never hue alone (system behavior; do not override it to a hue-only cue).
- **Each axis is labelled in words** (series `displayName` + unit) beside the plot AND on the tick axis —
  the two axes are told apart by their text labels and their distinct value domains, never by color.

**Honest absence in the scatter (the honesty constraint, visual rule — LOCKED):**
- A day missing EITHER factor contributes **NO point** — there is no mark at `0`, no mark on an axis line,
  nothing. Absence is the *absence of a mark*, never a plotted zero (`ScatterPairing` enforces this in the
  pure layer; the view must never add a placeholder mark).
- A logged literal **0 on both axes IS a real point** drawn at the `(0,0)` corner of the fixed domain —
  distinct from "not logged" (a point-at-origin vs no-point-at-all), exactly as the lanes read a logged 0.
- When too few both-logged days exist, the view shows the honest **sparse state**, NEVER a near-empty plot
  read as "no association".

## Scatter Specification (the executor's chart source of truth)

This is the central, phase-specific design decision — it encodes the LOCKED point semantics, the
count-encoding, the fixed real-unit axes, and the no-stats rule. Prototype the count-encoding early against
a dense fixture (RESEARCH "Looks Done But Isn't": seed 10 days at the same `(x,y)` → confirm ONE sized mark
+ a readout saying "10 days").

### Point semantics (SCAT-01 / SCAT-02 — LOCKED)

- **One `PointMark` per `ScatterPoint`** from `ScatterPairing.pairs(snapshots, x: xSeries, y: ySeries,
  calendar:)`. Each `ScatterPoint(x:y:count:)` is one occupied `(x, y)` cell; its `count` is how many
  both-logged days landed there. There is one mark per CELL, not one mark per day — identical day-pairs are
  already aggregated by the pure layer.
- **Count encoding (NEVER jitter):** drive mark size via `.symbolSize(by: .value("Days", point.count))`
  and/or per-mark opacity so a heavily-occupied cell reads as denser. Do NOT add any random offset / jitter
  to spread overlapping points — that fabricates fractional coordinates the user never logged (RESEARCH
  Pitfall 5; `ScatterPairing` deliberately exposes only integer-exact cells).
- **Both-logged-only (absence ≠ 0):** the view plots EXACTLY the `[ScatterPoint]` the pure layer returns —
  it never synthesizes a mark for a day missing a factor, never substitutes 0/last-known. A logged literal
  `(0,0)` IS plotted (the pure layer returns it; the view must render it).

### Axis contract (real units, fixed honest domains — NON-NEGOTIABLE)

- **X domain = `SeriesNormalization.domain(for: xSeries.scaleKind)`**, **Y domain =
  `SeriesNormalization.domain(for: ySeries.scaleKind)`** — the FIXED literal ranges (`0…10`, `1…5`, `1…4`,
  `0…24`, `0…240`), applied via `.chartXScale(domain:)` / `.chartYScale(domain:)`. NEVER a data-driven
  min/max (that would distort the cloud's position and hide that, e.g., severity never exceeded 6).
- **Real-unit tick labels on both axes** (`.chartXAxis` / `.chartYAxis`) plus a worded axis title beside
  the plot carrying the series `displayName` + unit. The user picks both axes freely; **neutral framing** —
  no copy or arrangement implies X causes/affects Y (RESEARCH Pitfall 5 / threat table).
- A presence/event series can NEVER reach an axis (the picker offers quantitative-only — see Component C);
  if a misroute ever occurred, `ScatterPairing` degrades to `[]` (the empty/sparse state), never a crash.

### Descriptive-only chrome (SCAT-03 — LOCKED, the most causality-sensitive surface)

- **NO fitted/trend/regression line. NO `LinearGradient` "trend" shading. NO r-value / correlation
  coefficient / slope / "% impact" / p-value / numeric confidence / shaded confidence band.** None of these
  may appear in the view, the view-model, or any string. (Grep gate: no `r =`, no `%`, no `p `, no
  regression math anywhere near the scatter — RESEARCH Pitfall 5 warning signs.)
- **A NEUTRAL caption only:** `ExploreCopy.scatterCaption(days:)` → "Based on {N} days where both were
  logged." The `{N}` digit is a FACTUAL tally (the sum of `count` across cells = the both-logged-day total),
  legal exactly like `InsightsCopy.supportingEvidence`'s "Seen across {n} logged days" — it is a count, not
  a statistic.
- The gated correlation engine remains the ONLY surface allowed to say "possible association"; the scatter
  shows raw points + the count caption and nothing more.

### Chart accessibility (REQUIRED — the scatter is never the sole carrier of meaning)

- A **one-line text summary** accompanies the plot via `ExploreCopy.scatterSummary(x:y:days:)` →
  "{X displayName} compared with {Y displayName}, {N} days where both were logged." This is the non-gesture
  parity: a VoiceOver user gets the point count + both axis names + the both-logged basis without seeing the
  cloud. (An Audio Graph implies a single value axis and would be LESS honest for a 2-axis cell cloud than a
  plain summary — the worded summary IS the a11y path here, mirroring the Phase-15 event-lane decision.)
- Per-mark `.accessibilityLabel` / `.accessibilityValue` carry the cell's real-unit values + count via the
  same `SeriesNormalization.readout` vocabulary (e.g. label "pelvic pain severity 7 of 10, stress 2 of 10",
  value "4 days") so VoiceOver can read each occupied cell.
- Charts respect **Reduce Motion** (no animated point transitions; render final state) and **Dynamic Type**
  (reduce tick density, never clip).

## Component & Interaction Inventory (native, phase-specific)

### A. The `Lanes | Scatter` mode toggle (SCAT-01)

- A **segmented `Picker`** pinned at the TOP of `ExploreView`'s content column (above the existing picker
  block), bound to a new ephemeral `@State` mode enum (`.lanes` / `.scatter`), default **`.lanes`** so the
  shipped Explore behavior is unchanged until the user opts into Scatter.
- Segment labels: **"Lanes"** (`square.stack.3d.up`) and **"Scatter"** (the RESERVED `chart.dots.scatter`).
  Labels via `ExploreCopy` (`modeLanes` / `modeScatter`), never literals.
- The mode is **ephemeral view `@State`**, NEVER persisted (consistent with the Phase-15 LOCKED privacy
  call — persisting a Scatter-interest would leak health-interest metadata outside the consent-gated store).
- Switching to Scatter swaps the lanes block for the axis-picker + plot block; the disclaimer + the screen
  scaffold are unchanged.
- **A11y identifiers:** `explore.mode` (the segmented control), `explore.mode.lanes`, `explore.mode.scatter`.

### B. The two-axis picker (SCAT-01) — quantitative-only

- In Scatter mode the picker surface presents **exactly two axis selectors, X and Y**, each choosing ONE
  series from the **quantitative-only** catalog: `ExploreSelection.offered(suppressed:)` filtered to
  `scaleKind.isQuantitative` (so presence/event series — food, clots, PRN, medication, bleeding-event — are
  NOT offered as axes; `bleeding.intensity`/`bleeding.event` remain hidden entirely under suppression).
- Each selector is a labelled control (a `Menu`/`Picker` of the quantitative series `displayName`s, "X" /
  "Y" labelled). Picking the SAME series for both axes is allowed (a self-vs-self diagonal is honest, if
  uninteresting) — no special-casing.
- Selection is **ephemeral view `@State`** (an X `ExploreSeries?` + a Y `ExploreSeries?`), NEVER persisted
  (same privacy invariant as the Lanes selection).
- **A11y identifiers:** `explore.scatter.axisX`, `explore.scatter.axisY`, and per-option
  `explore.scatter.axisX.<series.id>` / `explore.scatter.axisY.<series.id>` (stable, value-independent —
  the series id).

### C. The scatter plot (SCAT-01 / SCAT-02) — see Scatter Specification

- A single square `Chart` (`scatter-plot-height`) of `PointMark`s over the both-logged `[ScatterPoint]`,
  fixed real-unit X/Y domains, count-encoded mark size/opacity, worded X + Y axis titles, NO fitted line.
- Below the plot: the **neutral caption** (`ExploreCopy.scatterCaption(days:)`).
- **A11y identifiers:** `explore.scatter.plot` (the chart), `explore.scatter.caption` (the neutral caption),
  `explore.scatter.summary` (the worded text-summary a11y element).

### D. The two honest scatter states (SCAT-03)

| State | When | What the user sees |
|-------|------|--------------------|
| **Empty — "pick two factors"** | Scatter mode, but X and/or Y not yet chosen | The Phase-15 `honestState` pattern: `chart.dots.scatter` icon (`.secondary`), heading + body inviting the user to pick two factors. No empty axes, no placeholder cloud. id `explore.scatter.empty`. |
| **Sparse — "not enough overlapping days"** | Both axes chosen, but too few BOTH-logged days to plot meaningfully (e.g. < ~5 overlapping days) | An honest "not enough overlapping days to compare" state (NOT a near-empty plot read as "no association"). `.secondary`, no plot. id `explore.scatter.sparse`. |

- Absence stays absence in BOTH states — the view never fabricates a point. The both-logged-day threshold
  is computed from the `[ScatterPoint]` count sum (a pure, testable check), mirroring the Phase-15
  per-lane sparse test.

### E. The correlation-card deep-link (SCAT-04)

- On a `.correlation` `InsightCardView`, in the supporting-data area (alongside the existing words-only
  evidence line), add a **"See the days behind this"** affordance (`arrow.up.forward.square` + label) that
  opens Explore in **Scatter mode prefilled** with the card's two factors as X and Y.
- **The mapping is a TYPED carrier, never copy/string parsing** (the Phase-11 "direction from SIGNED effect,
  never parsed copy" discipline). The `.correlation` Insight's `signalKey` is
  `correlation.<factor.key>.symptom.<type>` or `correlation.<factor.key>.bleeding`. The app target adds a
  small, unit-tested resolver mapping `(factor.key, target)` → an OPTIONAL `(xSeries, ySeries)` pair of
  quantitative `ExploreSeries`:
  - **Quantitative factor → its severity/ordinal axis** + **symptom target → its `symptom.<type>.severity`
    axis.** Example: `stress.high` + `symptom.pelvicPain` → X = `stress` (0…10), Y =
    `symptom.pelvicPain.severity` (0…10). `mood.low` → `mood` (1…5). `bleeding` target →
    `bleeding.intensity` (1…4).
  - **Presence-only factors have NO quantitative axis** (food tags, activity, medication-taken, PRN,
    cycle-phase). For these, the resolver returns `nil` and **the affordance is HIDDEN** — the deep-link is
    shown ONLY when BOTH sides map to a quantitative axis (a presence factor cannot be a scatter axis;
    SCAT-01 / honesty constraint 5). This is the LOCKED behavior: no affordance rather than a broken or
    coerced axis.
  - A **suppressed** user: if the resolved Y is `bleeding.intensity` and the user is suppressed, the
    affordance is HIDDEN (the suppression gate carries through — never surface a bleeding axis).
- The deep-link CARRIES the resolved `(xSeries, ySeries)` value into Explore (sets the mode to `.scatter`
  and the X/Y `@State`); it NEVER re-derives the axes by parsing the audited public `.correlation` copy.
- Navigation seam: route through the dashboard's existing `NavigationStack` (`InsightsView`) — either a
  `navigationDestination` carrying the typed `(xSeries, ySeries)` payload, or a tab-switch-to-Explore with
  the payload threaded into `ExploreView` (the planner picks the exact seam; the contract is: a TYPED
  payload, prefilled, mode `.scatter`).
- The affordance copy is non-causal: **"See the days behind this"** — it points at the RAW evidence days,
  it does NOT restate or strengthen the association. Tapping it is a navigation, not a claim.
- **A11y identifiers:** `insights.card.<signalKey>.scatterLink` (stable, value-independent — hangs off the
  card's existing `idRoot`).

## Copywriting Contract

ALL new chrome copy is added to the EXISTING **`ExploreCopy`** enum's `auditableStrings` array and
**registered in `CopyAuditTests` in the SAME change** (constraint 7 / RESEARCH Pitfall 3). Mirror the
shipped `ExploreCopy` posture. The not-medical-advice framing is reused verbatim via `DisclaimerBanner`.
The per-point + caption value readouts route through `SeriesNormalization.readout(...)` (real unit, never a
statistic). The count digit (`{N}`/`{days}`) is a FACTUAL tally — legal exactly like
`ExploreCopy.eventLaneSummary` / `InsightsCopy.supportingEvidence`.

**SUBSTRING TRAPS — every string below is pre-verified against the `ClaimsPolicy` substring scans.**
Forbidden gendered tokens are hosted by `her` (⊂ together / whether / **other** / **higher** / there / here
/ she), `she`, `women`; forbidden verbs include `will`, `causes` / `cause` (⊂ be**cause**), `triggers`,
`predicts`, `treats` (`treat` ⊂ treatment). The copy below is curated to host **NONE** of these — verified
token-by-token in the table notes.

| Element | Copy (pre-verified) |
|---------|------|

> **SUBSTRING NOTE — "together".** The word **"together"** CONTAINS "her" (to·**get·her**) and is a
> `forbiddenGenderedTokens` host. The sparse-state body above MUST NOT ship the literal "together". The
> LOCKED replacement wording is: **"These two factors were logged on too few of the same days to plot. Keep
> logging and this fills in over time."** ("on the same days" carries the both-logged meaning with no
> forbidden host — "same" / "days" are clean). The executor uses THIS replacement; "together" is a rejected
> draft kept here only to document the trap (the same discipline that rejected "another" in Phase 15).

**Copy posture rules (enforced — `ClaimsPolicy` + `CopyAuditTests`):**
- **Descriptive only.** NO causal/diagnostic verbs (cause / causes / triggers / predicts / treats / will),
  NO association/confidence wording on the scatter (the gated engine owns "possible association"; the
  scatter does NOT restate it), NO r-value / % / p-value / coefficient — by acceptance criterion AND scan.
- **No gendered tokens** ("her" / "she" / "women" …) including the "higher"/"other"/"together"/"whether"
  traps; the table above is curated token-by-token, and the "together" trap is explicitly resolved.
- **Absence ≠ zero** — the empty-state body states it in words ("never counted as zero"); the view never
  plots a missing-factor day.
- **The deep-link is a navigation, not a claim** — "See the days behind this" points at raw evidence; it
  does not strengthen or restate the association.
- **Register first:** every new `ExploreCopy` string is added to `auditableStrings` AND `CopyAuditTests`
  in the SAME change that introduces it, BEFORE any view renders it (RESEARCH Pitfall 3). The interpolated
  forms (`scatterCaption(days:)`, the per-point readout, `scatterSummary(x:y:days:)`) register a
  representative instance (static prefix/suffix audited; the name + count interpolated — same posture as
  `eventLaneSummary`).

## Accessibility Contract (first-class — endo audience)

| Dimension | Requirement |
|-----------|-------------|
| Touch targets | Every interactive element ≥ **44pt × 44pt** (HIG): the `Lanes | Scatter` segmented control, each X/Y axis selector, the correlation-card deep-link affordance. |
| Color independence | The day-`count` is encoded by mark **SIZE / opacity + the worded per-point readout** ("{N} days — …"), NEVER hue alone. The two axes are told apart by **worded titles + distinct value domains + tick labels**, never color. The scatter uses a single accent hue for all marks (count is the only varying encoding, and it is size/text, not hue). |
| Charts (scatter) | A worded **one-line text-summary** (`explore.scatter.summary`) gives point count + both axis names + the both-logged basis WITHOUT the plot — the non-gesture a11y path (an Audio Graph would imply a single value axis and is LESS honest for a 2-axis cell cloud). Per-mark `accessibilityLabel`/`accessibilityValue` (real-unit cell values + count) for VoiceOver. Reduce Motion disables point animation; Dynamic Type scales axis labels (reduce tick density, never clip). |
| Honest absence (a11y) | A day missing a factor is exposed as a MISSING mark (no point, never "0"); the empty state reads "Pick two factors to compare."; the sparse state reads "Not enough overlapping days yet."; a logged literal `(0,0)` IS a real readable point. A suppressed user is never offered a bleeding axis NOR a bleeding-axis deep-link (provable by the option's / affordance's absence). |
| Deep-link reachability | The "See the days behind this" affordance is a real, focusable, labelled element on the card (`insights.card.<signalKey>.scatterLink`) — reachable by VoiceOver, not gated behind a gesture. |
| Dynamic Type | All text uses named text styles; the plot, axis labels, caption, and honest-state copy reflow (no clipping) to the largest accessibility sizes; multi-line copy uses `.fixedSize(…, vertical: true)`. |
| Descriptive-only (a11y) | VoiceOver never announces a fitted line, r-value, %, p-value, or "possible association" on the scatter — the scatter carries none of that chrome; it reads plain real-unit cell values + a factual day count. |
