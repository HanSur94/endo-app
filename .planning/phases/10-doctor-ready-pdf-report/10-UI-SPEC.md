# Phase 10 — UI Design Contract

> Visual and interaction contract for the Doctor-Ready PDF Report. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Two distinct surfaces are specified here:**
> - **Surface 1 — On-screen SwiftUI** (report-builder + PDFKit preview + ShareLink). MUST match the existing app's calm, plain, privacy-first SwiftUI language — system colors, `Form`/`List` sections, semantic Dynamic Type text styles, the existing `DisclaimerBanner` and pill/badge styles. NO new design system.
> - **Surface 2 — The PDF document** (a print artifact). Needs its own clinician-credible, black-on-white, vector layout with explicit point-based typography/margins, because CoreGraphics has no SwiftUI semantic styles to inherit.
>
> shadcn gate: **NOT APPLICABLE** — this is a native iOS SwiftUI app, not React/Next.js/Vite. Design system = first-party SwiftUI + an app-local PDF design token set. Registry safety: not applicable.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native SwiftUI + app-local PDF tokens) |
| Preset | not applicable |
| Component library | first-party SwiftUI (`Form`/`List`/`NavigationStack`) + PDFKit (`PDFView`, `PDFDocument`) + CoreGraphics (`UIGraphicsPDFRenderer`) + SwiftUI `ImageRenderer` (chart→vector bridge) |
| Icon library | SF Symbols (system) |
| Font (on-screen) | SF Pro via SwiftUI semantic text styles + Dynamic Type (system default — never a custom font) |
| Font (PDF) | system serif/sans at fixed point sizes — see §"PDF Document Layout". Use a single typeface family throughout the PDF (San Francisco / Helvetica-class sans for legibility on screen + print); bold weight for headings only. |

**Source of established language (do not re-invent — reuse verbatim):**
- `DisclaimerBanner` (`Sources/EndoApp/Content/Disclaimer.swift`) — `info.circle` + `.footnote` `.secondary` text, `.padding(12)`, `.quaternary.opacity(0.5)` in `RoundedRectangle(cornerRadius: 10)`.
- `HealthSourceBadge` (`Sources/EndoApp/Features/Health/HealthSourceBadge.swift`) — `heart.text.square` + text, `.caption2` `.secondary`, `.padding(.horizontal, 8)/.vertical, 3)`, `.quaternary.opacity(0.5)` in `Capsule()`.
- Confidence pill (`InsightCardView.swift`) — text word + per-level SF Symbol shape, `.padding(.vertical, 4)/.horizontal, 8)`, `.quaternary.opacity(0.5)` in `Capsule()`. Color is NEVER the sole carrier (text + shape).
- `SettingsView` `Form` + `Section(header:/footer:)` idiom — this is exactly where the report entry row and report-builder live.
- `CycleSummaryView` no-phantom-cycle three-state pattern (suppressed / not-enough-data / derived) — mirrored in the PDF cycle section.

## Spacing Scale

The app uses a **4-point base scale** (already established across `DisclaimerBanner`, `HealthSourceBadge`, `InsightCardView`, `CycleSummaryView`). Confirmed and reused; no new scale.

### On-screen (SwiftUI, points)

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight stacks (`VStack(spacing: 4)` cycle/sparse rows), pill vertical padding |
| sm | 8px | Card content `VStack(spacing: 8)`, pill horizontal padding, section gaps inside a card |
| md | 12px | Banner/card outer padding (`.padding(12)`), row spacing |
| lg | 16px | `Form` default row insets (system) |
| xl | 24px | Empty-state vertical padding (`.padding(.vertical, 24)`), major section breaks |

Exceptions (pre-existing in the established components — keep, do not "correct" to multiples of 4):
- `HealthSourceBadge` vertical padding = **3px** (the existing badge metric — match it exactly so the report's source tags are visually identical to the rest of the app).
- Inter-symbol `HStack(spacing: 4/6/10)` already in use; reuse the matching existing component's value rather than inventing one.
- Touch targets: every interactive control (preset buttons, Generate, Share, date pickers) stays on the system `Form`/`List` row, which already meets the 44px minimum — no custom hit areas.

### PDF document (points, 72 pt = 1 inch)

| Token | Value | Usage |
|-------|-------|-------|
| page-margin | 56px (≈0.78in) | Outer margin on all four sides of every page |
| section-gap | 24px | Vertical space before each major numbered section heading |
| block-gap | 12px | Space between a heading and its body, and between table/chart blocks |
| row-gap | 6px | Space between table rows / list lines |
| inline-gap | 4px | Gap between a value and its source tag |

## Typography

### On-screen (SwiftUI semantic styles — Dynamic Type, NEVER hardcoded px)

The app uses SwiftUI **semantic text styles** exclusively (so Dynamic Type + accessibility sizing work). Two effective weights: **regular** (body/caption/subheadline/footnote) and **semibold** (`.headline`). Reuse the existing role→style mapping verbatim:

| Role | Style | Effective Weight | Usage |
|------|-------|------------------|-------|
| Screen title | `.navigationTitle` (large title) | semibold | "Export report" nav bar title |
| Section/card heading | `.headline` | semibold | Builder section labels, cycle-day, empty-state heading |
| Body | `.body` | regular | Preset descriptions, primary copy |
| Secondary / detail | `.subheadline` | regular `.secondary` | Footers, helper lines, secondary detail |
| Caption / badge | `.caption` / `.caption2` | regular `.secondary` | Source tags, basis notes, "Generating…" |
| Disclaimer | `.footnote` `.secondary` | regular | `DisclaimerBanner` (reused verbatim) |

Line height: system default for each Dynamic Type style (do NOT override). Headings ≈1.2, body ≈1.4 as rendered by the system — never hand-set.

### PDF document (fixed point sizes — required because CoreGraphics has no semantic styles)

Exactly **4 sizes, 2 weights** (bold for headings, regular for body):

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Report title | 22pt | bold | 26pt (1.18) | "Endo-App — Self-Tracking Report" on the header (page 1) |
| Section heading | 14pt | bold | 18pt (1.29) | The 8 numbered section headings |
| Body / table cell | 10pt | regular | 14pt (1.4) | All data rows, tables, legend, summary prose |
| Caption / footer | 8pt | regular | 11pt (1.38) | Page footer disclaimer + "Page n of m", source tags, "From Apple Health"/"Self-reported" labels |

Color: **black `#000000` on white `#FFFFFF`** for body/headings (print-credible, max legibility). The PROMINENT header disclaimer renders in black at body-or-larger size inside a light-gray boxed band (see §Color) — never gray-on-white small print. Captions/secondary labels may use dark gray `#3C3C43` (matches iOS secondary label), never lighter than that on the PDF.

## Color

### On-screen (SwiftUI system colors — adaptive, Dark-Mode-safe)

The app uses **adaptive system colors only** (`.primary`/`.secondary`/`.quaternary`/`Color.accentColor`/`.red`). The 60/30/10 split is expressed via the system palette, not custom hex.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | system background (`Color(.systemGroupedBackground)` via `Form`) | Screen background, builder surface |
| Secondary (30%) | grouped `Form`/`List` row surface + `.quaternary.opacity(0.5)` pill/banner fills | Cards, sections, pills, disclaimer banner |
| Accent (10%) | `Color.accentColor` | See reserved-for list below |
| Destructive | `.red` (system) | Destructive role ONLY — see note |

**Accent (`Color.accentColor`) reserved for — explicit list:**
1. The primary **"Generate PDF"** call-to-action (the one prominent action on the builder).
2. The **"Share"** action in the preview toolbar.
3. The selected state of a date-range **preset segment** (Last 30 / Last 90 / Custom).
4. Chart line/point marks inside the embedded `InsightTrendChart` (already `Color.accentColor` — unchanged).

Accent is NEVER applied to: section chrome, source tags, the disclaimer, body text, or "all interactive rows."

**Destructive (`.red`) note:** Phase 10 has **NO destructive actions** (no delete/withdraw/overwrite in the report flow — the PDF is a throwaway temp file the user shares or discards). `.red` is therefore **not used anywhere in this phase**. (Existing `.red` usages — withdraw consent, remove med — live in pre-existing Settings sections, out of this phase's scope.) Source labels and the "not diagnostic" framing rely on **text + SF Symbol shape, never color**, matching the app's never-color-alone posture (`HealthSourceBadge`, confidence pill).

### PDF document (print palette)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white `#FFFFFF` | Page background |
| Secondary (30%) | light gray `#F2F2F7` fill + hairline rule `#D1D1D6` | Header disclaimer band, table header row fill, section rules, legend box |
| Accent (10%) | black `#000000` (NOT a hue) | Section headings, table header text, chart line (chart renders in a single ink color for print) |
| "Source" differentiation | **shape + text, never hue** | "Self-reported" = open-circle glyph + text; "From Apple Health" = `heart.text.square`-equivalent glyph + text. The legend explains both. A clinician printing in grayscale MUST be able to tell sources apart — so they are distinguished by glyph + word, never by color. |

The PDF is intentionally near-monochrome (black ink on white, gray bands for structure) — this is the clinician-credibility choice (D-01/D-04), not a stylistic limitation.

## Copywriting Contract

All copy routes through **`ClaimsPolicy`** (non-causal verbs, no gendered tokens incl. the "her" substring, not diagnostic) and is added to the existing `CopyAuditTests` scan. Mirror the existing auditable-copy pattern (`CycleSummaryCopy`, `InsightsCopy`, `HealthConnectCopy`): centralize every fixed report string in one auditable enum (e.g. `ReportCopy`).

### Surface 1 — on-screen builder + preview

| Element | Copy |
|---------|------|
| Settings entry row | **"Export report"** (label) with `doc.text` SF Symbol; footer: "Create a PDF summary of a date range to share with your clinician. It's made on your device and only leaves it if you choose to share it." |
| Screen title | **"Export report"** |
| Primary CTA | **"Generate PDF"** |
| Preset options | **"Last 30 days"** / **"Last 90 days"** / **"Custom range"** |
| Custom range pickers | **"From"** / **"To"** (two `DatePicker`s, hidden unless "Custom range" is selected) |
| Preview share action | **"Share"** (`square.and.arrow.up` SF Symbol) |
| Empty state heading | **"Nothing to report yet"** |
| Empty state body | "Once you've logged a few days in this range, your report will fill in here. Try a wider range, or log a day first." (NB: avoid "there's"/"here's"/"will fill" tripping the ClaimsPolicy substring audit — final wording is the auditable enum's responsibility; this is the intent.) |
| Generating state | **"Generating your report…"** (non-blocking caption / `ProgressView`, mirrors `insights.updating` — never a fabricated result while computing) |

### Surface 2 — PDF document copy

| Element | Copy |
|---------|------|

| Header meta | "Generated {date} · Covers {range start} – {range end}" (date RANGE, never a single hard date) |
| PROMINENT header disclaimer (RPRT-02) | A boxed, body-or-larger black-on-light-gray band carrying the single-source-of-truth `Disclaimer.text` verbatim ("…not medical advice and not a medical device… does not diagnose, treat, cure, or prevent…"). MUST be visually prominent (top of page 1, boxed), not footer fine print. |
| Per-section / per-value source tags (RPRT-02) | **"Self-reported"** / **"From Apple Health"** — driven by the Phase-9 `daySnapshotSources` provenance; **"Mixed"** when a section blends both. Glyph + word, never color. |

## Component & Interaction Inventory

### Surface 1 — On-screen flow (matches existing SwiftUI language)

1. **Settings entry row** — a `NavigationLink` row inside the existing `SettingsView` `Form` (its OWN `Section`, placed near Privacy), `Label("Export report", systemImage: "doc.text")`. a11y id `settings.report.entry`. Reuses the exact Settings row idiom.

2. **Report-builder screen** (`ReportBuilderView`) — a `Form` (NOT a custom layout), pushed onto the shell's `NavigationStack`, `navigationTitle("Export report")`, a11y id `report.builder`:
   - Section 1: range presets — a segmented `Picker` (`Last 30 days` / `Last 90 days` / `Custom range`), selected segment uses `Color.accentColor`. a11y id `report.range.preset`.
   - Section 2 (conditional, only when Custom): two `DatePicker`s "From"/"To" (`.date` components), a11y ids `report.range.from` / `report.range.to`. Inline invalid-range message when To < From.
   - Section 3: a prominent **"Generate PDF"** button (`Color.accentColor`, `.disabled` until range valid), a11y id `report.generate`. While generating, swap to a non-blocking "Generating your report…" caption + `ProgressView` (never block the screen).
   - Empty state: if the chosen range has effectively no logged data, the Generate path still produces an honest PDF (sections read "Not enough data in this range"); the builder itself shows the empty-state copy only if the WHOLE range is empty before generation.

3. **PDF preview screen** (`ReportPreviewView`) — presented (sheet or push) after generation, a11y id `report.preview`:
   - A PDFKit `PDFView` wrapped via `UIViewRepresentable` rendering the on-device `PDFDocument`. a11y id `report.preview.pdf`.
   - A toolbar **"Share"** action (`ShareLink` / `UIActivityViewController`) bound to the LOCAL temp/Documents file URL, `square.and.arrow.up`, `Color.accentColor`, a11y id `report.share`. **No automatic upload** — share fires only on this explicit tap (RPRT-03/D-09). Verifiable: the report module imports no `URLSession`/network.
   - Dismissing the preview discards the temp file. No confirmation (non-destructive).

4. **Reused components (verbatim):** `DisclaimerBanner` MAY also be pinned on the builder so the framing is visible before generation; `HealthSourceBadge` style and the confidence-pill style are mirrored INTO the PDF (not the live screen) for source tags.

### Surface 2 — PDF document structure (D-04 section order)

A multi-page, auto-paginated, US-Letter (or A4) vector document via `UIGraphicsPDFRenderer`. Section order:

1. **Header** (page 1) — app title, "Generated {date} · Covers {range}", and the PROMINENT boxed "self-tracked, not diagnostic" disclaimer band (RPRT-02).
2. **Summary / coverage** — days logged in range, sources present, a one-line honest coverage statement.
3. **Symptoms & pain** — a trend table (symptom · severity range · days logged) + an embedded vector chart (reuse `InsightTrendChart` via `ImageRenderer` into the `CGContext`, D-02). Per-row source tag.
4. **Cycle & bleeding** — the honest cycle summary mirroring `CycleSummaryView` (suppressed / not-enough-data / derived — NO phantom cycle). Bleeding days as a dated table.
5. **Lifestyle factors** — sleep / activity / food / stress / mood, each as a compact table or sparkline; absence ≠ 0 (an unlogged factor reads "Not logged", never 0).
6. **Insights** — the gated Trends / cycle-phase / associations for the range, honesty preserved (confidence words, non-causal copy). Sparse → "Not enough data…".
7. **Source legend** — explains "Self-reported" vs "From Apple Health" vs "Mixed" (glyph + text, never color).
8. **Footer** (every page) — "Self-tracked, not diagnostic · Endo-App" + "Page n of m".

**Pagination:** auto-paginate with a repeating top margin + footer on every page; a section heading never orphans at the very bottom of a page (carry it to the next page with its first block).

**Chart embedding (D-02):** charts render via SwiftUI `ImageRenderer` into the PDF `CGContext` as **vector** (`render { ... cgContext }`), NOT raster `UIImage` snapshots — crisp on print/zoom, small file (per CLAUDE.md "prefer the CG/PDF path over raster"). The chart ink is a single print color (black), keeping the never-color-alone posture; the chart is always accompanied by the table so it is never the sole carrier of meaning (mirrors `InsightTrendChart`'s text-summary rule).

## Accessibility Contract

- **Never color alone** (both surfaces): source labels, confidence, and the disclaimer all carry **text + shape/glyph**. The PDF is fully legible in grayscale print (clinician-credible).
- **On-screen:** every control keeps its system `Form`/`List` a11y; pills/badges combine into one VoiceOver element (mirror existing); Dynamic Type scales all text (no fixed px on screen); Reduce Motion respected by any embedded chart.
- **PDF:** text is selectable/searchable vector text (NOT rasterized) so it is screen-reader-friendly when opened in Preview/Files and crisp when printed.

---

## Honesty Contract (load-bearing — the endo pitfall)

- **Absence ≠ 0** everywhere: an unlogged factor/day reads "Not logged" / "Not enough data", never 0 or a fabricated value (mirror `TrendsEngine`/`CycleSummaryView`).
- **No phantom cycle**: the PDF cycle section reuses the three-state `CycleSummaryView` logic (suppressed / not-enough-data / derived) — never invents a 28-day cycle or a phase for a suppressed/irregular user.
- **Sparse/suppressed range** → the report reads "Not enough data in this range" per section, NEVER a fabricated full normal report.
- **All copy** passes `ClaimsPolicy` (non-causal, non-diagnostic, no gendered tokens) via the `CopyAuditTests` choke-point — both the on-screen `ReportCopy` enum and the PDF string surface.
- **No silent upload**: the report module makes zero network calls (no `URLSession`/upload import — grep-verifiable); the PDF is a local file shared only on explicit `ShareLink`/share-sheet action (RPRT-03/D-09).
