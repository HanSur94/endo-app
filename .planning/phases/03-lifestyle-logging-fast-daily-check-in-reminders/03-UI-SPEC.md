# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3 (Lifestyle Logging + Fast Daily Check-in & Reminders).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM:** Native **iOS app in SwiftUI** — NOT web/CSS/React. The design system is Apple-native:
> SF Symbols, system semantic colors, Dynamic Type text styles, native SwiftUI controls, and the Apple
> Human Interface Guidelines (HIG). The template's web-oriented fields (px spacing, hex colors,
> shadcn/Tailwind, line-height ratios) are adapted to their SwiftUI equivalents below. Where a web field
> has no native analogue it is marked `not applicable (native iOS)`.
>
> **AUDIENCE:** Endometriosis patients — accessibility is a first-class requirement, not an afterthought:
> ≥44pt touch targets, severity/intensity is NEVER color-only, full VoiceOver + Dynamic Type support,
> and a list/text fallback for every visual control.
>
> **HONESTY CONSTRAINT (cross-cuts the whole phase):** Absence of a symptom/factor is **"not logged"**,
> NEVER **"0 = healthy"**. Every control must visually and programmatically distinguish *unlogged* from a
> *logged zero/low value*. Reminder copy is gentle — no streak-shaming, no guilt framing (D-21).

## Spacing Scale

Native iOS does NOT use a web px scale. Spacing is expressed in **points (pt)** and, wherever possible,
delegated to **system defaults** (`Form`/`List` inset grouping, default `Section` spacing). Declared
values mirror the multiples-of-4 scale Phase 2 already uses (`spacing: 8`, `.padding(.leading, 28)`,
`.padding(.vertical, 2)`).

| Token | Value (pt) | Usage |
|-------|-----------|-------|
| xs | 4 | Tight inline gaps (`VStack(spacing: 4)` row title↔subtitle, as in `HomeView.dayRow`) |
| sm | 8 | Default control/label spacing (`VStack(spacing: 8)`, preset button row — matches `SeverityControl`) |
| md | 16 | Default element spacing within a section (system `Form` default) |
| revealed-control-indent | 28 | Leading indent for a control revealed under a selected row (`.padding(.leading, 28)`, matches the `SeverityControl` reveal in `DayLogEditorView`) |
| lg | 24 | Larger inter-group gaps where system default is insufficient |

**System-default first:** Do NOT hand-roll section/page padding. Use `Form { Section { … } }` and let the
grouped-inset list supply standard margins, exactly as `DayLogEditorView` and `SettingsView` do.

**Touch targets:** Every interactive element (factor chips, taken-toggles, "Same as yesterday", segmented
controls, check-in section confirms, reminder-time rows, add/remove med buttons) MUST have a **≥44pt × 44pt**
hit area (HIG minimum). Tag chips use `controlSize` no smaller than `.regular` for tap targets; the
`controlSize(.small)` preset buttons inherited from `SeverityControl` keep their ≥44pt row because they sit
in a tappable `Form` row.

Exceptions: none beyond the system-default and 44pt-minimum rules above.

## Typography

Native iOS uses **semantic Dynamic Type text styles**, NOT fixed px sizes or line-height ratios. Declaring
fixed sizes would BREAK Dynamic Type (an accessibility requirement for this audience). The contract is
expressed as text styles + weights; the system supplies size and line height per the user's Dynamic Type
setting. These mirror the styles already used in Phase 2 (`.headline`, `.subheadline`, `.subheadline.monospacedDigit()`).

| Role | SwiftUI text style | Weight | Used for |
|------|--------------------|--------|----------|
| Section header | `.headline` (system) | semibold (system default for the style) | `Section("…")` headers; day-row primary line (`HomeView.dayRow` uses `.headline`) |
| Body / row label | `.body` | regular | Factor labels, tag labels, picker option labels, check-in row titles |
| Secondary / caption | `.subheadline` and `.footnote`/`.caption` | regular | Secondary summary lines, section `footer` explanatory copy, "not logged" hints, units (mins/hours) |
| Numeric value | `.subheadline.monospacedDigit()` | regular | Numeric readouts (duration, hours, `n/10` — matches `SeverityControl`'s `"\(severity)/10"`) |

Rules:
- **Exactly these four roles** — do not introduce additional ad-hoc font sizes.
- **Never** use `.font(.system(size: <fixed>))` for content text; always a named text style so Dynamic Type
  scales it (one exception: monospaced-digit numeric readouts, which still use the **`.subheadline` named style** as the base).
- All text must remain legible and not truncate at the largest accessibility Dynamic Type sizes; multi-line
  copy uses `.fixedSize(horizontal: false, vertical: true)` where a row would otherwise clip.

## Color

Native iOS uses **semantic system colors** that auto-adapt to Light/Dark Mode and accessibility contrast
settings — NOT app-defined hex values. Hardcoding hex would break Dark Mode and contrast adaptation. The
60/30/10 split is expressed in semantic terms; the app already follows this in Phase 2.

| Role | Semantic value | Usage |
|------|----------------|-------|
| Dominant (60%) | `Color(.systemGroupedBackground)` / system `Form` background; text in `.primary` | The grouped-list canvas behind every screen (check-in sheet, editor, settings) |
| Secondary (30%) | `Color(.secondarySystemGroupedBackground)` (grouped cell surface); text in `.secondary` | `Section`/row card surfaces, footer/secondary copy, the "not logged" placeholder state |
| Accent (10%) | `Color.accentColor` (the app tint) | See reserved-for list below |
| Destructive | `.role(.destructive)` / `Color.red` (system) | ONLY the destructive confirmations listed in the copywriting contract |

**Accent (`Color.accentColor`) is reserved EXCLUSIVELY for:**
- The **selected/logged state** of a factor control (selected food tag, chosen activity type, chosen sleep
  quality, the `checkmark` on a logged option, a "taken" med marker) — exactly mirroring `DayLogEditorView`'s
  `checkmark.circle.fill`/`checkmark` tint.
- The primary **"Daily check-in"** Home CTA label/icon and the check-in sheet's confirmation action.
- The **interactive value** of system controls that already tint themselves (`Slider`, `Toggle` on-state,
  `DatePicker`) — system behavior, left as-is.

Accent is NEVER used for: decorative fills, every interactive element indiscriminately, body text, or
section backgrounds.

**Color-independence (MANDATORY — accessibility):**
- Severity, stress, mood, sleep quality, and activity intensity are **NEVER conveyed by color alone**.
  Every such value MUST also carry a **text label and/or SF Symbol and/or numeric readout** (e.g. stress
  shows `"7/10"`; mood shows a label like "Okay" plus its position; sleep quality shows "Poor / Okay / Good"
  text; intensity shows "Low / Medium / High" text). This mirrors `SeverityControl`'s always-visible `n/10`.
- Selection state uses a **shape/symbol change** (`circle` → `checkmark.circle.fill`, or a trailing
  `checkmark`), never a color swap alone — carried verbatim from `DayLogEditorView`.

**Unlogged vs. logged-zero (the honesty constraint, visual rule):**
- An **unlogged** factor section renders an explicit neutral placeholder in `.secondary` (e.g. "Not logged")
  and its control sits in a visibly **unset** state — NOT at "0", NOT pre-filled.
- Controls that *can* hold a low/zero value (stress `0/10`, mood `1`) MUST distinguish "no value selected"
  (nil → "Not logged") from "a low value was deliberately logged". Reuse the Phase 2 convention: `nil`
  binding = unlogged; a tapped value = logged. The `SeverityControl` only appears for stress **after** the
  user opts to log stress, so an untouched section never implies "0 = no stress".

## Component & Interaction Inventory (native, phase-specific)

This section is the executor's interaction source of truth. It supplements the web template, which lacks a
control-inventory field.

### A. Factor sections added to `DayLogEditorView` (LIFE-01/02/03, D-09)

Added as new `Section`s in the existing `Form`, following the exact symptom-section pattern (tappable row,
SF-Symbol selection state, revealed sub-control on selection, a11y identifiers `daylog.factor.*`):

| Factor | Control | States & rules |
|--------|---------|----------------|
| **Food** (LIFE-01, D-03) | Multi-select **trigger-category tag list** (`FoodTag` enum) — tappable rows with `circle`→`checkmark.circle.fill` (mirrors symptom multi-select) + an optional free-text `TextField` ("Anything else?", `axis: .vertical`, bounded at the `maxNoteLength` seam). NOT a calorie/macro diary. | No tag selected + empty text = **not logged**. Each tag is independent; "Something else" free-text is an escape hatch (D-02). |
| **Activity** (LIFE-02, D-04) | **Type** (`ActivityType`: walking, cardio, strength, yoga/stretching, other) as a single-select list (trailing `checkmark`); **duration** in minutes via `Stepper`/numeric field (`.monospacedDigit()`); **intensity** (low/med/high) as a `Picker(.segmented)` with **text labels**. | Section unlogged until a type is chosen. Duration shows units ("min"). Intensity text-labelled (never color-only). |
| **Sleep** (LIFE-03, D-05) | **Duration** in hours (`Stepper`/numeric, `.monospacedDigit()`, e.g. 0.5h steps) + **quality** (`SleepQuality`: poor/okay/good) as a segmented `Picker` with **text labels**. | Unlogged until the user sets either field. Quality text-labelled. |
| **Medication** (LIFE-03, D-06) | Per-day list of the user's **saved meds**, each a `Toggle`-style "taken today" row (label + optional type/note), plus a single **PRN pain-relief** marker toggle. A "Manage meds" affordance (add/edit/remove saved meds) lives in **Settings** (small user-maintained list, bounded strings). | A med not toggled = **not taken / not logged** (NOT "skipped" as a clinical claim). Empty saved list shows an empty-state pointing to "Add a medication" in Settings. |
| **Stress** (LIFE-03, D-07) | **Reuse `SeverityControl` (0–10) verbatim.** Appears only after the user opts to log stress (a "Log stress" reveal row, same pattern as a selected symptom revealing its severity). | `nil` = **not logged**, NEVER "0 = no stress / healthy". The 0 end of the scale is a *logged* low value, distinct from absence. |
| **Mood** (LIFE-03, D-08) | **Day-level mood, 1–5 valence**, as a row of 5 selectable options with **text labels** + SF Symbols (e.g. a 1–5 labelled segmented control or symbol row). Kept **visually and semantically distinct** from the Phase-2 "Low mood" *symptom*. | Unlogged until a value is tapped. Must read clearly as "overall mood for the day", not an acute symptom. Text-labelled, never color-only. |

### B. New fast "Daily check-in" sheet (CHCK-01, D-13/14/15/16)

- **Form factor:** a single **scrollable, sectioned `Form` in a `.sheet`** (`NavigationStack` inside, like the
  editor presentation in `HomeView`). One screen, smart defaults, nothing mandatory (D-15).
- **Sections (in order):** quick **symptom** chips → **factor** sections (food/activity/sleep/meds/stress/mood)
  → **bleeding** (reusing the Phase-2 flow control). Each section is independently skippable/confirmable.
- **"Same as yesterday" affordance (D-14):** a prominent control near the top that **prefills STICKY CONTEXT
  ONLY** — meds taken, typical sleep, activity type. It **NEVER** auto-carries symptoms or bleeding (those are
  events; carrying them forward fabricates data). Prefilled values are clearly marked as prefilled and fully
  editable before saving.
- **Empty confirm (D-15):** confirming with nothing entered records a lightweight **"checked in today"
  adherence marker** WITHOUT inventing any symptom/factor data.
- **Entry points (D-16):** (1) a prominent Home **"Daily check-in"** CTA `Section`/`Button` (above or beside
  the existing "Log today" button, accent-tinted, SF Symbol e.g. `checkmark.circle`); (2) tapping the
  reminder **notification deep-links** straight into this sheet.
- **A11y identifiers:** `checkin.sheet`, `checkin.sameAsYesterday`, `checkin.section.<factor>`,
  `checkin.confirmButton` — following the `daylog.*` / `home.*` convention the E2E harness drives.

### C. Reminders settings section (CHCK-02, D-17/18/19/20)

Added as a `Section` (with explanatory `footer`, matching `SettingsView`'s style) in `SettingsView`:

- **Master toggle: OFF by default** (D-18). Off-state shows gentle one-line explanation in the `footer`.
- On enabling: **just-in-time permission** request (D-20) — only here, never at launch/onboarding. If denied,
  the section reflects the **denied state** with a non-nagging line + a path to **Settings.app** (e.g.
  "Notifications are off for Endo-App. You can turn them on in Settings.").
- **One or more daily reminder times** (D-18): start by suggesting a single sensible evening default; user can
  add/remove times via `DatePicker(.hourAndMinute)` rows.
- **Quiet hours** (D-19a): a start/end window (`DatePicker`s) during which no reminder fires.
- Fatigue behavior (D-19b/c — non-visual but contract-relevant): the day's reminder auto-suppresses once the
  user has checked in/logged that day; no repeat-nagging within a day. The settings copy may state this
  reassurance gently.
- **A11y identifiers:** `settings.reminders.masterToggle`, `settings.reminders.addTime`,
  `settings.reminders.timeRow.<index>`, `settings.reminders.quietHoursStart/End`, `settings.meds.add`.

## Copywriting Contract

All copy routes through the **`Terminology` + `ClaimsPolicy`** choke-points (D-21): non-gendered,
non-diagnostic, non-causal, audited against `ClaimsPolicy.forbiddenVerbs` / `forbiddenGenderedTokens`.
Reminder copy is **gentle and non-coercive** — no streaks, no guilt, no "you missed…".

| Element | Copy |
|---------|------|
| Primary CTA (Home) | **"Daily check-in"** (verb-noun; opens the fast sheet, D-16) |
| Check-in confirm button | **"Done for today"** (gentle, non-coercive; records the day / adherence marker) |
| "Same as yesterday" control | **"Same as yesterday"** — subtitle: "Brings back your usual meds, sleep and activity. Symptoms and bleeding are never carried over." |
| Check-in empty-confirm (adherence) | Toast/inline: **"Checked in for today."** (no symptom data invented, D-15) |
| Empty state — meds list (no saved meds) | Heading: **"No medications saved yet."** Body: **"Add the medications you want to keep track of in Settings, and they'll appear here to tick off each day."** |
| Empty state — factor section unlogged | Inline placeholder, `.secondary`: **"Not logged"** (NEVER "0" / "None" / "Healthy") |
| Empty state — reminders off | Footer: **"Reminders are off. If you'd like a gentle nudge to check in, you can turn them on below — they always respect your quiet hours."** |
| Reminder notification body (gentle) | Title: **"Endo-App"** · Body: **"Whenever you have a moment, here's your daily check-in."** (no guilt, no streak, opt-out-respecting) |
| Permission-denied (reminders) | **"Notifications are turned off for Endo-App. You can turn them on anytime in Settings."** (with a button to open Settings.app) |
| Error — notification scheduling failed | **"We couldn't set that reminder right now. Please try again, or check notification permissions in Settings."** |
| Error — save failed (factor write) | **"That didn't save. Please try again — nothing has been lost from what you already logged."** |
| Destructive — remove a saved medication | Confirmation: title **"Remove this medication?"** · message **"This stops it from appearing in your daily check-in. Days you already logged it as taken are not changed."** · buttons **"Remove"** (`.destructive`) / **"Cancel"** (`.cancel`) — `.confirmationDialog`, matching the Phase-2 delete pattern. |
| Destructive — remove a reminder time | Inline swipe-to-delete / minus button; no modal needed (low-stakes, reversible by re-adding). Label: **"Delete"** (`.destructive` swipe action, like `home.dayRow.delete`). |

**Copy posture rules (enforced):**
- No causal/diagnostic verbs ("trigger", "causes", "worsens", "treats", "fixes") in any factor label, check-in,
  or reminder text — these are *contextual factors* being *captured*, not diagnosed.
- No gendered tokens; bleeding noun resolves through `Terminology.bleedingNoun`.
- No streak/guilt framing anywhere ("don't break your streak", "you missed yesterday", "X days in a row" are
  all forbidden).
- "Not logged" / "Not taken" are the absence words — never "0", "None", or anything implying healthy/zero.

## Accessibility Contract (first-class — endo audience)

| Dimension | Requirement |
|-----------|-------------|
| Touch targets | Every interactive element ≥ **44pt × 44pt** (HIG). |
| Color independence | Severity / stress / mood / sleep quality / intensity ALWAYS carry text and/or symbol and/or numeric value — **never color alone**. Selection = symbol/shape change, not a color swap. |
| VoiceOver | Every control has a meaningful `accessibilityLabel` and, for valued controls, an `accessibilityValue` (e.g. stress: "7 of 10", mirroring `SeverityControl`). Selected rows add `.isSelected`. Reminder times announce as "Reminder at 8:00 PM". |
| Dynamic Type | All text uses named text styles; layouts reflow (no clipping) up to the largest accessibility sizes; multi-line copy uses `.fixedSize(…, vertical: true)`. |
| List/text fallback | Any visual control (tag grid, mood symbol row, intensity segmented control) has a fully usable list/labelled-row form — no information is conveyed by visual layout alone. |
| Unlogged honesty (a11y) | "Not logged" is exposed to VoiceOver as the section's value when unset — an empty section never reads as "0" or "none/healthy". |
