## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HealthKit framework to app-side service | Untrusted, OS-owned HK samples cross here; must be mapped to Sendable value types before escaping (Swift 6 + privacy). |
| App-side value types to SwiftData store | `ImportedSample` rows are written to the local store and (when CloudKit active) mirrored to the user's PRIVATE iCloud DB. |
| App target to EndoInsights package | The Foundation-only boundary: HealthKit must never cross into the package (SC1). |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | `ImportedSample` columns mirrored to private CloudKit | mitigate | Store only category-level imported health values (flow raw, sleep hours/quality, activity type/minutes, ate-that-day) — same posture as `CachedInsight`; no free-text/note prose; documented in the model header. |
| T-09-02 | Tampering / DoS | Garbage/unknown HK sample values in mapping | mitigate | Every mapping function is total + defensive (unknown workout to `.other`, unknown flow to `nil`, unknown sleep stage excluded) — never crashes, never fabricates (V5 input validation); asserted by `HealthSampleMappingTests`. |
| T-09-03 | Tampering / data integrity | V5to V6 migration under CloudKit | mitigate | Purely additive (one new model) `.lightweight` stage — NEVER `.custom` (hooks don't fire under CloudKit, Pitfall 3); proven by the V5to V6 survival test. |

| T-09-SC | Tampering | npm/pip/cargo/SPM installs | accept | Zero new third-party packages — HealthKit/HealthKitUI are first-party Apple system frameworks (RESEARCH Package Legitimacy Audit: no install, no slopsquatting surface). |
