<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pre-consent ↔ health-data processing | The consent gate is the access-control boundary: no `@Model` health record is read/written until `ConsentState == .consented` (ONBD-01, GDPR Art. 9, ASVS V4). |
| App ↔ local SwiftData store | The only persistence surface; local-only (`.none`) in Phase 1, no network/sync, no external reader. |
| Control flags ↔ synced store | The consent flag lives in `UserDefaults`, deliberately OUTSIDE the SwiftData store so it never round-trips through CloudKit (RESEARCH Pattern 3 anti-pattern). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Repudiation / Compliance | Processing health data before consent (GDPR Art. 9) | mitigate | `AppGate` blocks all health-data processing until explicit opt-in; `WalkingSkeletonView` (the only write path) is reachable only from the `.consented` branch; `withdraw()` re-gates (ConsentGateTests proves it). |
| T-01-04 | Information Disclosure | Consent/health state pushed to CloudKit | mitigate | Consent flag stored in `UserDefaults`, not a synced `@Model`; container ships `.none` (no sync) in Phase 1 (D-10, RESEARCH Pattern 3). |
| T-01-05 | Tampering | Unsafe schema breaking future CloudKit sync (silent data loss) | mitigate | Schema designed CloudKit-safe from v1: no `@Attribute(.unique)`, all optional/defaulted, `VersionedSchema`; grep-gated in Task 1 acceptance. |
| T-01-06 | Information Disclosure | Health values leaked via logs / crash output | mitigate | Never log `DayEntry`/`BleedingEvent` field values; no print of health content in the skeleton write/read path; no crash/analytics SDK present (RESEARCH §Security Domain V7). |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No application package installs — all-first-party Apple frameworks (RESEARCH §Package Legitimacy Audit). No `[ASSUMED]`/`[SUS]`/`[SLOP]` packages. |
</threat_model>
