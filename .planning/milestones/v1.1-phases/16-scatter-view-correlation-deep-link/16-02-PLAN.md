<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user axis selection → ScatterPairing | the chosen X/Y series cross into the pure pairing layer (already-consented in-memory data) |
| scatter mode/X/Y state → process memory | ephemeral selection metadata must never persist (health-interest leak) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-06 | Information disclosure | persisted scatter mode/X/Y selection | mitigate | Ephemeral `@State` only; grep gate forbids `@AppStorage`/`@SceneStorage`/`UserDefaults` on the mode/X/Y state (LOCKED privacy invariant, mirrors `ExploreView.selection`) |
| T-16-07 | Information disclosure | suppressed user offered a bleeding axis | mitigate | `ScatterAxisPicker` options = `ExploreSelection.offered(suppressed:)` filtered to quantitative — `bleeding.intensity` is removed under suppression (defense-in-depth alongside the Phase-14 accessor gate) |
| T-16-08 | Tampering (honesty contract) | stats/jitter creep onto the scatter | mitigate | Grep gate over `ScatterPlotView.swift`: no `LinearRegression`/`regression`/`rValue`/`coefficient`/`Double.random`/`jitter`/`LineMark`; `PointMark` + `symbolSize` present; both domains via `SeriesNormalization.domain` (never data-driven) |
| T-16-09 | Information disclosure | scatter as sole carrier of meaning | mitigate | A worded `explore.scatter.summary` element + per-mark a11y labels carry point count + axis names + readouts without the plot; count is size+text, never hue alone |
| T-16-10 | Tampering | misrouted presence axis crashes the view | accept→mitigate | `ScatterPairing.pairs` degrades a wrong-kind axis to `[]` (the sparse/empty state), never a trap — the picker is quantitative-only so this is unreachable in practice |
</threat_model>
