# Phase 15 — UI Design Contract

> Visual and interaction contract for Phase 15 (Explore Tab & Overlay Lanes — EXPL-01..07).
> Generated by gsd-ui-researcher; verified by gsd-ui-checker.
>
> **PLATFORM:** Native **iOS app in SwiftUI + Swift Charts** — NOT web/CSS/React. The design system is
> the locked v1.0 app: SF Symbols, semantic system colors, Dynamic Type text styles, native SwiftUI
> controls, and Swift Charts on an absolute-date X-axis. Web-oriented template fields (px spacing, hex
> colors, shadcn/Tailwind, line-height ratios, registry) are adapted to their SwiftUI equivalents below;
> web-only fields are marked `not applicable (native iOS)`. The shadcn/registry gate is N/A — there is no
> component registry in a SwiftUI project (Apple system frameworks only, zero UI dependencies).
>
> **AUDIENCE:** Endometriosis patients. Accessibility is a first-class requirement: ≥44pt touch targets,
> no information by color alone, full VoiceOver + Dynamic Type, and a text/Audio-Graph fallback for every
> chart.
>
> **WHAT EXPLORE IS.** A new consent-gated **Explore** tab (third tab in `ConsentedShell`) where the user
> overlays multiple of their own logged series on one honest, shared time axis: **aligned per-scale
> quantitative lanes** (each in its REAL unit) plus **event-marker lanes** below, with ONE shared scrub
> state reading every visible series at once. Explore reads `Repository.daySnapshots()` directly and
> deliberately BYPASSES `InsightsEngine`/`HonestyGate` — those gate CLAIMS; Explore shows RAW descriptive
> data with no confidence pills, no associations, no causal framing. The scatter view is Phase 16 (out of
> scope here).
>
> **SIX HONESTY CONSTRAINTS THAT SHAPE EVERY PIXEL (carry over, LOCKED):**
> 1. **Unlogged days stay GAPS in every lane** — absence ≠ 0, never a 0, never an interpolated bridge.
>    Re-key Swift Charts `series:` per (data-series × contiguous-run) via `ChartSeriesGrouping` so no lane
>    connects across a gap (RESEARCH Pitfall 2). A logged literal 0 IS a plotted point (distinct from a gap).
> 2. **Per-scale lanes in REAL units** — each quantitative series in its own lane with its FIXED honest
>    `SeriesNormalization.domain` Y range; NO dual independent y-axis, NO silent 0–100 normalization
>    (RESEARCH Pitfall 4; the normalized "shape view" is explicitly out of scope for v1.1).
> 3. **Binary/event series are event-marker lanes** — date-aligned ticks/dots under the quantitative
>    lanes, NEVER a fake 0/1 line (RESEARCH Pitfall 6 / EXPL-04).
> 4. **Descriptive only** — no causal framing, no r-values, no "% impact", no confidence/association
>    chrome anywhere in Explore (it bypasses the gate; the gate's job is not duplicated here).
> 5. **ALL new chrome copy is `ExploreCopy`, registered in `CopyAuditTests` BEFORE it is written** — an
>    unregistered copy surface silently escapes the ClaimsPolicy substring scans (RESEARCH Pitfall 3).
> 6. **A chart is NEVER the sole carrier of meaning** — text-summary parity per lane; series colors are
>    colorblind-safe AND never the only signal (legend word + symbol/dash + lane-local axis label).
>
> **SUPPRESSION (LOCKED product call):** for a suppressed user the bleeding series are **hidden entirely**
> — the picker must NOT offer `bleeding.intensity` or `bleeding.event` chips (no empty lane, no
> offered-but-empty chip). Consistent with v1.0 suppress→section-omitted. The Phase-14 accessors already
> gate bleeding on `!snap.suppressed`; the picker filter is the UI half of the same invariant.

## Spacing Scale

Native iOS uses **points (pt)**, delegating to system defaults wherever possible. Declared values mirror
the multiples-of-4 scale Phases 2–3 and the Phase-8 dashboard already use. Explore's lanes get explicit,
named heights/insets so each lane's axis labels never clip at large Dynamic Type and the stacked lanes
stay vertically rhythmic.

| Token | Value (pt) | Usage |
|-------|-----------|-------|
| xs | 4 | Tight inline gaps (chip icon↔label, scrub-tooltip line spacing, lane-title↔lane gap) |
| sm | 8 | Default control spacing inside the picker / chip-to-chip gaps; lane vertical inset so top/bottom marks aren't clipped |
| md | 16 | Default element spacing / content inset between the picker block, the chart block, and the range control |
| lg | 24 | Inter-block gaps where the system default is insufficient (picker block ↔ lanes block ↔ states) |
| lane-quant-height | 120 | Each QUANTITATIVE per-scale lane's `Chart` frame height (`.frame(height: 120)`); reflows taller if axis labels need it at large Dynamic Type |
| lane-event-height | 44 | Each EVENT-MARKER lane's height — a single row of date-aligned ticks; also the ≥44pt touch floor when the lane is itself a scrub target |
| chart-vertical-inset | 8 | Per-lane plot vertical padding so the top/bottom marks + value labels are not clipped |

**System-default first:** do NOT hand-roll page padding. Compose the Explore screen as a `ScrollView`
(NOT a `List` — the chart is a fixed, free-scrub surface, NOT inside a scrolling List; this resolves the
Phase-13 scroll-vs-scrub tension by construction) with system-standard section margins. Chips wrap in a
flowing layout; the lanes stack in a `VStack(spacing: md)`.

**Touch targets:** every interactive element (each toggle chip, each range preset, the remove-to-add
affordance, any "remove" on a chip) MUST have a **≥44pt × 44pt** hit area (HIG). Event-marker lanes are
`lane-event-height = 44`.

Exceptions: none beyond the system-default and 44pt-minimum rules above.

## Typography

Native iOS uses **semantic Dynamic Type text styles**, NOT fixed px sizes or line-height ratios. Declaring
fixed sizes would BREAK Dynamic Type (an accessibility requirement for this audience). The contract is text
styles + weights; the system supplies size and line height. These mirror the Phase-8 dashboard styles.

| Role | SwiftUI text style | Weight | Used for |
|------|--------------------|--------|----------|
| Screen title | `.title2` (nav title) | semibold (style default) | "Explore" navigation title |
| Lane title / series legend | `.subheadline` | semibold | Each lane's series name + unit (e.g. "Pelvic pain severity — of 10"); the chip-derived legend label |
| Body / state copy | `.body` | regular | Empty-state ("pick a series") and sparse-state ("not enough data") body copy; the remove-to-add helper line |
| Chip label | `.subheadline` | regular (selected: semibold) | Each toggle chip's `displayName`; selected vs unselected differ by weight + fill + checkmark, never color alone |
| Scrub tooltip — date | `.caption` | semibold | The scrubbed day's absolute date header in the shared tooltip |
| Scrub tooltip — per-series value | `.caption` | regular | Each visible series' real-unit value line, or its "Not logged" line |
| Chart axis / value labels | `.caption` / `.caption2` (Swift Charts defaults) | regular | Per-lane absolute-date X tick labels + Y value labels — must stay non-clipping at large Dynamic Type |
| Disclaimer | `.footnote` | regular | The reused `DisclaimerBanner` (not-medical-advice framing) |

Rules:
- **Exactly these roles** — no ad-hoc font sizes. Never `.font(.system(size: <fixed>))` for content text;
  always a named style so Dynamic Type scales it.
- Multi-line state copy uses `.fixedSize(horizontal: false, vertical: true)` so honest framing never
  truncates.
- Chart axis labels use Swift Charts' built-in `.caption`-class styling; reduce tick density rather than
  clip at the largest accessibility Dynamic Type size.
- The lane title carries the series UNIT in words ("— of 10", "— h", "— min") so the real scale is legible
  without reading the axis (honesty constraint 2, text parity).

## Color

Native iOS uses **semantic system colors** that auto-adapt to Light/Dark Mode and accessibility-contrast
settings — NOT app-defined hex values. The 60/30/10 split is expressed in semantic terms.

| Role | Semantic value | Usage |
|------|----------------|-------|
| Dominant (60%) | `Color(.systemGroupedBackground)` / system background; text in `.primary` | The Explore canvas behind the whole screen and each lane's chart plot background |
| Secondary (30%) | `Color(.secondarySystemGroupedBackground)`; text in `.secondary` | The picker chip surfaces (unselected); the scrub-tooltip card surface; lane titles' unit suffix; empty/sparse placeholder copy; the disclaimer banner background (`.quaternary`) |
| Accent (10%) | `Color.accentColor` (the app tint) | See reserved-for list below |
| Per-series palette | Swift Charts `chartForegroundStyleScale` over a **colorblind-safe** ordered palette | Each selected quantitative series gets ONE stable hue from the palette, carried by `.foregroundStyle(by:)` — but ALWAYS paired with a per-series symbol/dash style + a labelled legend word (never hue alone) |
| Destructive | not used as a hue here | Removing a chip / clearing a series is a low-stakes, reversible preference — NOT a destructive red action. Use the secondary `xmark.circle`, never red. |

**Accent (`Color.accentColor`) is reserved EXCLUSIVELY for:**
- The **selected** state of a toggle chip (selected chip's fill/tint + checkmark) — the one "primary
  action" surface in the picker.
- The Explore **tab item's** selected tint (system tab behavior).
- System controls that already self-tint (segmented control selection, disclosure chevrons) — left as-is.

Accent is NEVER used for: an individual data series' line color (those come from the colorblind-safe
`chartForegroundStyleScale` palette, NOT the accent), every chip indiscriminately, body text, lane
backgrounds, or the scrub rule-mark (that is `.secondary`/gray chrome, as the Phase-13 dashboard scrub
already is).

**Color-independence (MANDATORY — accessibility):**
- **Selected vs unselected chips** differ by **fill + a checkmark/`xmark` symbol + font weight**, never
  hue alone — a grayscale or Smart-Invert user must tell selected from unselected by shape + text.
- **Each data series is distinguishable without color.** Per RESEARCH Pitfall 2, series carry a stable
  hue via `chartForegroundStyleScale` AND a **labelled legend** (the series `displayName`) AND, where two
  series ever share a lane scale, a distinct **symbol/dash** style. Each lane also has its own real-unit
  Y axis label. Color is a redundant cue, never the only one. (Grayscale + sparse-fixture screenshot
  checks are a phase verification item.)
- **The scrub rule-mark + tooltip are chrome, not data** — `.secondary`/gray (the Phase-13 precedent),
  so the data series stay the visual focus.

**Honest absence in charts (the honesty constraint, visual rule — carry over):**
- A **gap** (a day the user did not log THAT series) is an **actual gap / broken line** in that lane,
  NEVER interpolated and NEVER drawn as `0`. Reuse `ChartSeriesGrouping` per (series × contiguous-run);
  omit the mark for the unlogged date. Absence ≠ zero.
- A logged literal `0` (e.g. severity 0) IS drawn as a point at the lane's zero line — distinct from a
  gap (point-at-zero vs no-point-at-all), exactly as the dashboard already reads them.
- **Event-marker lanes** show a tick ONLY on days the event was logged (`occurrenceDays`); a day with no
  tick is "not logged that event", never "logged absent" — there is no "0/1 line" implying a continuous
  off-state.

## Swift Charts Specification (the executor's chart source of truth)

This section encodes the LOCKED lane layout, the shared scrub state, and the absence-≠-zero rule. It is
the central design decision of the phase (full-UI-rework recovery cost — prototype the lane composition
early, per RESEARCH Phase-3 flag).

### Lane layout (EXPL-03 / EXPL-04 — LOCKED)

- **One vertical stack of lanes, one shared absolute-date X axis.** Each selected QUANTITATIVE series
  renders in its OWN lane: a separate `Chart` of `lane-quant-height` with `LineMark` per (series ×
  contiguous-run) + `PointMark` per logged day, Y domain = `SeriesNormalization.domain(for: scaleKind)`
  (the FIXED honest range: `0…10`, `1…5`, `1…4`, `0…24`, `0…240`), real units. NO dual y-axis, NO
  normalization (constraint 2). Points come from `ExploreSeriesExtraction.quantitativePoints(...)`.
- **All lanes share ONE X domain** = the selected `TrendWindow`'s absolute-date range ending at the
  injected `today` (`.chartXScale(domain: windowStart...asOf)`), DST-safe, `.month().day()` ticks — the
  SAME axis vocabulary as the dashboard (EXPL-06). A sparse lane reads as "sparse over the window", never
  "N consecutive days".
- **Event-marker lanes sit BENEATH the quantitative lanes.** Each presence/event series
  (`scaleKind == .presenceEvent`) is a `lane-event-height` row of date-aligned ticks (`RuleMark` /
  `PointMark` at each `ExploreSeriesExtraction.occurrenceDays(...)` date on the shared X axis) — NEVER a
  0/1 `LineMark` (constraint 3 / EXPL-04). A day with no occurrence has no tick.
- **Lane vertical alignment:** every lane uses the IDENTICAL X scale + plot leading/trailing inset so a
  single vertical scrub line crosses all lanes at the same date (the shared-scrub requirement). Lane
  titles (`.subheadline` semibold) sit directly above each lane with the series name + unit.

### Shared scrub state (EXPL-05 — LOCKED)

- **ONE `chartXSelection`-bound selected date drives every lane.** Free scrub is OK here (the chart is NOT
  inside a scrolling List — resolves the Phase-13 scroll-vs-scrub tension). On scrub, resolve the day per
  series through the Phase-13 **`ChartScrubSelection`** resolver (exact-day match only — gap → no value;
  logged literal 0 → a real 0; NEVER nearest-neighbor / interpolation).
- **ONE shared multi-series tooltip** for the scrubbed day: a single card listing the absolute date once,
  then EACH visible series on its own line — the real-unit value via `SeriesNormalization.readout(...)`
  (e.g. "Pelvic pain severity: 6 of 10", "Sleep: 6.5 h") OR a **"Not logged"** line for that series if
  that day is a gap for it (gap-honest, never 0). Event lanes contribute a "logged" / "not logged" line
  for the scrubbed day. The tooltip is `.secondary` chrome; it lives while touching and dismisses on
  release (the Phase-13 lifecycle).
- A vertical `RuleMark` (gray, zIndex below the data) marks the scrubbed date across the aligned lanes.
- A **selection haptic** (one `UISelectionFeedbackGenerator` per view identity) fires on resolved-DAY
  change only (the Phase-13 precedent; nil↔day transitions silent).

### Axis contract (absolute date — NON-NEGOTIABLE, carry over)

- **X-axis = absolute calendar dates** anchored on the selected `TrendWindow`, ending at the injected
  `today`. NEVER cycle-relative. X domain is the full window even when sparse. Same `TrendWindow` family
  + range-preset vocabulary as the dashboard (EXPL-06).
- **Y-axis is per-lane and FIXED** to `SeriesNormalization.domain(for:)` so a series' shape is stable
  across window switches and the real unit is always legible.

### Chart accessibility (REQUIRED on every lane)

- Every mark carries `.accessibilityLabel` (date) / `.accessibilityValue` (real-unit value via the same
  `readout` vocabulary, e.g. "June 3, 6 of 10") so VoiceOver + the **Audio Graph** rotor can read each
  lane. Mirror `InsightTrendChart`'s `@preconcurrency AXChartDescriptorRepresentable` — ONE descriptor
  per quantitative lane (categorical day axis, the lane's fixed value domain, logged points only — gaps
  OMITTED, never zeros).
- A **per-lane one-line text summary** (the series name + window + a plain descriptive note) accompanies
  each lane so the information is available without seeing the chart (text parity — constraint 6).
- The **multi-series scrub readout is reachable WITHOUT the drag gesture** — expose the scrubbed-day
  values as VoiceOver-readable elements (the Phase-13 transparent-overlay-proxy pattern: Swift Charts does
  NOT expose `.annotation` content to the AX tree, so the readout + a11y ids ride a transparent overlay
  proxy, and the visual annotation is `.accessibilityHidden(true)`).
- Charts respect Reduce Motion (no animated transitions; render final state) and Dynamic Type (reduce
  tick density, never clip).

## Component & Interaction Inventory (native, phase-specific)

### A. The Explore screen (EXPL-01)

- **Container:** a `ScrollView` inside a `NavigationStack`, navigation title **"Explore"**. NOT a `List`
  (the lanes are a fixed free-scrub surface).
- **Persistent disclaimer:** the reused **`DisclaimerBanner`** (`Disclaimer.text`), `.footnote`,
  `.secondary`, `info.circle` symbol — pinned so the not-medical-advice framing is always visible, exactly
  as the dashboard ships it.
- **Top → bottom layout:** (1) the **series picker** (toggle chips); (2) the **range-preset** control;
  (3) the **lanes** block (quantitative lanes, then event lanes) with the shared scrub; OR (4) an honest
  **empty / sparse** state in place of the lanes.
- **Tab:** the THIRD tab in `ConsentedShell`, label **"Explore"**, SF Symbol **`square.stack.3d.up`**
  (distinct from Insights' `chart.line.uptrend.xyaxis`). The a11y id MUST be set on the **tab-item
  `Label`** (`tab.explore`) — a content-view id does NOT reach the tab-bar button (the Phase-8 dashboard
  lesson, carried). Built ONLY inside the `.consented` branch (consent-by-construction; unreachable before
  opt-in).
- **A11y identifiers:** `explore.screen`, `explore.disclaimer`, `tab.explore`.

### B. The series picker — toggle chips (EXPL-02)

- **Toggle chips** wrap in a flowing layout, each showing the catalog `displayName` (from
  `ExploreSeriesCatalog.all`, routed through `ExploreCopy` for any chrome). Tap toggles a series into/out
  of the view-local selection. Selected chip = accent fill + checkmark + semibold; unselected = secondary
  surface + `plus.circle`-style affordance + regular weight (color-independent).
- **Quantitative cap = 3–4 simultaneously.** When the quantitative cap is reached, further unselected
  quantitative chips are **disabled** with a clear **"remove one to add a new one"** helper line
  (`ExploreCopy.capReached…`); event-marker series are a SEPARATE small allowance (not counted against the
  quantitative cap). The remove-to-add affordance is a tap on a selected chip's `xmark` (low-stakes,
  reversible — never destructive red).
- **Suppression filter (LOCKED):** when the user's data is suppressed, the picker MUST NOT offer
  `bleeding.intensity` or `bleeding.event` chips at all (no empty lane, no offered-but-empty chip). Filter
  the catalog on the same `!snap.suppressed` invariant the Phase-14 accessors enforce.
- **Selection state is view-local `@State`, EPHEMERAL** — modeled as a pure value type (cap rules
  unit-testable). Deliberately NOT `@AppStorage`/persisted: persisting series keys would leak
  health-interest metadata outside the consent-gated store (LOCKED privacy call).
- **A11y identifiers:** `explore.picker`, `explore.chip.<series.id>` (stable, value-independent — the
  series id), `explore.chip.<series.id>.remove`, `explore.picker.capHint`.

### C. The range-preset control (EXPL-06)

- The **same preset vocabulary as the dashboard**: the `TrendWindow` family (last 7 / last 30 / last 90 /
  all time), rendered as a segmented `Picker` (or a small row of preset chips), labels via
  `ExploreCopy.windowLabel(_:)` mirroring `InsightsCopy.windowLabel`. Switching the range re-anchors the
  shared X domain across all lanes (absolute dates, gap breaks preserved).
- **A11y identifiers:** `explore.range`, `explore.range.<window.rawValue>`.

### D. The lanes block (EXPL-03 / EXPL-04 / EXPL-05) — see Swift Charts Specification

- Quantitative lanes (one per selected quantitative series, each its own `Chart` at `lane-quant-height`),
  then event-marker lanes (one per selected presence series, at `lane-event-height`), all sharing the X
  domain + the single scrub `RuleMark` + the shared multi-series tooltip.
- **A11y identifiers:** `explore.lanes`, `explore.lane.<series.id>` (quantitative),
  `explore.lane.<series.id>.event` (event-marker), `explore.scrub.tooltip`,
  `explore.scrub.tooltip.<series.id>` (per-series value line — value-independent id; the `.notLogged`
  suffix when that series is a gap on the scrubbed day, mirroring the Phase-13
  `.tooltip` / `.tooltip.notLogged` shielding).

### E. The two honest states (EXPL-07)

| State | When | What the user sees |
|-------|------|--------------------|
| **Empty — "pick a series"** | Nothing selected (the default on first open) | A single, warm full-screen state in place of the lanes: icon (`square.stack.3d.up`, `.secondary`), heading + body copy (see Copywriting) inviting the user to pick a series from the chips. No fake/placeholder lanes, no empty axes. |
| **Sparse — "not enough data"** | One or more series selected, but the selected series have too few logged days in the window to plot meaningfully | An honest **"not enough data"** state (or per-lane sparse note) — explicitly an honest signal, NOT a blank lane read as "0". Unlogged days stay gaps; the state never fabricates a value. `.secondary`, no scrub. |

- Unlogged days stay **gaps** in every rendered lane regardless of state (constraint 1).
- **A11y identifiers:** `explore.empty` (pick-a-series), `explore.sparse` (not-enough-data).

## Copywriting Contract

ALL new chrome copy is a NEW **`ExploreCopy`** enum with an `auditableStrings` array, **registered in
`CopyAuditTests` BEFORE any string is written** (constraint 5 / RESEARCH Pitfall 3 — an unregistered enum
silently escapes the `ClaimsPolicy.forbiddenVerbs` / `forbiddenGenderedTokens` / numeric-confidence
scans). Mirror the `InsightsCopy` posture. The not-medical-advice framing is reused verbatim via
`Disclaimer.text` / `DisclaimerBanner` (NOT duplicated). Series value readouts route through
`SeriesNormalization.readout(...)` (real unit, never the normalized number).

**SUBSTRING TRAPS — every string below is pre-verified against the ClaimsPolicy substring scans:**
"her" is hosted by *together / whether / other / higher / there / here / she*; "treat" by *treatment*;
forbidden verbs include *will / causes / cause (⊂ because) / triggers / predicts / treats*. The copy below
is curated to host NONE of these.

| Element | Copy (pre-verified) |
|---------|------|
| Tab label | **"Explore"** |
| Nav title | **"Explore"** |
| Persistent disclaimer | reused `Disclaimer.text` via `DisclaimerBanner` (always visible) |
| Empty-state heading ("pick a series") | **"Pick a series to begin."** |
| Empty-state body | **"Choose one or more of your logged series from the chips above to plot them on a shared timeline. Each series keeps its own real scale."** *(no "her"/"treat"/"will"/"cause" host words)* |
| Sparse-state heading ("not enough data") | **"Not enough data yet."** *(matches the dashboard sparse wording, audit-clean)* |
| Sparse-state body | **"Keep logging and these lanes fill in over time. Unlogged days stay as gaps — a gap is honest, not a zero."** |
| Cap-reached helper | **"Up to four series at once. Tap a selected chip to remove one, then add a new one."** *(states the remove-to-add affordance; substring-verified clean — note "another" ⊃ "her" was REJECTED and replaced with "a new one")* |
| Remove-chip action (a11y label) | **"Remove series"** |
| Add-chip affordance (a11y hint) | **"Add to the timeline."** |
| Range-preset labels | **"last 7 days" / "last 30 days" / "last 90 days" / "all time"** (maps `TrendWindow`, reusing the dashboard vocabulary) |
| Scrub tooltip — date header | the absolute date, formatted `.month().day()` (e.g. **"Jun 3"**) — system-formatted, not a literal |
| Scrub tooltip — per-series value line | **"{series displayName}: {readout}"** via `SeriesNormalization.readout` (e.g. "Sleep: 6.5 h", "Stress: 7 of 10") — a factual readout; digits in a value are legal (the bare-digit scan is scoped to confidence words, which Explore has none of) |
| Scrub tooltip — per-series gap line | **"{series displayName}: Not logged"** (reuse the LOCKED `InsightsCopy.scrubNotLogged = "Not logged"` posture; gap-honest, never "0", never "No data", never an error tone) |
| Lane text summary | **"{series displayName}, {window label}."** (plain, descriptive — no direction/causal word; Explore is descriptive-only) |

**Copy posture rules (enforced — `ClaimsPolicy` + `CopyAuditTests`):**
- **Descriptive only.** NO causal/diagnostic verbs (trigger / causes / treats / predicts / will), NO
  associations/confidence wording, NO r-value/%/p-value — Explore shows RAW data and bypasses the gate;
  the gate's claim-framing is NOT reintroduced here.
- **No gendered tokens** ("her" / "she" / "women" …) including the "higher"/"lower"/"other"/"together"
  traps; resolve any bleeding/cycle noun through `Terminology`.
- **A gap is honest** — "Not logged", never a fabricated value, never "0 = none".
- **Removing a series is a preference, not destruction** — no red, no scary confirmation.
- **Register first:** `ExploreCopy.auditableStrings` is added to `CopyAuditTests` in the SAME change that
  introduces the enum, BEFORE any view renders a string (RESEARCH Pitfall 3).

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| not applicable (native iOS app) | none — SwiftUI system controls + **Swift Charts** (Apple system framework) + project-owned views only | not applicable — no shadcn/third-party UI or chart registry in an iOS/SwiftUI project |

## Accessibility Contract (first-class — endo audience)

| Dimension | Requirement |
|-----------|-------------|
| Touch targets | Every interactive element ≥ **44pt × 44pt** (HIG): each toggle chip, each chip's remove affordance, each range preset, the Explore tab. Event-marker lanes are `lane-event-height = 44`. |
| Color independence | **Chip selected/unselected** = fill + checkmark/`xmark` symbol + weight (never hue). **Data series** = colorblind-safe `chartForegroundStyleScale` hue + labelled legend (`displayName`) + per-lane real-unit axis label (+ symbol/dash if two ever share a scale) — never color alone. **Scrub chrome** = `.secondary` gray, distinct from data. |
| Charts | Per-mark `accessibilityLabel`/`accessibilityValue` (date + real-unit value) for VoiceOver + Audio Graph; ONE `AXChartDescriptor` per quantitative lane (logged points only, gaps omitted, never zeros); a per-lane one-line **text summary** (full text fallback); Reduce Motion disables animation; Dynamic Type scales axis labels (reduce tick density, never clip). |
| Multi-series scrub without gesture | The scrubbed-day per-series values are reachable WITHOUT the drag gesture — the readout + a11y ids ride a transparent overlay proxy (Swift Charts does NOT expose `.annotation` content to the AX tree — the Phase-13 discovery); the visual annotation is `.accessibilityHidden(true)`; shield proxy ids with `.accessibilityElement(children: .contain)` so a parent id can't mask them. |
| Honest absence (a11y) | Chart **gaps** are exposed as missing data (no mark, never "0"); a gap on the scrubbed day reads **"Not logged"** to VoiceOver; the **sparse** state reads "Not enough data yet"; a **suppressed** user is never offered a bleeding chip (provable by the chip's absence). |
| Dynamic Type | All text uses named text styles; lanes + chips + tooltip reflow (no clipping) to the largest accessibility sizes; multi-line state copy uses `.fixedSize(…, vertical: true)`. |
| Descriptive-only (a11y) | VoiceOver never announces a confidence/association/percentage in Explore — Explore carries no such chrome; it reads plain real-unit values and "Not logged". |
