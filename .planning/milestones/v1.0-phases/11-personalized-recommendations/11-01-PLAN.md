Add two types and one static func:
- `enum RecommendationDirection { case beneficial, aggravating }` — package-internal, `Equatable`. Encode the direction SEMANTICS from RESEARCH Pattern 2 "Direction semantics": for the SEVERITY arm, `beneficial` when `meanDiff < 0` (the factor's present-group has LOWER symptom severity), `aggravating` when `meanDiff > 0` (higher). Derive direction INSIDE the engine from the private `Arm` (which already carries `meanDiff` for severity and `riskRatio` for presence) — add a computed `direction` helper on `Candidate`/`Arm`.
- `struct CorrelationFinding` — package-internal, `Equatable`: `let signalKey: String`, `let factorLabel: String`, `let targetLabel: String`, `let confidence: InsightConfidence`, `let pairedDays: Int`, `let effectMagnitude: Double`, `let direction: RecommendationDirection`. This is the typed survivor the recommendation engine consumes.
- `static func scoredCandidates(from rawSnapshots:[DaySnapshot], asOf today:Date, calendar:Calendar = .current) -> [CorrelationFinding]` — returns EXACTLY the same survivors `insights(...)` emits, in the SAME deterministic order, as typed findings. Keep `insights(...)`'s public behavior byte-identical (the existing CorrelationEngineTests must stay green).

Do NOT change `Insight` (Option B is rejected — RESEARCH A1 / Alternatives Considered). Do NOT add a public symbol — `scoredCandidates`/`CorrelationFinding`/`RecommendationDirection` are package-internal so only `RecommendationsEngine` (same module) reaches them; the package boundary (BoundaryLintTests) stays Foundation-only.
