# Phase 11 — UI Design Contract

> Visual and interaction contract for Phase 11 (Personalized Recommendations).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM:** Native **iOS app in SwiftUI** — NOT web/CSS/React. The web-oriented template fields
> (px spacing, hex colors, shadcn/Tailwind, line-height ratios, registry) are `not applicable (native iOS)`
> or expressed in their SwiftUI equivalents. shadcn / registry-vetting gates do **not** apply.
>
> **THIS IS A REUSE PHASE — NOT A NEW DESIGN SYSTEM.** Phase 11 adds a single new **"Recommendations"
> section** to the EXISTING, already-checker-verified `InsightsView` dashboard, rendering a new
> `.recommendation` `InsightKind` through the EXISTING, kind-agnostic `InsightCardView`. **It introduces
> NO new tokens, NO new components, NO new visual language.** Every spacing/typography/color/accessibility
> decision is **inherited verbatim** from the LOCKED Phase 8 contract
> (`08-UI-SPEC.md`, status: approved). This document declares ONLY the deltas:
>   1. the new section (header copy + placement + omit-when-empty),
>   2. the recommendation card's **discussion-prompt** copy + direction-aware framing,
>   3. the new **forbidden-imperative** copy scan that gates that copy,
>   4. the a11y identifiers for the new section/cards.
>
> **FOUR HONESTY CONSTRAINTS (inherited from Phase 8 — restated because they shape every recommendation):**
> 1. **Confidence is plain-language ONLY** — "Low / Medium / High — possible association" + an SF-Symbol
>    shape. NEVER a number/percentage/coefficient (D-05, inherits D-11). No false precision.
> 2. **Copy is NON-PRESCRIPTIVE** — a recommendation is a **discussion prompt**, never a medical
>    instruction. No imperative/directive verbs ("take", "stop", "avoid", "start", "should", "must",
>    "use", "try", "cut") — enforced by a NEW forbidden-imperative scan layered on the existing
>    forbidden-verb / gendered-token / numeric-confidence scans (D-04). The scan is the choke-point and
>    **wins over any template wording**.
> 3. **Color is NEVER the sole signal** — confidence carries text word + SF-Symbol shape (inherited
>    `InsightCardView` confidence pill); dismiss is gray/secondary, never red.
> 4. **Honest absence by non-existence** — a zero-recommendation section does **NOT** render (no empty
>    shell, no placeholder). A suppressed/sparse user with no qualifying associations sees **NO**
>    Recommendations section at all — never a fabricated "do this" (D-06 / D-08 / SC3).

## Component & Interaction Inventory (the Phase-11 deltas only)

### A. The new "Recommendations" section (D-06)

- **Placement:** a new `Section` in `InsightsView`, added **AFTER** the "Possible associations"
  (`.correlation`) section — recommendations are derived FROM associations, so they read after them
  (D-06). Final section order, top → bottom:
  **Trends → Cycle phase → Possible associations → Recommendations.**
- **Built with the existing helper:** call the SAME `section(title:identifier:kind:)` builder used by the
  other three kinds, with `title: RecommendationsCopy.sectionRecommendations`,
  `identifier: "insights.section.recommendations"`, `kind: .recommendation`. The helper already filters
  `coordinator.insights` by kind and **omits the section entirely when it has zero insights** — so the
  honest-absence behavior is inherited with no new code path.
- **Omit-when-empty (D-06 / D-08 / SC3):** a zero-recommendation section does NOT render — no empty shell,
  no "no recommendations yet" placeholder. A suppressed/sparse user with no qualifying associations has
  **no `insights.section.recommendations` element at all** (provable by ABSENCE, mirroring the
  cycle-phase-suppressed test). This is the make-or-break honesty rule: never fabricate a recommendation.
- **Rows:** each row is the EXISTING `InsightCardView`, unchanged, rendering a `.recommendation` `Insight`.
  Its `supportingData` switch already routes `.recommendation` to the words-only evidence line
  ("Seen across {n} logged days." + window label) — NEVER a coefficient/percentage. No chart.
- **Disclaimer / recompute / instant-load:** all inherited from §A of the Phase-8 contract (the pinned
  `DisclaimerBanner`, the non-blocking "Updating…" caption, `loadCached()` then `dataChanged()` on appear).
  No new triggers.
- **A11y identifier:** `insights.section.recommendations` (and, provable by absence for an unsupported user,
  the non-existence of that element).

### B. The recommendation card (reused `InsightCardView`, kind `.recommendation`)

Structure is the **inherited** fixed top→bottom layout (no change to the view):

1. **Headline** — the engine's `insight.headline`, verbatim: the **discussion-prompt** line
   (e.g. *"You tend to feel better on days with gentle movement."* / *"Your pelvic pain tends to be higher
   on days with poor sleep — something you might explore."*). Direction-aware (D-03), NEVER imperative.
2. **Confidence pill** — inherited: text word ("Low / Medium / High — possible association") + per-level
   SF-Symbol shape. Plain-language only, no number (D-05).
3. **Detail** — the engine's `insight.detail`, verbatim: the non-prescriptive elaboration
   (e.g. *"This is a pattern in your own data, not advice — something to discuss with your clinician."*).
4. **Supporting data** — words-only evidence: "Seen across {n} logged days." + the window label. No chart,
   no coefficient (inherited `.recommendation` branch of `supportingData`).
5. **Basis note** — "Based on your logs." (inherited `InsightsCopy.basisNote`).

- **Dismiss (D-07):** inherited verbatim — the non-destructive gray "This isn't right" affordance via
  `.swipeActions` + `.contextMenu` + the VoiceOver custom action, wired through the screen's existing
  `coordinator.dismiss(signalKey:)` → `DismissedInsight` → recompute-excludes. No new dismiss path.
- **A11y identifiers (inherited shape, new keys):** `insights.card.<signalKey>` (the recommendation's
  stable, value-independent `signalKey` — Claude's discretion per CONTEXT, must be window-independent like
  the trend/correlation signals), `.confidence`, `.evidence`, `.dismiss`.
- **VoiceOver:** inherited — the card is one contained element reading
  "headline, {confidence}, detail"; dismiss is a custom action.

## Copywriting Contract (the substantive Phase-11 surface)

All recommendation copy lives in a NEW auditable **`RecommendationsCopy`** surface (mirroring the existing
`InsightsCopy` / `CycleSummaryCopy` posture: an `enum` of fixed strings + an `auditableStrings` array). It
is scanned by `CopyAuditTests` against `ClaimsPolicy.forbiddenVerbs` / `forbiddenGenderedTokens` / the
numeric-confidence scan **AND the NEW forbidden-imperative scan** (D-04). The engine's recommendation
`headline`/`detail` are **also** routed through `RecommendationsCopy` templates (NOT free text) so they pass
the same scan before they are ever emitted — the audit is the honesty choke-point and wins over any wording.

**Discussion-prompt framing (D-03 / D-04) — the core copy rule:** a recommendation is phrased as something
the user *might explore* or *discuss*, never as an instruction. Direction-aware:

| Direction | Framing (template intent — exact wording is planner/executor's, subject to the scan) |
|-----------|--------------------------------------------------------------------------------------|
| **Beneficial** association | *"You tend to feel better on days with {factor}."* → discussion-prompt, e.g. *"…— something you might explore."* |
| **Aggravating** association | *"Your {symptom} tends to be higher on days with {factor} — something you might explore."* (descriptive "tends to be higher", NEVER "{factor} causes {symptom}", NEVER "avoid {factor}") |

| Element | Copy |
|---------|------|
| Section header — Recommendations | **"Recommendations"** (the new section, after "Possible associations") |
| Recommendation headline (beneficial) | A direction-aware **discussion prompt**, e.g. **"You tend to feel better on days with {factor}."** — non-causal, non-imperative |
| Recommendation headline (aggravating) | e.g. **"Your {symptom} tends to be higher on days with {factor} — something you might explore."** (avoid "higher/lower" → the "her" trap; resolve via the existing direction wording / `Terminology` as needed) |
| Recommendation detail | A non-prescriptive basis + invitation, e.g. **"This is a pattern in your own data, not advice — something to discuss with your clinician."** |
| Confidence indicator | Inherited verbatim: **"Low / Medium / High — possible association"** + the per-level symbol (D-05; never "certain"/"proven"/a percentage) |
| Supporting evidence line | Inherited: **"Seen across {n} logged days."** (plain words from `sampleSize`; NEVER a coefficient/percentage/p-value) |
| Window label | Inherited: **"last 7 days" / "last 30 days" / "last 90 days" / "all time"** |
| Basis note | Inherited: **"Based on your logs."** |
| Dismiss action label | Inherited: **"This isn't right"** |
| Dismiss confirmation | Inherited: gentle, inline — the card animates out (no modal, no "are you sure?") |
| Empty / suppressed | **(none rendered)** — a zero-recommendation section is OMITTED entirely (D-06). There is deliberately NO empty-state copy for this section: absence is shown by non-existence, never by a placeholder sentence. |

**Copy posture rules (enforced — `ClaimsPolicy` + the NEW imperative scan + `CopyAuditTests`):**
- **NO imperative / directive verbs** (the NEW scan, D-04): forbid **"take", "stop", "avoid", "start",
  "should", "must", "use", "try", "cut"** (and their obvious inflections) in recommendation copy. A
  recommendation is a discussion prompt ("you might explore…", "something to discuss with your
  clinician…"), never an instruction ("take X", "stop Y", "avoid Z").
- **NO causal / diagnostic verbs** (inherited — engine `ForbiddenTerms` + `ClaimsPolicy`): "trigger",
  "causes", "treats", "predicts", "will", "because", "due to", "leads to". A recommendation re-frames a
  *possible association*, never a cause.
- **NO numeric confidence** anywhere (inherited D-11/D-05): no "%", "p =", "r =", effect-size number;
  confidence is one of three words only.
- **NO gendered tokens** (inherited): "her"/"she"/"women" — including the "higher"/"lower" substring trap.
- **NO fabricated recommendation** (D-08 / SC3): a recommendation appears ONLY when it composes a real,
  already-gated correlation/strong-trend that passed the `HonestyGate` (`minSample(.correlation)==10` +
  the confidence floor). A suppressed/sparse user gets none — never a "do this" invented to fill space.
- **Dismiss is a preference, not destruction** (inherited): no red, no scary confirmation, no "delete".
