Cross-device sync, offline reconcile, reinstall restore, and auto-mirror of existing local data all ride on NSPersistentCloudKitContainer framework defaults with last-writer-wins and zero custom code (D-05/D-14) — so this plan writes the gate, not a sync engine. The 4 real multi-device DATA criteria are device-only and ship in the HUMAN-UAT plan (04-03).
Output: `EndoApp.entitlements`, the `AccountAvailability` seam, account-aware `SyncMode`/`makeModelContainer`, composition-root wiring, the `\.accountAvailability` Environment key, and `SyncModeTests` — full suite GREEN local-only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → user's private iCloud (CloudKit) | GDPR Art. 9 health data now leaves the device to the user's PRIVATE iCloud DB. Acceptable (no third party, Apple-managed encryption), but the entitlement/container MUST be private-DB-only. |
| build config → runtime activation | The entitlement is inert without a Team ID; the runtime gate (`SyncMode.resolve`) decides local-vs-cloud. A misordered gate (P-2) could mis-activate CloudKit on the intended-local path. |
| account state → store | iCloud sign-out wipes the local store (iOS 18, P-1). Unsynced edits can be lost — accepted for v1, documented, not code-mitigated this phase. |
