# Phase 8 — UI Design Contract

> Visual and interaction contract for Phase 8 (Insights Integration — Coordinator, Cached Insights & the Insights Dashboard).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **PLATFORM:** Native **iOS app in SwiftUI + Swift Charts** — NOT web/CSS/React. The design system is
> Apple-native: SF Symbols, semantic system colors, Dynamic Type text styles, native SwiftUI controls, and
> **Swift Charts** (`Chart`/`LineMark`/`BarMark`/`PointMark` on an absolute-date X-axis). The web-oriented
> template fields (px spacing, hex colors, shadcn/Tailwind, line-height ratios, registry) are adapted to
> their SwiftUI equivalents below; web-only fields are marked `not applicable (native iOS)`.
>
> **AUDIENCE:** Endometriosis patients. Accessibility is a first-class requirement, not an afterthought:
> ≥44pt touch targets, no information conveyed by color alone, full VoiceOver + Dynamic Type, and a
> text/audio-graph fallback for every chart.
>
> **THIS IS THE PAYOFF SCREEN.** The dashboard is what makes the daily logging effort worth it. It must
> render the user's REAL data **honestly** — and the engine has already done the honesty work
> (`InsightsEngine` → `HonestyGate`). The dashboard renders the gate's output **verbatim** and must NOT
> re-introduce causal language, invent confidence precision, surface withheld insights, or draw a phantom
> cycle phase.
>
> **FOUR HONESTY CONSTRAINTS THAT SHAPE EVERY PIXEL (cross-cut the whole screen):**
> 1. **Confidence is plain-language ONLY** — "low / medium / high possible association". NEVER a numeric
>    percentage, p-value, correlation coefficient, or effect-size number (D-11). No false precision.
> 2. **Charts use an ABSOLUTE calendar-date X-axis** — never a cycle-relative axis (SC3 / D-06).
> 3. **Color is NEVER the sole signal** — every confidence level, severity, and series also carries a
>    text label and/or SF Symbol and/or shape.
> 4. **Suppressed → the Cycle-phase section does NOT render at all** — no phantom phase, no empty
>    placeholder implying a hidden cycle (D-07). The engine emits zero `.cyclePhase` insights for
>    suppressed/irregular users; the UI simply has no section to show.

## Spacing Scale

Native iOS does NOT use a web px scale. Spacing is in **points (pt)** and, wherever possible, delegated to
**system defaults** (`List`/`Form` inset grouping, default `Section` spacing). Declared values mirror the
multiples-of-4 scale Phases 2–3 already use. Charts get explicit, named insets so axis labels never clip at
large Dynamic Type sizes.

| Token | Value (pt) | Usage |
|-------|-----------|-------|
| xs | 4 | Tight inline gaps (headline↔confidence row, point-label spacing) |
| sm | 8 | Default label/control spacing inside a card (`VStack(spacing: 8)`) |
| md | 16 | Default element spacing within a section / card content inset |
| lg | 24 | Inter-card / inter-section gaps where the system default is insufficient |
| chart-height | 200 | Default `Chart` frame height (`.frame(height: 200)`); reflows taller if axis labels need it at large Dynamic Type |
| chart-vertical-inset | 8 | `.chartYAxis`/plot vertical padding so the top/bottom marks and labels are not clipped |

**System-default first:** Do NOT hand-roll section/page padding. Use a grouped `List`/`Form { Section { … } }`
(as `HomeView` and `SettingsView` do) and let the inset-grouped list supply standard margins. Cards are
`Section`s (or grouped rows), NOT hand-built rounded rectangles with custom padding.

**Touch targets:** Every interactive element (each insight card's dismiss affordance, the Home "Insights"
entry point, any "Tell me more" disclosure) MUST have a **≥44pt × 44pt** hit area (HIG). Swipe actions and
context menus inherit the full row's ≥44pt height automatically.

Exceptions: none beyond the system-default and 44pt-minimum rules above.

## Typography

Native iOS uses **semantic Dynamic Type text styles**, NOT fixed px sizes or line-height ratios. Declaring
fixed sizes would BREAK Dynamic Type (an accessibility requirement for this audience). The contract is text
styles + weights; the system supplies size and line height per the user's Dynamic Type setting. These mirror
the styles already used in Phases 2–3 (`.headline`, `.subheadline`, `.footnote`, `.caption`).

| Role | SwiftUI text style | Weight | Used for |
|------|--------------------|--------|----------|
| Screen / section title | `.title2` (nav title) / `.headline` (`Section` header) | semibold (system default for the style) | "Insights" navigation title; "Trends" / "Cycle phase" / "Correlations" section headers |
| Insight headline | `.headline` | semibold (style default) | The non-causal headline line of each insight card (the most prominent text in a card) |
| Body / detail | `.body` | regular | The plain-language effect/detail sentence under the headline; empty/sparse-state body copy |
| Confidence + meta | `.subheadline` (confidence pill label) / `.caption` (window label, basis note) | regular | The plain-language confidence indicator; the window label ("last 30 days"); "Based on your logs."; supporting-point captions |
| Disclaimer | `.footnote` | regular | The persistent not-medical-advice banner (matches `DisclaimerBanner`) |
| Chart axis / value labels | `.caption` / `.caption2` (Swift Charts default annotation styles) | regular | Absolute-date axis tick labels, value annotations — must remain non-clipping at large Dynamic Type |

Rules:
- **Exactly these roles** — do not introduce ad-hoc font sizes. The confidence indicator is **text**, never a
  bare number.
- **Never** `.font(.system(size: <fixed>))` for content text; always a named style so Dynamic Type scales it.
- Multi-line headlines/details use `.fixedSize(horizontal: false, vertical: true)` so a long non-causal
  sentence never truncates and hide its honest framing.
- Chart axis labels use Swift Charts' built-in `.caption`-class styling and MUST stay legible/non-overlapping
  at the largest accessibility Dynamic Type size (thin axis tick density when space is tight).

## Color

Native iOS uses **semantic system colors** that auto-adapt to Light/Dark Mode and accessibility-contrast
settings — NOT app-defined hex values. Hardcoding hex would break Dark Mode and contrast adaptation. The
60/30/10 split is expressed in semantic terms; the app already follows this in Phases 2–3.

| Role | Semantic value | Usage |
|------|----------------|-------|
| Dominant (60%) | `Color(.systemGroupedBackground)` / system `List`/`Form` background; text in `.primary` | The grouped-list canvas behind the whole dashboard and the chart plot background |
| Secondary (30%) | `Color(.secondarySystemGroupedBackground)` (grouped card surface); text in `.secondary` | Each insight card's surface; confidence/window/basis meta text; empty/sparse placeholder copy; the disclaimer banner background (`.quaternary`, as `DisclaimerBanner` already uses) |
| Accent (10%) | `Color.accentColor` (the app tint) | See reserved-for list below |
| Destructive | not used as a hue here — the **dismiss** action is `.gray`/secondary, NOT red | Dismiss is "this isn't right / not relevant", a low-stakes preference, NOT a dangerous/destructive action — so it must NOT borrow the red destructive color (avoids alarming the user about their own health data). See Copywriting note. |

**Accent (`Color.accentColor`) is reserved EXCLUSIVELY for:**
- The primary **chart series mark** (the `LineMark`/`BarMark` data line/bars) — the data IS the focus.
- The **Home entry point** to Insights (the tab item's selected tint / the CTA label+icon).
- System controls that already self-tint (e.g. a disclosure chevron) — system behavior, left as-is.

Accent is NEVER used for: the confidence indicator background as the *only* differentiator (each confidence
level carries text + symbol, see below), every card indiscriminately, body text, or section backgrounds.

**Color-independence (MANDATORY — accessibility):**
- **Confidence is NEVER color alone.** Each insight's plain-language confidence renders as a **labelled pill**:
  a text word ("Low / Medium / High possible association") **plus** a distinct SF Symbol per level
  (e.g. `circle` / `circle.lefthalf.filled` / `circle.fill`, or a 1/2/3-dot indicator). A grayscale or
  Smart-Invert user must be able to tell the three levels apart by **text + shape**, not hue.
- **Chart series are distinguishable without color.** A single-series chart relies on its axis labels and
  value annotations; if a future card shows two series, they MUST differ by **symbol/dash style + a labelled
  legend**, never color alone. Severity values on a line chart carry **value annotations** (the `n/10` style,
  mirroring `SeverityControl`), not just vertical position-by-color.
- **Direction** (a trend going up/down/steady) is shown with a **text word + an SF Symbol** (`arrow.up.right`
  / `arrow.down.right` / `arrow.right`), never a green/red arrow alone. Direction is descriptive
  ("higher recently" → avoid the word "higher": it contains the gendered substring "her" — use
  "more recently" / "trending up"), never evaluative (no "good"/"bad" coloring of a health value).

**Honest absence in charts (the honesty constraint, visual rule):**
- A **gap** in the data (days the user did not log) is rendered as an **actual gap / broken line**, NEVER
  interpolated as a straight line through zero and NEVER drawn as `0`. Absence ≠ zero — a missing day is
  missing, not "a day with no symptoms". Use Swift Charts' missing-data handling (omit the mark for that
  date; do not back-fill `value: 0`).
- A logged value of literally `0` (e.g. severity 0) IS drawn as a point at 0 — distinct from a gap. The chart
  must read these two differently (a plotted point at the zero line vs. no point at all).

## Swift Charts Specification

This section is the executor's chart source of truth (the web template has no chart field). It encodes D-06
(absolute-date axis) and the absence-≠-zero rule.

### Chart types per insight kind

| Insight kind | Visual | Marks | Notes |
|--------------|--------|-------|-------|
| `.trend` — symptom **severity** over time | Line chart | `LineMark(x: .value("Date", point.date), y: .value("Severity", point.value))` + optional `PointMark` for the actual logged days | One line per insight (one symptom). Y domain `0...10` (matches `SeverityControl`). Logged days = points; unlogged days = **gap** (no mark), never interpolated to 0. |
| `.trend` — **frequency** (e.g. bleeding-day / poor-sleep frequency per window) | Bar chart | `BarMark(x: .value("Date", point.date, unit: …), y: .value("Count", point.value))` | Bars on absolute-date buckets. A bucket with no logged days shows **no bar** (absent), not a zero-height bar implying "logged none". |
| `.cyclePhase` — symptom↔phase association | **Text + confidence card** (no chart required; optional tiny phase-band viz) | — (text-first) | Rendered as a card with the engine's headline + confidence. If a viz is added it MUST still be on an **absolute-date** axis with phase bands as `RectangleMark`/`RuleMark` overlays — NEVER a cycle-relative axis. Omitted entirely for suppressed/irregular (engine emits none). |
| `.correlation` — factor↔symptom association | **Text + confidence card** (no chart) | — (text-first) | A correlation is a relationship, not a time series — render the engine's plain-language headline + detail + confidence + supporting-`sampleSize` (as words, e.g. "seen across 12 logged days"), NEVER a coefficient/p-value or a misleading scatter that implies causation. |
| `.recommendation` (Phase 11) / `.flare` (Phase 12) | reserved | — | The dashboard MUST accommodate these as additional cards routed through the SAME `InsightsEngine`/`HonestyGate` (D, out-of-scope now). Card layout below is kind-agnostic. |

### Axis contract (absolute date — SC3, NON-NEGOTIABLE)

- **X-axis = absolute calendar dates** anchored on the insight's `window` (last7 / last30 / last90 / allTime),
  ending at the engine's injected `today`. `.chartXAxis` shows real dates (`.month().day()` style), DST-safe.
- **NEVER a cycle-relative / cycle-day axis.** Cycle phase, when shown, is an *overlay band* on the absolute
  date axis, not the axis itself.
- X domain is the window's date range even when data is sparse (so a 3-points-in-30-days chart reads as
  "sparse over a month", not "3 consecutive days").
- Y domain is fixed per kind (severity `0...10`; frequency `0...maxCount`) so windows are visually comparable.

### Chart accessibility (REQUIRED on every `Chart`)

- Every mark carries `.accessibilityLabel`/`.accessibilityValue` (date + value, e.g. "June 3, severity 6 of
  10") so VoiceOver and the **Audio Graph** rotor can read the series.
- The whole chart has a one-line text **summary above or below it** (e.g. "Pelvic pain severity, last 30
  days — trending up.") so the information is available without seeing the chart at all (the text/list
  fallback the a11y contract requires).
- Charts respect Dynamic Type (axis labels scale; reduce tick density rather than clip) and Reduce Motion
  (no animated chart transitions when Reduce Motion is on; render the final state directly).
- The chart is NEVER the only carrier of an insight's meaning — the card's headline + confidence already
  state it in words.

## Component & Interaction Inventory (native, phase-specific)

### A. The Insights screen (D-05)

- **Container:** a grouped `List`/`ScrollView` inside a `NavigationStack`, navigation title **"Insights"**.
- **Persistent disclaimer:** the reused **`DisclaimerBanner`** (renders `Disclaimer.text`) pinned so it is
  always visible with the insights — at the top of the list (or a non-scrolling header). It is `.footnote`,
  `.secondary`, with the `info.circle` symbol, exactly as Phase 1 ships it (D-12).
- **Sections, in order:** **Trends** → **Cycle phase** → **Correlations**, each a `Section` whose rows are
  insight cards. A section that has **zero** gated insights does NOT render an empty shell — it is omitted
  (and Cycle phase is omitted entirely for suppressed/irregular users — D-07).
- **Instant-load + recompute:** cached insights render immediately on open (D-04); a fresh recompute lands
  via the `@Observable InsightsCoordinator` and the list updates in place. A subtle, **non-blocking** "Updating…"
  affordance (a small `.secondary` caption or a `ProgressView` in the section header) is allowed during a
  recompute — NEVER a full-screen blocking spinner (cached content stays visible, SC2 / no jank).
- **A11y identifiers:** `insights.screen`, `insights.disclaimer`, `insights.section.trends`,
  `insights.section.cyclePhase`, `insights.section.correlations`, `insights.updating`.

### B. The insight card (D-08) — kind-agnostic

Each card is a grouped row / `Section` cell with this fixed vertical structure (top → bottom):

1. **Headline** — the engine's `insight.headline`, `.headline`, `.primary`, non-causal (verbatim from the gate).
2. **Confidence indicator** — a labelled pill: SF Symbol (per-level shape) + text word
   ("Low/Medium/High possible association"). `.subheadline`. **Plain-language only — no number** (D-11).
3. **Detail / effect** — the engine's `insight.detail`, `.body`, `.primary` (the plain-language effect sentence).
4. **Supporting data** — for `.trend`: the Swift **Chart** (per the chart spec). For `.cyclePhase`/`.correlation`:
   a `.caption` evidence line phrased in words from `insight.sampleSize` (e.g. "Seen across 12 logged days"),
   and the `insight.window` as a `.caption` label ("last 30 days") — **never** a coefficient/percentage.
5. **Basis note** — `.caption`, `.secondary`: "Based on your logs." (reuses the `CycleSummaryCopy.basisNote`
   posture).

- **Dismiss affordance** (D-09): a per-card **"This isn't right"** action available via BOTH a trailing
  **`.swipeActions`** button AND a **`.contextMenu`** (long-press) — so it is discoverable and reachable with
  one hand. The icon is `hand.thumbsdown` or `xmark.circle`; the role is **NOT** `.destructive` (it is a
  preference, not data deletion — see Color note). On tap → `Repository.dismissInsight(signalKey:)` → the card
  animates out and **stays dismissed** across sessions/devices (Phase-6 `DismissedInsight`, syncs via Phase 4),
  and the coordinator re-feeds `dismissedSignalKeys()` into the engine so a recompute excludes it (D-10).
- **A11y identifiers:** `insights.card.<signalKey>` (stable, value-independent — the dismissal key),
  `insights.card.<signalKey>.confidence`, `insights.card.<signalKey>.chart`,
  `insights.card.<signalKey>.dismiss`.
- **VoiceOver:** the card is an `.accessibilityElement(children: .contain)` group reading
  "headline, {confidence} possible association, {detail}"; the dismiss action is exposed as a VoiceOver
  **custom action** ("This isn't right") so it is reachable without the swipe gesture.

### C. The three honest states (D-07) — reuse the `CycleSummaryView` model

| State | When | What the user sees |
|-------|------|--------------------|
| **Empty** (no insights at all yet) | The engine returns zero gated insights AND the user has essentially no data | A single, warm full-screen empty state (NOT empty sections): icon (`chart.line.uptrend.xyaxis`, `.secondary`), heading + body copy (see Copywriting), and the persistent disclaimer. No fake/placeholder cards. |
| **Sparse** (some data, a given signal under-sampled) | The engine emits the typed **insufficiency notice** for a signal (`isInsufficiencyNotice == true`) | An honest **"not enough data yet"** card in the relevant section — explicitly an honest signal, NOT a hidden/blank row. `.secondary`, no chart, no confidence pill. |
| **Suppressed** (continuous-treatment / no-cycle user) | The engine emits zero `.cyclePhase` insights (D-07) | The **Cycle phase section does NOT render** — it is absent, not blank. NO phantom phase, NO "cycle hidden" placeholder. Trends + Correlations still render normally. |

- **A11y identifiers:** `insights.empty`, `insights.card.<signalKey>.insufficient` (the sparse notice),
  and — provable by its **absence** — no `insights.section.cyclePhase` element exists for a suppressed user
  (the E2E asserts non-existence, mirroring the `home.cycleSummary.suppressed` no-phantom test).

### D. Home entry point (D-17, Claude's discretion → decided here)

- **Decision: a bottom `TabView` tab** titled **"Insights"** (SF Symbol `chart.line.uptrend.xyaxis`), alongside
  a "Home"/"Log" tab — the dashboard is the product's payoff and deserves a persistent, top-level entry, not a
  buried link. (If the team prefers to keep the single-`NavigationStack` shell for v1, the fallback is a
  prominent **`NavigationLink` row / CTA** in `HomeView`, accent-tinted, labelled "Insights", `chart.*` symbol —
  same copy, same a11y id. Either is acceptable to the contract; the tab is recommended.)
- **A11y identifiers:** `tab.insights` (or `home.insightsButton` for the fallback CTA).

## Copywriting Contract

All copy routes through the **`ClaimsPolicy`** choke-point and reuses **`Disclaimer.text`** verbatim: non-causal,
non-diagnostic, plain-language confidence, no false precision. The **insight headlines/details themselves come
from the engine** (already gate-audited for forbidden terms — Phase 6 `ForbiddenTerms`); the UI only adds the
chrome copy below, which MUST also pass the `ClaimsPolicy.forbiddenVerbs` / `forbiddenGenderedTokens` scan
(centralize these strings in an `InsightsCopy` surface like `CycleSummaryCopy`, scanned by `CopyAuditTests`).

| Element | Copy |
|---------|------|
| Primary CTA / tab label | **"Insights"** (the top-level entry from Home) |
| Persistent disclaimer | The reused `Disclaimer.text`: *"Endo-App is an informational self-tracking tool. It is not medical advice and not a medical device…"* — rendered via `DisclaimerBanner`, always visible with the insights (D-12). |
| Confidence indicator — low | **"Low — possible association"** + the low-shape symbol |
| Confidence indicator — medium | **"Medium — possible association"** + the medium-shape symbol |
| Confidence indicator — high | **"High — possible association"** + the high-shape symbol (never "certain"/"proven"/a percentage) |
| Section header — Trends | **"Trends"** |
| Section header — Cycle phase | **"Cycle phase"** (omitted entirely when suppressed/irregular) |
| Section header — Correlations | **"Possible associations"** (avoid "Correlations" reading as a causal claim; "possible associations" matches `ClaimsPolicy.allowedFraming`) |
| Empty state heading | **"Keep logging — insights appear once there's enough data."** |
| Empty state body | **"As you log your symptoms and daily factors, the app looks for patterns in your own data and shows them here. There's nothing to see yet — keep going."** |
| Sparse state (per-signal) | **"Not enough data yet."** subtitle: **"Keep logging and this will fill in over time."** (reuses the `CycleSummaryCopy.notEnoughData` posture; NEVER a fabricated value) |
| Supporting evidence line | **"Seen across {n} logged days."** (plain words from `sampleSize` — NEVER a coefficient, percentage, or p-value) |
| Window label | **"last 7 days" / "last 30 days" / "last 90 days" / "all time"** (maps `TrendWindow`) |
| Basis note | **"Based on your logs."** (reused from `CycleSummaryCopy.basisNote`) |
| Direction word (trend) | **"trending up" / "trending down" / "steady"** (descriptive, never evaluative; avoid "higher/lower" — the "her" substring) |
| Dismiss action label | **"This isn't right"** (the dismiss affordance; matches the project's honesty posture — gives the user a voice over their own data) |
| Dismiss confirmation/feedback | Inline, gentle: the card animates out; an optional brief, `.secondary` line **"Thanks — we won't show that again."** No modal, no "are you sure?" (low-stakes, reversible by re-logging; NOT destructive). |
| Error — insights failed to load/compute | **"We couldn't update your insights just now. Your logs are safe — pull to refresh or try again in a moment."** (reassures the data is intact; offers a retry path) |
| Updating indicator (non-blocking) | **"Updating…"** (small, `.secondary`; cached insights stay on screen) |

**Copy posture rules (enforced — `ClaimsPolicy` + `CopyAuditTests`):**
- **No numeric confidence anywhere.** No "%", no "p =", no "r =", no effect-size number in user-facing copy.
  Confidence is one of three words only (D-11).
- **No causal/diagnostic verbs** ("trigger", "causes", "treats", "predicts", "will") — engine-enforced for
  headlines/details, UI-enforced for chrome copy.
- **No gendered tokens** ("her"/"she"/"women"…) — including the "higher"/"lower" trap; resolve any bleeding/cycle
  noun through `Terminology`.
- **"Not enough data yet" / a gap is honest**, never a fabricated value, never "0 = healthy".
- **Dismiss is a preference, not destruction** — no red, no scary confirmation, no "delete".
