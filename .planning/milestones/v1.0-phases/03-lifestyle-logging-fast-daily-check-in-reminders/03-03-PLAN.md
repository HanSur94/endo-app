<objective>
Vertical slice delivering CHCK-02 (configurable fatigue-aware reminders) plus the LIFE-03 medication-management surface: a UserDefaults-backed `ReminderSettings`, a Settings reminders section (master toggle OFF by default, just-in-time permission, add/remove times, quiet hours, denied-state handling) wired to the Plan 01 `NotificationScheduler`, a "Manage meds" section for saved-medication CRUD, and the `NotificationScheduler` injection into the composition root. After this plan a user can opt into gentle, quiet-hours-respecting reminders and maintain the saved-medication list that powers per-day "taken" toggles.

Implements D-06 (saved-med management UI), D-17 (NotificationScheduler wired via Environment), D-18 (opt-in, default off, single evening default suggestion), D-19 (quiet hours + the auto-suppress logic landed in Plan 01), D-20 (JIT permission + graceful denied state), D-21 (gentle non-coercive reminder copy).

Purpose: Reminders are the adherence lever; the fatigue controls (opt-in, quiet hours, auto-suppress, no-nag) are what make them non-harmful. The saved-meds list is the prerequisite for the check-in's per-day med toggles.
Output: `ReminderSettings.swift`, extended `SettingsView.swift` (reminders + manage-meds sections), and `AppDependencies.swift` with the scheduler injected.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → iOS UNUserNotificationCenter | Notification content + scheduled requests cross to the system; content visible on lock screen. |
| Settings UI → UserDefaults | Reminder config (device pref) written outside the synced store. |
| Settings UI → Repository | Med name/note free-text crosses into persistence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Information Disclosure | Notification body on the lock screen | mitigate | Generic, non-specific reminder copy ("here's your daily check-in") — NEVER a factor value or med name in the body; copy audited by ClaimsPolicy. |
| T-03-10 | Denial of Service | Med name/note free-text in addMedication | mitigate | `maxNoteLength` prefix-clamp at the Settings commit + Repository seam (Plan 01). |
| T-03-11 | Elevation of Privilege | Requesting notification authorization too early | mitigate | JIT request only inside the first-enable handler (D-20); never at launch/onboarding (asserted by grep that App init has no requestAuthorization). |
| T-03-12 | Information Disclosure / Data Protection | Reminder config placement | mitigate | Reminder times/quiet-hours/enabled in UserDefaults only (device pref), never in the CloudKit-bound store (A2). |
| T-03-13 | Tampering / data loss | Med removal orphaning prior "taken" history | mitigate | Soft-archive (`archiveMedication` sets isArchived) — never hard-delete; prior `.medication` readings keyed by med id stay valid. |
| T-03-SC | Tampering | package installs | accept | Zero external packages — first-party UserNotifications/SwiftUI only (no entitlement for local notifications). |
</threat_model>
