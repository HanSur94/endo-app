<objective>
Ship durable insight dismissal (INST-04 SC4 / D-09/D-10/D-18): a CloudKit-safe `DismissedInsight` `@Model`, a new additive `SchemaV4` with a lightweight V3→V4 migration, a `SchemaMigrationTests` V3→V4 survival case, and consent-gated `Repository.dismissInsight(signalKey:)` / `dismissedSignalKeys() -> Set<String>`. This is a closed-world repeat of the proven `FactorReading`/`SchemaV3` additive-migration recipe. The live UI dismiss-button + wiring `dismissedSignalKeys()` into `InsightsEngine` is Phase 8 (out of scope).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository write → SwiftData store → private CloudKit DB | A new synced record (`DismissedInsight`) crosses into the user's private iCloud DB; only a signalKey + timestamp may cross |
| Caller → Repository dismissal CRUD | Health-data persistence boundary — must be consent-gated (ONBD-01) |
| V3 store on disk → V4 reopen | Migration boundary — data-loss here is catastrophic for a health log |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-09 | Information Disclosure | `DismissedInsight` synced to a CloudKit DB | mitigate | The model carries ONLY an engine-generated category `signalKey` (e.g. `cyclePhase.luteal.symptom.pelvicPain`) + a timestamp — a category label, NOT raw symptom text/severities; stored in the user's PRIVATE CloudKit DB only (Phase 4 entitlement). Confirmed by the model's two fields + header comment |
| T-06-10 | Elevation / Repudiation | Dismissal record written pre-consent | mitigate | `assertConsented()` defence-in-depth on BOTH new Repository methods (V4 pattern), like every sibling |
| T-06-11 | Tampering / DoS | Data loss on V3→V4 migration | mitigate | Additive `.lightweight` V3→V4 (NEVER `.custom`) + the survival test proving every V3 row persists and `DismissedInsight` is queryable (mirrors the proven V2→V3 case) |
| T-06-12 | Tampering | `signalKey` collision causing wrong dismissal | mitigate | signalKeys are namespaced, value-independent strings produced by the engine (`cyclePhase.<phase>.symptom.<type>`) — not user free-text, so no injection surface (V5); dedupe-on-read via `Set` |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | Zero new third-party packages (RESEARCH §Package Legitimacy Audit: not applicable); first-party SwiftData only |
