
Rationale / substring-trap notes (DOCUMENT THESE in the ForbiddenTerms doc-comment per CONTEXT):
- `"diagnos"` (stem) catches diagnose/diagnosis/diagnostic in one entry.
- `"predict"` catches predict/prediction/predicts.
- `"certain"` catches certain/certainty/certainly; `"definitely"` catches the certainty adverb.
- `"will flare"` is a two-word stem catching the binary "you will flare" (note: `"will"` ALONE is already in `ForbiddenTerms.causal`; the two-word stem is the alarmist-specific binary form).
- `"alarm"` ⊂ nothing in the calm copy; `"alert"` ⊂ "alerted" (not used). `"danger"` whole-word.
- `"episode"` and `"attack"` are the endo-specific additions (a flare must never read as an "attack"/"episode").
- DO NOT add `"warning"` to this list: the section HEADER copy is literally "Flare early-warning" (D-07 / UI-SPEC), so `"warning"` as a forbidden substring would self-fail the header. The header is the ONLY sanctioned use of the word; the alarmist scan covers the in-card copy. Exclamation marks are caught structurally by curating no `"!"` into FlareCopy; the alarmist list does not include `"warning"`.

The app-side `ClaimsPolicy.forbiddenAlarmist` MUST be byte-set-identical to the package `ForbiddenTerms.alarmist` (Plan 02's `FlareDriftGuard` + drift test assert set-equality).

## Positive / negative controls the scan must satisfy (mirror the Phase-11 imperative controls)
- POSITIVE (must be FLAGGED): "a flare attack is imminent", "we predict a flare", "you will flare", "this is an emergency".
- NEGATIVE (must pass CLEAN — the curated calm forms Plan 02 ships): "your recent pattern looks similar to times before more difficult days", "something to keep an eye on and discuss with your clinician", "based on a recent rising pattern and a factor you have logged recently". (NOTE: the naive UI-SPEC wording "not a prediction" contains "predict" → it would be FLAGGED, so the curated detail deliberately AVOIDS "prediction"; the negative-control set uses the final clean forms only.)

## RED FlareEngine contract (the suite references symbols Plan 02 creates)
`FlareEngine.flareWarning(from: [DaySnapshot], asOf: Date, calendar: Calendar) -> [Insight]` — same signature shape as `RecommendationsEngine.recommendations`. The suite calls it and asserts:
- suppressed fixture → `[]`
- a flat/no-rise fixture (history but no recent rising severity) → `[]`
- an under-21-evidence rising fixture → either `[]` OR exactly one `isInsufficiencyNotice` card (the cusp case, A3) — assert NO non-notice warning surfaces
- a rising-with-≥21-evidence fixture → exactly one `.flare` Insight, `window == .allTime`, `signalKey == "flare.warning"`, `confidence <= .medium && confidence >= .low`, `points.isEmpty`, `sampleSize >= 21`, and zero forbidden terms (causal ∪ imperative ∪ alarmist) in headline+detail
- determinism: same fixture twice → equal `[Insight]`
