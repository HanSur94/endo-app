<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk SQLite DB ↔ future schema migrations | A v(N)→v(N+1) bump that loses data (destructive fallback) |
| health-value columns ↔ nil→0 coercion | Room's non-null freedom tempting a DEFAULT 0 that destroys absence≠0 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-01 | Denial of service (data loss) | Room schema migration | critical | mitigate | exportSchema=true + committed schemas/1.json + MigrationTestHelper scaffold (Task 2/3); destructive-migration fallback structurally banned by DestructiveMigrationBanTest (Task 3) — a schema bump can never silently wipe health history |
| T-18-05 | Tampering (data integrity) | nullable health-value columns | high | mitigate | Optional health signals stay nullable (no NOT NULL DEFAULT 0, no `?: 0`); non-null spent only on id/day-key/timestamps — absence≠0 preserved end-to-end (Task 1 grep gate) |
| T-18-06 | Denial of service | corrupt/future raw string stored in a column | medium | accept | Raw enum strings stored verbatim at the entity layer; defensive decode is enforced at the SnapshotProjector bridge (Plan 04), not duplicated per column here |
</threat_model>
