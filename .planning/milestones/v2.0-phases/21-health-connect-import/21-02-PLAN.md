## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HC provider record → ImportedSample row | Untrusted record fields (flow/stage/exerciseType ints, timestamps) cross into the app's value model here; a malformed field must never crash or fabricate a health value. |
| HealthReader interface boundary | No androidx.health.* type escapes; the mapper is the sole place HC records become app values, keeping the merge JVM-testable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-02a | Tampering (data integrity) | HealthRecordMapping defensive decode | medium | mitigate | Unknown flow/stage/exerciseType → honest fallback (spotting/excluded/OTHER), never a crash or fabricated value (V5); a present record is honest (no record = no field, never 0). |
| T-21-02b | Tampering (correctness) | epochDay bucketing | high | mitigate | Bucket by the START instant in ZoneId.systemDefault() (never the record zoneOffset); DST/travel/midnight test vectors pin iOS parity so two platforms never disagree which day a record started. |
| T-21-02c | Spoofing / loop | own-package guard in HealthConnectReader | low | mitigate | UpsertionChange from our own packageName is skipped (we write none anyway) so a re-imported self-write can never loop. |
