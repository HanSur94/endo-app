<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app ↔ Health Connect provider | The app declares itself an HC client via manifest permissions + rationale intents; the OS/HC provider owns the actual grant. Over-broad or write permissions here are an elevation/Play-rejection risk. |
| app ↔ Google Maven (supply chain) | connect-client is pulled at build; a forbidden coordinate would breach the zero-network audit surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-01 | Elevation of Privilege / Tampering | AndroidManifest.xml permission set | high | mitigate | Declare ONLY the four health READ + READ_HEALTH_DATA_HISTORY; zero WRITE_, no READ_HEALTH_DATA_IN_BACKGROUND, no INTERNET. ManifestPermissionsTest allow-list + deny-list (DOM-parse, comment-safe) fails the build on any injected WRITE/background/network permission. |
| T-21-01b | Spoofing / DoS | Dual rationale declaration | high | mitigate | Declare BOTH the Android 13- rationale <activity> AND the 14+ <activity-alias>; a missing declaration yields an empty grant set on that OS generation or Play rejection. Manifest test asserts both are present. |
| T-21-SC | Tampering (supply chain) | connect-client 1.1.0 install | low | accept | First-party AndroidX Maven artifact (verified against the official AndroidX release page + STACK.md); the npm/pip/cargo legitimacy seam does not apply. VersionCatalogAuditTests confirms no analytics/auth/networking coordinate. No blocking-human checkpoint needed (mirrors T-20-SC WorkManager). |
</threat_model>
