# Phase 20 — UI Design Contract

> Visual and interaction contract for the Tracking Screens phase (Daily Check-In, Day Log editor + BodyMap, medications, Settings + reminders). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a PORT.** Visual/interaction direction is FIXED by the shipped iOS tracking screens (`Features/CheckIn/DailyCheckInView.swift`, `Features/DayLog/{DayLogEditorView,BodyMapView,SeverityControl}.swift`, `Features/Settings/SettingsView.swift`, `Reminders/{ReminderSettings,NotificationScheduler}.swift`) and the already-ported **Bloom** design system (Phase 19). This document is a *translation* to Jetpack Compose / Material 3 — not a new look. Where a generic UI heuristic collides with faithful parity, **parity wins**, with the deviation noted.
>
> **Do not redefine tokens.** All color / typography / spacing / radius / component contracts are the Phase-19 Bloom contract (`19-app-shell-consent/19-UI-SPEC.md`, realized in `com.endoapp.app.designsystem`: `BloomColors`/`LocalBloomColors`, `BloomTypography`, `BloomShapes`, `BloomComponents` — `bloomCard`, `BloomPrimaryButton`, `BloomChip`, `EyebrowLabel`, `DisclaimerBanner` — `BloomNavigationBar`, `BloomTabIcons`). This spec references those by name and only adds the *new* component contracts this phase introduces (SeverityControl, BodyMap, section-list rows, reminder time rows).

## 2. BodyMap Accessibility Contract (SYMP-02 — first-class, non-visual path required)

The non-visual path is a **hard requirement**, not a nicety. The accessibility contract — not the exact silhouette geometry — is load-bearing (mirrors the iOS `BodyMapBindingTests` / SYMP-02 contract).

**Rendering approach (discretion, recommended):** a Compose `Canvas` drawing the silhouette as a `Path` in a 200×440 author view-box scaled aspect-preserving (`.aspectRatio(200f/440f)`), on a `surfaceSunken` rounded card. Transcribe the iOS `BodySilhouette` path if faithful geometry is wanted; geometry may iterate later without any contract change. Front and back share one silhouette; only the hotspot set differs.

**Hotspots — one focusable ≥48dp element per `BodyRegion`:**
- Rendered as `Box`es positioned by the normalized center below (`x*width`, `y*height`), each with a visible dot (~22–26dp) but an **effective ≥48dp hit target** (`Modifier.size(48.dp)` + `minimumInteractiveComponentSize()`), `contentShape`.
- Each carries: `Modifier.semantics { role = Role.Button; contentDescription = region.plainLabel; stateDescription = "severity N of 10" | "not marked" }` + `testTag = "bodymap.region.<raw>"`. Tapping opens the region severity sheet.
- **Severity conveyed by NUMBER (a centered badge) + tint — never color alone.** Marked: `rose` halo ramped by severity + a `plum` badge with the white numeral. Unmarked: faint `rose` ring.
- **Focus order:** front/back toggle → each hotspot in `BodyRegion.allCases` order → marked-areas summary → "All areas (list)" fallback.

**Front/back sets** (verbatim from iOS): Front = `lowerAbdomenPelvis, lowerQuadrantLeft, lowerQuadrantRight, bladder, upperThighs, chestDiaphragm, shoulder`; Back = `lowerBack, hips, rectalBowel`.

**Normalized hotspot centers** (unit coords in the 200×440 box — verbatim from iOS `hotspotCenter`):

| Region (`raw`) | x | y | Side |
|----------------|---|---|------|
| `shoulder` | 0.500 | 0.155 | front |
| `chestDiaphragm` | 0.500 | 0.239 | front |
| `lowerAbdomenPelvis` | 0.500 | 0.398 | front |
| `lowerQuadrantLeft` | 0.380 | 0.420 | front |
| `lowerQuadrantRight` | 0.620 | 0.420 | front |
| `bladder` | 0.500 | 0.482 | front |

**Non-map LIST fallback (fully operable without the visual map):** a "All areas (list)" disclosure (`testTag=bodymap.listFallback`) listing ALL ten regions as buttons (`testTag=bodymap.list.<raw>`), each with `contentDescription = region.plainLabel`, `stateDescription = "severity N of 10" | "not marked"`, `Role.Button` — opening the SAME severity sheet and setting the SAME draft point. TalkBack users complete the pain map entirely through this list.

**Region severity sheet:** `ModalBottomSheet` titled "Pain area" containing the region label + `SeverityControl` (`testTag=bodymap.region.<raw>` scope) + a destructive "Clear this area" (`bodymap.region.<raw>.clear`, disabled when unmarked) + a "Done" (`bodymap.region.<raw>.done`).

**Marked-areas summary:** petal `BloomChip`-style pills (`testTag=bodymap.markedSummary`), region label + `N/10`; the numeric value always carries meaning (mini-bar is decorative, `clearAndSetSemantics {}` / hidden).

**testTag scheme:** mirror the iOS `bodymap.*` a11y ids verbatim — `bodymap.sideToggle`, `bodymap.region.<raw>`, `bodymap.region.<raw>.clear`, `bodymap.region.<raw>.done`, `bodymap.list.<raw>`, `bodymap.listFallback`, `bodymap.markedSummary`. (Android `testTag` ≠ TalkBack description; supply both.)

## 3. Honesty in the UI (absence ≠ 0)

The UI-side carry of the engine/persistence honesty invariant. **An untouched optional field is "not logged", never 0.** A logged severity 0 is a real 0. Every optional draft is nullable; the UI never fabricates a value, and the round trip (edit → `EndoRepository` write → reload) preserves nil-vs-0 exactly.

| Field | Draft type | "Not logged" shown as | Real-zero distinct? | Round-trip rule |
|-------|-----------|------------------------|---------------------|-----------------|
| Symptom severity | `Map<SymptomType,Int>` (absent = not selected) | symptom row unchecked; no SeverityControl | severity `0` is a real logged 0 (slider left end) | absent symptom → repo `removeSymptom`; present → `upsertSymptom` |
| Pain-region severity | `Map<BodyRegion,Int>` (absent = not marked) | "not marked" (badge absent, `stateDescription`) | severity `0` real | absent → `removePainPoint`; present → `setPainPoint` |
| Bleeding flow | `FlowIntensity?` | no flow selected (clots toggle disabled) | n/a (categorical) | nil flow clears the day's bleeding |
| Food tags / note | `Set<FoodTag>` + `String` | "Not logged" placeholder when both empty | n/a | empty note → nil at seam |
| Activity type/min/intensity | `ActivityType?` + `Double` + `ActivityIntensity?` | "Not logged" until a type chosen | minutes `0` with a type = real 0 | nil type → minutes+intensity also nil |
| Sleep hours / quality | `Double` + `sleepHoursSet: Boolean` + `SleepQuality?` | read-out "—"; "Not logged" until either set | `0.0 h` with `sleepHoursSet` = real 0 | `sleepHoursSet=false` → hours nil at seam |
| Medication taken | `Set<UUID>` | untoggled = not taken/not logged (never "skipped") | n/a | per-med `setMedicationTaken(taken)` |
| PRN | `Boolean` | off = not logged | n/a | `setPRN` |
| Stress | `Int?` behind opt-in | "Not logged"; control hidden | `0` real once opted in | not opted in → nil clears |
| Mood | `Int?` (1–5) | "Not logged" until a value tapped | n/a (1–5) | nil clears |
| Day note | `String` | empty field | n/a | empty → nil at seam |

**Empty states:** no saved meds → a calm "No medications saved yet." card that points to Settings (see Copy for audit-safe wording); Log home with no logged days → an honest "Nothing logged yet" prompt to start a check-in (audit-safe wording). Each untouched factor section renders the shared **"Not logged"** caption (`inkSecondary`), never a 0.

## 4. Reminder / Notification UX (inexact, one channel, no flare notifications)

| Concern | Contract |
|---------|----------|
| **Scheduling** | Daily check-in reminder via **WorkManager periodic work** (recommended — survives reboot with no extra manifest receiver, needs no exact alarm). **NEVER `SCHEDULE_EXACT_ALARM`** and never `setExact*`. Minutes of drift are acceptable. Reschedule idempotently on every edit (mirror `reschedule(times, quietHours)`); quiet-hours windows (incl. midnight-crossing 22:00–07:00) suppress a time via the ported `isInQuietHours`. |
| **Just-in-time permission** | Request `POST_NOTIFICATIONS` (Android 13+) **only** when the user flips the reminders master toggle ON — never at launch/onStart. On Android <13 no runtime request (implicitly granted). Mirror the iOS JIT `enableReminders()` flow: request → if granted, seed a single default time (20:00) when none exist + schedule; if denied, leave the toggle visibly OFF with calm copy + an "Open Settings" path (no nag loop). |
| **Channel** | Exactly **one** `NotificationChannel` for the daily reminder (created on first enable). Channel name/description are user-facing → copy audit. The channel exists ONLY for reminders. |
| **Notification content** | Generic, audited, non-health-revealing: title **"Daily check-in"**, body **"Whenever you have a moment, your daily check-in is ready."** No symptom/flare/streak wording (lock screen is semi-public). |
| **Deep link** | Tapping the notification opens the app → **lands on the consent gate** → if consented, the consented Log subtree observes `CheckInRouter.presentCheckIn` and pushes the Daily Check-In. The intent carries only a non-sensitive flag; it never constructs health UI pre-consent. Flag reset once consumed. |
| **Auto-suppress on log** | Completing a check-in/day-log records a today-marker consulted at delivery so today's reminder is suppressed WITHOUT deleting the repeating registration (it re-fires tomorrow). Dismissal/save is never blocked on the notification side effect (fire-and-forget). |
| **Reboot** | WorkManager reschedules its periodic work across reboot itself; add `RECEIVE_BOOT_COMPLETED` to the manifest **only** if an inexact-`AlarmManager` fallback is chosen instead. |
| **Denied state** | Reminders section shows a calm line — "Notifications are turned off for Endo-App. You can turn them on anytime in Settings." — plus an "Open Settings" button. The app stays fully usable; logging is never gated on reminders. |

**Design invariant — no flare notifications (from CONTEXT §5):** the reminder package (`com.endoapp.app.reminders`) is the **ONLY** notification/alarm surface in the app and is **physically separate** from any flare/insights code. There are deliberately NO flare/alarm notifications. Do NOT reference `POST_NOTIFICATIONS`, `NotificationManager`, `NotificationChannel`, `WorkManager`-for-alerts, or any alarm API anywhere near flare logic. The Phase-22 structural scan (flare sources contain zero notification/alarm APIs) must stay clean; ensure this package is cleanly separable so that guard (seeded here or in Phase 22) passes.

## 7. Copywriting Contract

### The substring gate (READ FIRST — non-negotiable)

Every user-facing string this phase introduces MUST be registered in `CopyAuditRegistry.sources` (an `object …Copy : AuditableCopy`) **in the same change** that introduces the screen. `CopyAuditTest` runs a **case-insensitive SUBSTRING** scan against `ClaimsPolicy` (causal + imperative + alarmist + gendered + precision). Curated copy must avoid these substrings entirely, including innocent host words:

- `her` ⊂ **here / there / where / other / gather** → avoid all.
- `use` ⊂ used/cause/because; `start` ⊂ started; also avoid as substrings: `take, stop, avoid, should, must, try, cut` (imperative); `will, causes, trigger, detect, diagnose, treat, cure, prevent, because` (causal); `attack, alarm, alert, urgent, danger, predict, imminent, certain, definitely, episode, guarantee` (alarmist); `%, p =, r =` (precision).

**Near-miss audit performed on the port copy — three iOS strings FAIL the Android substring gate and are reworded below:**
- iOS "…they'll appear **here** to tick off each day." / "…mark it taken **here**." → **"here"** contains `her`. Reworded to end "…each day." (drop "here").
- iOS meds-remove "This **stops** it from appearing…" → **"stops"** contains `stop`. Reworded to "This keeps it out of your daily check-in…".
- iOS cycle-off footer "…continuous **treatment**. Endo-App **stops** showing…" → **"treatment"** contains `treat`, **"stops"** contains `stop`. Reworded to "…continuous hormonal medication. Endo-App then hides…".

Also confirmed SAFE (classic near-misses that pass): **"Great"** (mood) does not contain `treat`; **"Moderate"/"Severe"** clean; **"Same as yesterday"**, **"carried over"**, **"never"**, **"Whenever…ready."** all clean (no `her`); **"usual"** has no `use`; **"stretching"/"strength"** clean.

## 8. Acceptance / Verification Hooks

Robolectric/JVM Compose where possible (preferred), else instrumented. What the phase's tests assert:

1. **Absence ≠ 0 round trip (per screen):** log a day touching *some* fields and skipping others → write via `EndoRepository` → reload the editor/check-in → skipped optional fields read "not logged" (nil), a slid-to-0 severity reads a real 0. Pin every row in §3. (Mirrors the iOS honesty tests.)
2. **Empty confirm records adherence, invents nothing:** confirming Check-In with no input records only the `checkInMarker` (DayEntry anchor), surfaces "Checked in for today.", and writes zero symptom/factor/bleeding rows.
3. **"Same as yesterday" prefills sticky context only:** applying it fills meds/sleep/activity from yesterday's snapshot and leaves `severities`, `flow`, `clots` untouched (never fabricates symptom/bleeding events).
4. **BodyMap per-region semantics present:** for all ten regions, a focusable node exists with `Role.Button`, a non-empty `contentDescription`, a `stateDescription` reflecting "severity N of 10"/"not marked", ≥48dp target, and `testTag=bodymap.region.<raw>`; the list fallback (`bodymap.list.<raw>`) sets the same point. Assert on the semantics tree.
5. **Save-suppresses-reminder decoupling:** saving/confirming fires the reminder auto-suppress as an independent effect and does not block dismissal.
6. **Reminder schedules inexactly + JIT permission:** enabling reminders requests `POST_NOTIFICATIONS` (Android 13+) only in the enable handler (source/behavioral scan — no request at launch), schedules via WorkManager (no `setExact*`, no `SCHEDULE_EXACT_ALARM`), creates exactly one channel, and quiet-hours suppress the fire (pure `isInQuietHours` unit test incl. midnight-crossing).

Assert allow-list AND deny-list.

9. **Copy registered & clean:** every string in §7 is in `CopyAuditRegistry.sources`; `CopyAuditTest` green (the three reworded strings pass; enum labels re-registered; withdraw copy reuses Phase-19 registration).
