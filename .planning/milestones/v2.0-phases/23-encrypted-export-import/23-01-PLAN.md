  <behavior>
    - deriveKey(passphrase: CharArray, salt: ByteArray, iterations: Int, keyBits: Int) returns a 256-bit AES SecretKeySpec derived via PBKDF2WithHmacSHA256; identical inputs → identical key bytes (deterministic); different salt → different key.
    - encrypt(plaintext, key, iv) then decrypt(ciphertext, key, iv) round-trips to the exact plaintext (AES/GCM/NoPadding, 128-bit tag).
    - decrypt with a key derived from the WRONG passphrase throws AEADBadTagException (the tag is the wrong-passphrase signal).
    - secureRandomBytes(n) returns n bytes; two calls differ (SecureRandom).
    - Hygiene: PBEKeySpec.clearPassword() is called in a finally; the raw derived key-byte array is zeroed after wrapping into the SecretKeySpec.
  </behavior>
  <action>
    Create `object ExportCrypto` in package `com.endoapp.app.export`, PURE JVM — imports ONLY `javax.crypto.*` (Cipher, SecretKeyFactory, SecretKey, spec.SecretKeySpec, spec.PBEKeySpec, spec.GCMParameterSpec, AEADBadTagException) and `java.security.SecureRandom`; NO `android.*`, NO `androidx.*`.

    Expose: `deriveKey(passphrase: CharArray, salt: ByteArray, iterations: Int, keyBits: Int): SecretKey` — build a `PBEKeySpec(passphrase, salt, iterations, keyBits)`, `SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256").generateSecret(spec).encoded`, wrap as `SecretKeySpec(bytes, "AES")`, zero the intermediate byte array, and call `spec.clearPassword()` in a `finally`. Name the algorithm as a `private const val` (available since API 26 = minSdk). Do NOT hard-code iterations/keyBits inside deriveKey — they are PARAMETERS (the caller passes the header's recorded values).

    Expose two thin AES-GCM helpers used by the codec: `encrypt(plaintext: ByteArray, key: SecretKey, iv: ByteArray): ByteArray` and `decrypt(ciphertext: ByteArray, key: SecretKey, iv: ByteArray, offset: Int = 0, length: Int = ciphertext.size): ByteArray` — each `Cipher.getInstance("AES/GCM/NoPadding")` with `GCMParameterSpec(128, iv)`; the ciphertext output already carries the appended 128-bit tag (javax.crypto's doFinal contract). Let AEADBadTagException propagate from decrypt (the codec maps it). Add `secureRandomBytes(n: Int): ByteArray` filling from a `SecureRandom`.

    Do NOT log the passphrase, key bytes, or plaintext anywhere (V7). Keep the file free of any I/O.

    Write `ExportCryptoTest` (JUnit4, pure JVM) proving the five behaviors above.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| passphrase (user secret) → key derivation | The only secret; never stored, never logged |
| import file (untrusted bytes) → decode | A crafted/corrupt file must never crash or OOM the parser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-01 | Tampering / Information disclosure | ExportCodec.encode salt/IV | high | mitigate | Fresh SecureRandom 16-byte salt + 12-byte IV per export, recorded in the header; TwoExportsDifferTest pins that two exports of identical data differ (GCM nonce-reuse structurally impossible) |
| T-23-02 | Information disclosure | ExportCrypto.deriveKey | high | mitigate | PBKDF2WithHmacSHA256 with the header's 600k iterations (OWASP-current) over a fresh salt; params recorded in-header so the count is upgradeable |
| T-23-03 | Information disclosure | ExportCrypto passphrase/key handling | medium | mitigate | CharArray passphrase + PBEKeySpec.clearPassword() in finally; zero the derived key bytes after wrapping; no logging of passphrase/key/plaintext |
| T-23-04 | Denial of Service | ExportCodec.decode headerLength | medium | mitigate | Bounds-check headerLength (reject ≤0 or >64 KiB) before allocating; out-of-range → NotAnExport (never allocate from an untrusted length) |
| T-23-05 | Spoofing / Tampering | ExportCodec.decode ordered checks | medium | mitigate | Order magic/parse/version checks BEFORE decryption; only doFinal's AEADBadTagException maps to WrongPassphrase; ExportErrorTaxonomyTest pins the three distinct outcomes with no exception escape |
| T-23-SC | Tampering | dependencies / version catalog | low | accept | No new package this phase — all crypto is platform `javax.crypto`, compression is `java.util.zip`, Base64 is `java.util.Base64`, serialization reuses catalog kotlinx-serialization; the catalog-audit stays green, so there is nothing to install and no [ASSUMED]/[SUS] package to gate |
</threat_model>
