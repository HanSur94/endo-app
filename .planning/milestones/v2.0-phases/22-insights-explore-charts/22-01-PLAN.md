<objective>
Build the `InsightsCoordinator` — the app-scoped, off-main insight recompute + fingerprint-cache coordinator (the Android analog of the shipped iOS `InsightsCoordinator`, per D-01/D-03/D-13 and STATE `[08-02]`). It reads Room-projected day snapshots + dismissed keys, runs the ALREADY-PORTED `InsightsEngine` (Phase 17) OFF the main thread via `withContext(Dispatchers.Default)`, caches results in the ALREADY-EXISTING `CachedInsight` entity (replace-all), loads that cache instantly on appear, excludes `DismissedInsight` keys, and publishes a `StateFlow` the dashboard renders. Recompute triggers are foreground + save + dismiss.

Purpose: this is the engine-to-UI seam. Without it the dashboard would run the correlation matrix on the main thread and re-run it on every open — the exact "insights recompute on main thread" freeze called out in PITFALLS (Performance Traps). This plan is pure coordination + persistence wiring; it renders nothing (Plan 04 renders `coordinator.state`).

Output: `InsightsCoordinator`, `InsightFingerprint`, three new consent-gated `EndoRepository` cache/dismiss methods over the existing `InsightsDao`, construction in `AppDependencies`, and JVM tests proving off-main, cache hit/miss, debounce, and dismiss feed-through.
</objective>

Expose immutable UI state as a `StateFlow`: define `data class InsightsUiState(val insights: List<Insight> = emptyList(), val isUpdating: Boolean = false)` and back it with a private `MutableStateFlow` surfaced as `val state: StateFlow<InsightsUiState>`.

EVERY dependency is an INJECTED seam so the coordinator is unit-testable with no store or clock (mirror STATE `[08-02]`): `loadSnapshots: suspend () -> List<DaySnapshot>`, `loadDismissed: suspend () -> Set<String>`, `loadCache: suspend () -> List<Insight>`, `persist: suspend (List<Insight>, Long, String) -> Unit`, `writeDismissed: suspend (String) -> Unit`, `now: () -> LocalDate`, `nowMillis: () -> Long`, `engine: (List<DaySnapshot>, LocalDate, Set<String>) -> List<Insight>` (default `InsightsEngine::insights`), a `CoroutineScope`, `defaultDispatcher: CoroutineDispatcher = Dispatchers.Default`, and `debounceMillis: Long = 400`.

Behavior:
- `fun loadCached()` — launch on the scope: set `isUpdating` appropriately, call `loadCache()`, publish those insights instantly (the instant paint before any recompute). Never blocks.
- `fun dataChanged()` — cancel any in-flight recompute job, then launch a job that `delay(debounceMillis)` (coalesces rapid save/foreground/dismiss bursts into ONE recompute) then calls the private `recompute()`.
- private `suspend fun recompute()` — read `loadSnapshots()` + `loadDismissed()` on the calling context, compute `InsightFingerprint.make(snapshots, dismissed)`; if it equals `lastFingerprint` → cache HIT, skip the engine entirely, clear `isUpdating`, return. Else set `isUpdating = true`, run the engine INSIDE `withContext(defaultDispatcher) { engine(snapshots, now(), dismissed) }` (the ONLY off-main work — never on the main/Compose thread), then `persist(result, nowMillis(), fingerprint)` best-effort, publish `result`, store `lastFingerprint`, clear `isUpdating`.
- `fun dismiss(signalKey: String)` — launch: `writeDismissed(signalKey)` (append-only `DismissedInsight`, non-destructive — NEVER deletes logged data), optimistically drop that card from the current `state.insights`, then `dataChanged()` so the recompute excludes the key.

Wire it in `AppDependencies`: construct `val insightsCoordinator: InsightsCoordinator` over the live `repository` seams (`loadSnapshots = repository::daySnapshots`, `loadDismissed = repository::dismissedSignalKeys`, `loadCache = repository::loadCachedInsights`, `persist = repository::replaceCachedInsights` wrapped best-effort with `runCatching`, `writeDismissed = { repository.dismissInsight(DismissedInsight(id = UUID.randomUUID().toString(), signalKey = it, dismissedAtMillis = System.currentTimeMillis())) }`, `now = { LocalDate.now() }`, `nowMillis = System::currentTimeMillis`, `scope = applicationScope`). Do NOT thread it into the shell here — Plan 04 threads it into the Insights tab. Adding no notification/alarm/WorkManager import keeps the existing `NotificationSeparationTest` green.
  </action>
