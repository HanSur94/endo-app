# Phase 22 — UI Design Contract

> Visual and interaction contract for the Insights Dashboard, Explore & Charts phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a PORT.** The visual/interaction direction is FIXED by the shipped iOS Insights + Explore screens (`Sources/EndoApp/Features/Insights/*.swift`, `Sources/EndoApp/Features/Explore/*.swift`) and by the already-ported **Bloom** design system (Phase 19). This document is a *translation* of those screens into a concrete Jetpack Compose / Material 3 + **Compose Canvas** contract — not a new look. The chart DATA-PREP + engine are ALREADY PORTED (Phase 17, `:insights`); this phase RENDERS them, coordinates recompute, and makes every data point TalkBack-accessible.
>
> **Reuse, do not redefine.** All design tokens (color, typography, spacing, radius, shadow), the `BloomTheme`/`LocalBloomColors` exposure, the Bloom components (`Modifier.bloomCard`, `BloomChip`, `BloomPrimaryButton`, `EyebrowLabel`, `DisclaimerBanner`), the `CopyAudit` substring gate, and the `testTag` conventions are established in [19-UI-SPEC.md](../19-app-shell-consent/19-UI-SPEC.md) and shipped in `com.endoapp.app.designsystem`. This spec references them; it re-states only the NEW deltas this phase introduces (chart rendering, chart a11y, confidence pill, dashboard/Explore layout, and the new copy surfaces).

## Screen / State Inventory

Two tabs of the Phase-19 `ConsentedShell` are filled: **Insights** (`tab.insights`) and **Explore** (`tab.explore`). Both are referenced ONLY inside the consented branch (consent-by-construction, Phase 19). Both read logged (Phase 20) + imported (Phase 21) data uniformly through `SnapshotProjector → daySnapshots()`.

### A. Insights tab — the gated dashboard

Root: a `LazyColumn` (the iOS grouped `List` analog) on `canvas` background, `testTag = insights.screen`. Vertical rhythm uses Phase-19 spacing (`space.xl` 24dp between blocks, `space.lg` 16dp screen horizontal padding). Chrome header = `bloomTitle` "Insights" + `body`/`inkSecondary` subtitle.

**Fixed block order (top → bottom) — mirrors `InsightsView.swift`:**

| # | Block | testTag | Notes |
|---|-------|---------|-------|
| 1 | Serif title + subtitle | `insights.header` | Presentational chrome. Subtitle from `InsightsCopy` (audit-clean). |
| 2 | At-a-glance stat strip | `insights.statStrip` | Shown only when `insights` non-empty. Derived counts (total surfaced + distinct kinds) over the already-loaded list — no new data source, no fabricated stats. Two `bloomCard(padding=14.dp)` tiles. |
| 3 | Pinned disclaimer | `insights.disclaimer` | Reused `DisclaimerBanner` (Phase 19) — always visible with the insights (not-medical-advice framing). Never duplicated; renders `Disclaimer.text` verbatim. |
| 4 | Updating caption | `insights.updating` | Non-blocking. A subtle "Updating…" caption + small spinner in the top area while `coordinator.isUpdating`. NEVER a full-screen blocking spinner; cached content stays visible. |
| 5 | **Flare** section | `insights.section.flare` | **Placed FIRST** among the kind sections (time-sensitivity by POSITION only). Same calm section helper + same kind-agnostic card as every other section — NO alarm color/badge/glyph (see §Calm Flare). |
| 6 | Trends section | `insights.section.trends` | `.trend` cards — each embeds the trend line chart (§Chart Rendering). |
| 7 | Cycle-phase section | `insights.section.cyclePhase` | `.cyclePhase` cards. **Provably ABSENT for a suppressed / no-cycle user** (the engine emits zero `.cyclePhase`; the section is omitted, not an empty shell). |
| 8 | Possible-associations section | `insights.section.correlations` | `.correlation` cards. Header copy = "Possible associations" (avoids "Correlations"/causation). Each card may carry the scatter deep-link affordance (§Interaction). |
| 9 | Recommendations section | `insights.section.recommendations` | `.recommendation` cards, read AFTER the associations they derive from. |

**Section helper contract:** a section with ZERO gated insights of its kind is **OMITTED entirely** — never rendered as an empty shell. This is the honesty mechanism behind the suppressed-cycle case and the absence-by-omission of flare/recommendations for sparse users.

**The three honest states (`InsightsView` §C):**

|-------|---------|--------|---------|

| **Sparse** | a per-signal insufficiency notice (`insight.isInsufficiencyNotice == true`) | a "Not enough data yet." card by the SAME `InsightCard` composable (no chart, no confidence pill) | `insights.card.<signalKey>.insufficient` |
| **Empty** | zero gated insights total | ONE warm full-screen empty state (NOT empty sections) — chart glyph + heading + body | `insights.empty` |
| **Suppressed** | engine emits no `.cyclePhase` | the cycle-phase section is provably absent | assert ABSENCE of `insights.section.cyclePhase` |

**The kind-agnostic insight card (`InsightCard`, mirrors `InsightCardView.swift`) — fixed top→bottom anatomy inside a `Modifier.bloomCard()`:**

| # | Element | Source | testTag |
|---|---------|--------|---------|
| 1 | Headline | `insight.headline` VERBATIM (engine-audited), `bloomH3` | — |
| 2 | Confidence pill | plain-language text + icon (§Confidence Pill) — NEVER a number, NEVER color alone. Omitted on the sparse state. | `insights.card.<signalKey>.confidence` |
| 3 | Detail | `insight.detail` VERBATIM, `body`/`ink` | — |
| 4 | Supporting | `.trend` → the trend line chart; `.cyclePhase`/`.correlation`/`.recommendation`/`.flare` → a **words-only** evidence line ("Seen across {n} logged days." + window label) — NEVER a coefficient/percentage/p-value; plus the optional scatter deep-link (`.correlation` only) | `insights.card.<signalKey>.chart` / `.evidence` / `.scatterLink` |

The card carries a stable `testTag = insights.card.<signalKey>` (value-independent — survives recompute, keyed to the dismissal key). Kind-agnostic: flare, cycle-phase, correlation, recommendation, trend all use it.

## Chart Rendering Spec (Compose Canvas)

All charts render with Compose `Canvas` / `drawWithCache`. Chart inputs are `@Immutable`/stable holder classes produced ONCE by the ported data-prep layer (the same seam the honesty tests pin). Scrub state is read only in the **draw phase** (never composition) so a finger movement invalidates draw, not composition/layout (PITFALLS #14 — the difference between Canvas being viable and a premature Vico switch). `Path`s are built in `drawWithCache` keyed on series + size; only the scrub rule/lollipop draws per frame. Tooltip text updates via `derivedStateOf` snapping to day granularity.

### Chart-honesty invariants (LOCKED — design invariants, pinned by tests on the data-prep layer AND asserted in render where applicable)

| # | Invariant | Where enforced |
|---|-----------|----------------|
| H1 | **Gaps stay gaps.** An unlogged day is a **line BREAK**, never a zero, never interpolation. Each contiguous logged-day run is a distinct path segment; the line breaks between runs. | data-prep (`ChartScrubSelection` never interpolates/snaps) + render (per-run path segmentation) |
| H2 | **Absence ≠ zero.** A logged severity-0 day draws a real `PointMark` at the zero line (distinct from a gap, which has NO mark). Gap resolves to `Resolution(day, point=null)`; logged 0 resolves to a real point value 0. | data-prep + render + a11y (§Chart a11y) |
| H3 | **No dual y-axis, no shared y-axis.** Explore overlay lanes are SEPARATE stacked lanes, each on its own FIXED real-unit y-domain (`SeriesNormalization.domain(for:)`); they share only the x (time) axis. | render (one Canvas per lane) + data-prep (`SeriesNormalization` fixed domains) |
| H4 | **No silent normalization.** Values plot in their real units on fixed per-scale domains; the readout is the real value (`SeriesNormalization.readout`), never a normalized 0…1 number. | data-prep + render |
| H5 | **Scatter is descriptive-only.** NO fitted/trend line, NO regression, NO r-value / coefficient / slope / percent-impact. Density is encoded by mark SIZE (count), NEVER jitter, NEVER hue. | render (no line drawn; `symbolSize` by count) + data-prep (`ScatterPairing` has no r-value/fit) |
| H6 | **Confidence is plain-language.** Text + icon, never a number, never color alone (§Confidence Pill). | render + copy audit |
| H7 | **Suppression hides bleeding.** Bleeding/cycle series never render for a suppressed user. | data-prep (accessor gate) + render (picker filter) |

### 1. Trend line chart (Insights `.trend` card — Canvas)

Mirrors `InsightTrendChart.swift`. Absolute calendar-date x-axis ONLY (never cycle-relative). Fixed y-domain `0..10` (matches severity control). A one-line text summary sits ABOVE the chart so it is never the sole carrier of meaning. Chart height ≈ 200dp.

- **Line:** one path per contiguous logged run → breaks at every gap (H1). Ink color `plum` (Bloom on-brand; the Phase-24 PDF path will pass a single print-ink color).
- **Points:** one dot per logged day (so a single day still shows; a logged 0 draws at the zero line — H2).
- **Scrub:** a vertical rule-mark (gray `inkMuted @ 50%`, drawn behind the data, NEVER accent) + a **lollipop tooltip** pinned at the chart top (so it never clips at edges / under the finger). Tooltip lines: the absolute date, then either "Severity {n} of 10" (logged, semibold) or "Not logged" (gap, de-emphasized — the gap is information, never bold/red/an error). The tooltip surface = Bloom `card` in a `RoundedCornerShape(8.dp)` with a `strokeSubtle` hairline.
- **Day-change haptic:** fire ONE `HapticFeedbackType`-equivalent tick on resolved-DAY change only (dayA→dayB, including logged↔gap transitions). nil→day (initial touch) and day→nil (release) fire nothing. Device-gated feel → documented manual verification.
- The ONLY raw-date → value path is `ChartScrubSelection.resolve` (exact day) — NO position-based `value(atX:)`, NO nearest-point math anywhere.

### 2. Explore overlay lanes (aligned per-scale — Canvas)

Mirrors `ExploreLaneChart.swift` + `ExploreLanesView.swift`. A vertical stack of sibling lane Canvases: all quantitative lanes first (each preceded by a `subheadline`/`inkSecondary` title carrying name + unit), then all event lanes. Every lane shares the IDENTICAL x-domain and the SAME scrub day; a single rule-mark crosses every lane at the same date.

- **Per-scale y-domains (H3/H4):** each lane draws on its own FIXED real-unit domain from `SeriesNormalization.domain(for: series.scaleKind)`. The numeric y-axis is HIDDEN (no left gutter) so all plots share full width and the scrub rule aligns across lanes; the scale lives in the lane TITLE (e.g. "Sleep — h", "Stress — of 10"). NEVER a dual/shared y-axis.
- **Mark hues (semantic, from `scaleKind` — never drift):** severity/pain/stress → `rose`; sleep hours → `indigo`; bleeding intensity → `plum`; mood → `gold`; activity minutes → `teal`; presence/event ticks → `plum`. Hue is a redundant cue paired with the lane title + real-unit readout (colorblind-safe).
- Quantitative lane height ≈ 120dp; gaps = line breaks (H1); one dot per logged day (H2).
- **Scrub:** ONE multi-series tooltip card over the whole stack (not per-lane), on Bloom `card` surface with `strokeSubtle` hairline: the scrubbed date once, then one line per visible series — real-unit readout for a logged day, or "{name}: Not logged" for a gap. Quantitative lines resolve via `ChartScrubSelection.resolve` (exact day); event lines resolve via `series.isPresent(in: snapshotForThatDay)` (Pitfall 2: events have NO scrub-resolver path).

### 3. Event-marker lane (Canvas)

Mirrors `EventLaneChart.swift`. A presence series (food tags, clots, PRN, medication-taken, bleeding-as-event) renders as a ROW of date-aligned occurrence ticks — one mark per logged-present day at a constant y — NEVER a connected 0/1 line. A day with no occurrence has NO tick ("not logged that event", never "logged absent"). No value mapping exists (extraction returns `List<LocalDate>`, so a 0/1 line is structurally unrepresentable). Lane height ≈ 44dp (also the ≥48dp-adjacent touch floor — use ≥48dp for the interactive scrub region). Shares the same x-domain + scrub rule.

### 4. Scatter plot (descriptive-only, count-encoded — Canvas)

Mirrors `ScatterPlotView.swift`. Renders EXACTLY the both-logged `List<ScatterPoint>` from `ScatterPairing.pairs` — one `PointMark` per occupied `(x, y)` cell, size encoded by the cell's `count` (H5). Square plot ≈ 320dp. Both axes on FIXED real-unit domains (`SeriesNormalization.domain(for:)`), NEVER data-driven min/max. Single accent hue (`plum`) throughout — count is size + text, never color. A neutral factual caption ("Based on {n} days when both were logged.") + a worded summary; **NO fitted line, NO r-value, NO trend line, NO slope/percent** anywhere. Identical day-pairs are already aggregated into one cell by the pure layer — NEVER add jitter.

## Accessibility (TalkBack) — the HIGH-complexity bespoke overlay

Compose `Canvas` (including any `drawText`) is **completely invisible to TalkBack**, and Android has **no Audio Graph / `AXChartDescriptor` equivalent** (FEATURES.md). So every chart gets a **bespoke per-data-point semantics overlay** — focusable, invisible semantics nodes, one per rendered data point / lane point — reading from the **SAME gap-honest `ChartScrubSelection` resolver** as the visual scrub. This is the strongest argument for the owned-Canvas decision: a chart library would not give honesty-aware descriptions. Pinned by a semantics-tree test; mirrors the iOS non-gesture VoiceOver path.

### Semantics contract (precise)

| Requirement | Contract |
|-------------|----------|
| One node per data point | For each logged/scrubbable day in a chart, emit a focusable semantics node (an invisible/transparent overlay child, `≥48dp` focus target where a touch target, non-hit-testing where purely a reader node). TalkBack steps through them in **date order** (focus order = chronological left→right). |
| Gap-honest source | Each node's text is resolved through the SAME `ChartScrubSelection.resolve` (or `series.isPresent` for events) the visual scrub uses — so a gap announces **"not logged"** and a logged severity-0 announces a **real 0** ("Severity 0 of 10"). "not logged" vs "0" is answered ONCE, in one tested place. |
| `contentDescription` / `stateDescription` templates | Trend/quant lane point (logged): label = the date (`month().day()`), `stateDescription`/value = "Severity {n} of 10" / real-unit readout. Gap: label = date, value = "Not logged". Event tick: label = date, value = "Logged". Scatter cell: label = "{X name} {x readout}, {Y name} {y readout}", value = "{count} days". |
| Chart-level summary node | Each chart also carries a one-line worded summary node (the text summary shown visually above/below the chart) so the chart is never the sole carrier of meaning even before per-point stepping. Event lanes carry a summary node ("{name} — logged on {n} days") INSTEAD of a value axis (a value axis would imply a "1" the data does not carry). |
| Multi-series scrub proxy | The Explore multi-series tooltip is `clearAndSetSemantics`/hidden on the visual card; the readout + testTags ride a transparent overlay with one node per visible series (quant + event), each `mergeDescendants`-shielded so the container testTag can't mask the per-series ids. |
| testTag scheme | Trend tooltip: `insights.card.<signalKey>.chart.tooltip`, gap marker `…tooltip.notLogged`. Explore scrub: `explore.scrub.tooltip.<series.id>`, gap `…<series.id>.notLogged`. Per-point reader nodes: `<chartTag>.point.<epochDay>` (logged) / `<chartTag>.point.<epochDay>.notLogged` (gap). Scatter cell: `explore.scatter.point.<x>x<y>`. |
| Touch / scrub targets | All interactive scrub/chip/axis/dismiss targets ≥48dp (`Modifier.minimumInteractiveComponentSize()` / `sizeIn(minHeight = 48.dp)`). |
| Tooltip + dismiss labels | The scrub readout nodes and the dismiss affordance are TalkBack-labeled (dismiss = "This isn't right", a custom accessibility action on the card so it is reachable without the swipe gesture). |

**No library shortcut** — this overlay is written by hand in `ui.charts`, and the honesty contract extends into the semantics tree (pinned by the semantics-tree test in §Verification).

## Confidence Pill

Plain-language text + icon, per confidence level — **NEVER a number, NEVER color alone** (H6). The icon conveys the level by SHAPE (filled fraction), so grayscale / high-contrast users distinguish the three by text + shape. Rendered as a Bloom pill: `foreground = plum`, `background = petal` in `CircleShape` (pill), `1dp petalLine` border, padding `h10/v6` (the Phase-19 `BloomChip` contract). Text from `InsightsCopy.confidenceWord(...)` (audited). An adjacent ⓘ affordance opens an in-app explainer popover of what Low/Medium/High mean.

| Engine `InsightConfidence` | Text (audited) | Icon (shape, not hue) |
|----------------------------|----------------|-----------------------|
| `.high` | `High — possible association` | filled circle (`Icons.Filled.Circle` / full) |
| `.medium` | `Medium — possible association` | half-filled circle |
| `.low` / `.none` | `Low — possible association` | outline circle |

Omitted entirely on the sparse (insufficiency-notice) card. testTag `insights.card.<signalKey>.confidence`; explainer `…confidence.info`.

## Calm Flare (design invariant)

The Flare section is surfaced **IN-APP ONLY** and placed **FIRST by POSITION only** (§Insights block order). It is rendered with the **IDENTICAL** calm section helper + the SAME kind-agnostic `InsightCard` as every other section. As an invariant:

- **NO alarm color** — no red/roseDeep fill, no red text, no red badge; the flare card uses the same neutral `card` fill + `ink`/`inkSecondary` text as a trend card.
- **NO alarm badge, NO alarm glyph** — no exclamation mark, no warning triangle, no "!" badge. The only sanctioned "warning" word is the section header "Flare early-warning"; the in-card copy never uses it.
- **Calm, uncertainty-first copy** (engine-generated, audited in `:insights`): "Your recent pattern looks similar to times before more difficult days." + "…something to keep an eye on and discuss with your clinician." No prediction, no certainty, no imperative.
- **No notifications** — the insights/flare code imports NO notification/alarm API (§Verification: the NotificationSeparation scan extends to the insights package; the reminders package remains the SOLE notification owner).

**No-alarm-visual check:** a source scan asserts the flare rendering path uses no alarm color token (`roseDeep`/red), no exclamation/warning glyph, and no badge — calm by construction.

## Interaction & Platform

| Concern | Contract |
|---------|----------|
| **Instant load + non-blocking recompute** | On the Insights tab appearing: `coordinator.loadCached()` paints instantly from the fingerprint-keyed `CachedInsight` cache, then `coordinator.dataChanged()` kicks a debounced (~400ms) off-main recompute. The engine runs OFF the main thread (`withContext(Dispatchers.Default)`); only `Sendable`/value snapshots + dismissed keys cross the boundary; the `[Insight]` publishes back on the main thread. While `isUpdating`, only the subtle "Updating…" caption shows — cached content stays. Recompute triggers: **foreground + save + dismiss**. A fingerprint (count + latest-edit + dismissed-canonical) gates cache HIT (skip) vs MISS (recompute + replace cache). |
| **Dismiss (non-destructive)** | Each card's dismiss writes a `DismissedInsight` (append-only, consent-gated CRUD) THROUGH the coordinator's own repo context, optimistically drops the card, then recomputes EXCLUDING that `signalKey`. It **never deletes logged data** — a reversible preference, not destruction. Affordance is gray/secondary (never red), reachable via a swipe/overflow AND a TalkBack custom action "This isn't right". testTag `insights.card.<signalKey>.dismiss`. |
| **Scatter deep-link** | A Possible-association card whose `signalKey` resolves (via the ported `ScatterDeepLink.resolve(signalKey, suppressed)`) to two quantitative axes shows a "See the days behind this" affordance (`insights.card.<signalKey>.scatterLink`, accent-tinted, ≥48dp). Tapping it sets the cross-tab router payload (typed `x`/`y` axes — NEVER re-derived from copy) then switches to the Explore tab; Explore consumes the payload on appear/change → scatter mode prefilled, then clears it (so an identical later tap re-triggers). A presence-only / sleep-quality / suppressed-bleeding correlation resolves to `null` → affordance HIDDEN (not disabled). |
| **Edge-to-edge** | Both tabs render inside the Phase-19 `Scaffold` `innerPadding`; content respects `systemBars` insets (targetSdk 36). Explore's scroll container respects insets so scrub is never under the nav bar. |
| **Back behavior** | Inherits the Phase-19 shell: system back from Insights/Explore returns to the Log tab (predictive back on by default; do not intercept). No modal navigation within these tabs beyond the confidence explainer popover and the axis menus, which dismiss on back. |
| **Privacy** | Explore selection/mode/axes live in EPHEMERAL state — never persisted (persisting a series/axis interest would leak health-interest metadata outside the consent-gated store). The coordinator never logs snapshots, dismissed keys, or insight copy. |

## Copywriting Contract

**The insight COPY ITSELF is engine-generated and ALREADY audited in `:insights`** (`InsightsCopy`/`RecommendationsCopy`/`FlareCopy` mirrors — `ForbiddenTerms`-clean, rendered VERBATIM). ## Acceptance / Verification Hooks

What this phase's tests assert (JVM/Robolectric + Compose where possible; semantics-tree + source scans preferred over emulator):

1. **Honesty on data-prep (already green, Phase 17) + render:** gaps-stay-gaps (line breaks, `ChartScrubSelection` never interpolates/snaps), no dual y-axis (each lane its own fixed `SeriesNormalization.domain`), no silent normalization (real-unit readouts), scatter has no fitted line/r-value, count-encoding by size not jitter. Render-layer assertions where the drawing can be inspected (per-run segmentation, per-lane domain, no scatter line path).
2. **Per-data-point semantics present + gap-honest:** a semantics-tree test asserts one focusable node per rendered data point, in date order, and that a gap node announces **"not logged"** while a logged severity-0 node announces a **real 0** — both resolved through the SAME `ChartScrubSelection` resolver as the visual scrub. The Explore multi-series proxy and scatter cell nodes carry their testTags un-masked.
3. **Confidence never numeric:** the confidence pill renders text + icon (per level); a scan asserts no digit / `%` / `p =` / `r =` in the confidence surface and that color is not the sole signal (text + shape present).
4. **Flare no-alarm-visual + notification-free:** the flare card path uses no alarm color token / exclamation / warning glyph / badge (source scan); the NotificationSeparation/HealthSeparation scan extends to the insights package and stays green (insights imports no notification/alarm API; reminders remains the sole owner).
5. **Dismiss non-destructive:** dismissing writes a `DismissedInsight` and excludes the signal on recompute WITHOUT deleting any logged data (logged rows survive a dismiss round-trip); the affordance is non-destructive (no red) and reachable via a TalkBack custom action.
6. **Suppression hides bleeding:** a suppressed user is offered no bleeding chip/axis, no bleeding lane renders, and the scatter deep-link resolves bleeding targets to null.
7. **Instant cached load + non-blocking recompute:** cache paints before recompute; recompute runs off-main; `isUpdating` shows only the subtle caption; foreground/save/dismiss triggers fire a coalesced recompute; cache HIT skips the engine.
8. **Section omit-when-empty:** a suppressed/sparse user has the cycle-phase (and flare/recommendations, when empty) sections provably ABSENT — not empty shells.
9. **Copy registered & clean:** every new chrome string is in the `CopyAudit` registry and passes the substring gate; the engine copy is rendered verbatim (audited in `:insights`).
10. **Chart performance (PITFALLS #14):** Layout-Inspector recomposition counts flat during scrub; chart composables `skippable`; `@Immutable` chart inputs; scrub state read in the draw phase only. Device feel/haptic/TalkBack-sweep → documented manual verification.
